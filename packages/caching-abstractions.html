XiHan.Framework.Caching.Abstractions ​

缓存子系统的抽象包：字节存储 ICacheStore、类型化缓存 ICache / ISharedCache、序列化器、分布式锁、Idempotency 阶段中间件与 IDistributedCache 适配都在这里，能力 caching.local@1 与 caching.distributed@1 由 Provider 提供。写缓存 Provider、在特性里用缓存或锁时引用它。

项内容
包 IDXiHan.Framework.Caching.Abstractions
环层Ring 2（抽象）
能力定义 caching.local@1、caching.distributed@1（CachingCapabilities），本包不提供
特性入口—
配置节XiHan:Caching:Idempotency（由提供 caching.distributed 的 Provider 读取）
依赖XiHan.Framework.Kernel、XiHan.Framework.Localization.Abstractions；Microsoft.Extensions.Caching.Abstractions、Microsoft.Extensions.DependencyInjection.Abstractions
AOT兼容；JsonCacheSerializer.CreateReflectionBased() 标了 RequiresUnreferencedCode / RequiresDynamicCode，AOT 下不可用
稳定性Stable；CacheStoreDistributedCache、DistributedCacheServiceCollectionExtensions、键管理与变更通知类型为 Preview

概述 ​

子系统只有一个存储契约 ICacheStore：读、写、不存在才写（TryAddAsync）、删、比较删（TryRemoveAsync）、比较后重设到期（TryRefreshAsync）六个原子操作，加上批量的 GetManyAsync / SetManyAsync / RemoveManyAsync。Provider 只实现这一个接口，类型化缓存、分布式锁与幂等去重都由本包建立在它之上：

  • SerializingCache 把存储与 ICacheSerializer 组合成 ISharedCache，跨进程的 Provider（Redis、Remote）直接用它。
  • StoreDistributedLock 用 TryAddAsync 写入 lock:<resource> 与唯一令牌、用 TryRemoveAsync 按令牌释放、用 TryRefreshAsync 按令牌续约，任何存储都能复用。
  • IdempotencyMiddleware 用 TryAddAsync 写「处理中」标记，用 SetAsync 写完成记录，用 TryRemoveAsync 清理。
  • CacheStoreDistributedCache 把 .NET 的 IDistributedCache 架在存储上。

本包另有两个可选接口给管理界面（ICacheStoreInspector、ICacheInspector）和一个给两级缓存的变更通知接口（ICacheChangeFeed），存储或缓存能做就实现，业务代码不依赖它们。

何时使用 ​

  • 特性要用缓存或锁：引用本包，按需在清单里声明 caching.local@1 或 caching.distributed@1，从容器取 ICache、ISharedCache 或 IDistributedLock。
  • 写新的缓存 Provider：实现 ICacheStore（可选再实现 ICacheStoreInspector、ICacheChangeFeed），用本包的 SerializingCache、StoreDistributedLock、IdempotencyMiddleware、AddXiHanDistributedCache 完成其余注册，并通过 Caching.Conformance 的 CacheStoreConformance。
  • 只需要一个能跑的缓存：直接用 Caching.InMemory（随 Profiles.Standard 装配），不必单独引用本包。

安装与启用 ​

bash
dotnet add package XiHan.Framework.Caching.Abstractions --prerelease

当前是预览版，安装要带 --prerelease；从源码或本地包源引用见快速上手。本包没有特性入口，服务由 Provider 的特性注册。

配置 ​

幂等选项 IdempotencyOptions 由 Provider 在装配时用 IdempotencyOptions.FromConfiguration 读取：

键类型缺省说明
XiHan:Caching:Idempotency:TimeToLiveSeconds数字86400已完成调用结果的保留时间
XiHan:Caching:Idempotency:InProgressTimeToLiveSeconds数字60「处理中」标记的保留时间，即处理器崩溃且未能清理时同一个键被封锁的最长时间
json
{ "XiHan": { "Caching": { "Idempotency": { "TimeToLiveSeconds": 3600, "InProgressTimeToLiveSeconds": 30 } } } }

值按不变区域性解析，不是正数时抛 ArgumentException。

使用示例 ​

在 ICacheStore 的原子原语上手写一个只允许一个调用方通过的门闩，适合需要按值判断的场景（锁已经封装了这一模式，优先用 IDistributedLock）：

csharp
using System.Text;
using XiHan.Framework.Caching.Abstractions.Stores;

public sealed class OneShotGate(ICacheStore store)
{
    // 只有第一次写入成功的调用方拿到 true；ttl 到期后门闩重新打开
    public ValueTask<bool> TryEnterAsync(string name, string owner, TimeSpan ttl, CancellationToken cancellationToken)
        => store.TryAddAsync(new CacheKey($"gate:{name}"), Encoding.UTF8.GetBytes(owner), CacheEntryOptions.Expires(ttl), cancellationToken);

    // 只有当前持有者能提前打开门闩
    public ValueTask<bool> LeaveAsync(string name, string owner, CancellationToken cancellationToken)
        => store.TryRemoveAsync(new CacheKey($"gate:{name}"), Encoding.UTF8.GetBytes(owner), cancellationToken);
}

ICacheStore 由内存与 Redis Provider 登记在容器里；用远程 Provider 时从 ISharedCache.Store 取。缓存读写、批量、锁与幂等键的完整示例见缓存与分布式锁。

行为与限制 ​

  • 基础设施失败（存储不可达、超时）抛出携带 CACHING_UNAVAILABLE_001 的 FrameworkException，不伪装成未命中。
  • 批量方法一次往返、结果与入参顺序一一对应、空集合不触后端；SetManyAsync 任一项选项不合法时整批不写；RemoveManyAsync 同一个键出现多次第二次为 false。
  • GetOrCreateAsync 不合并并发：多个未命中的调用方各自执行工厂，后写覆盖先写。
  • LockHandle 是抽象类，只释放一次（基类原子置位，并发释放也只执行一次）；锁到期后被他人获取会换成新令牌，原句柄释放返回 false。包外实现 IDistributedLock 时派生它并实现 ReleaseCoreAsync 与 ExtendCoreAsync。锁不可重入；TryExtendAsync 原子续约，释放之后返回 false。
  • 幂等记录的作用域键是 idem:<租户>:<长度>.<主体>:<键>（匿名与没有租户为 -，主体带长度前缀，ADR-0205），不满足 CacheKey 文法时以 CACHING_VALIDATION_001 结束调用；处理中返回 CACHING_CONFLICT_002；成功与失败的结果都会回放，操作调用回放时还原首次的响应（XGI 载荷、类型化对象、HTTP 状态码与正文），记录属于另一个调用或响应无法还原时返回 CACHING_CONFLICT_003（ADR-0064）。
  • CacheStoreDistributedCache：绝对过期两种写法取较早者，已过去的时刻抛 ArgumentOutOfRangeException；与滑动过期同时给时绝对优先；都不给时用 Provider 的默认存活时间（内存与 Redis 缺省 5 分钟）；同步成员阻塞等待异步存储。
  • ICacheStoreInspector.RemoveByPrefixAsync 与 ICacheInspector.RemoveByPrefixAsync 返回 Result<long>，空前缀或不合法的前缀返回 CACHING_VALIDATION_004、不访问后端；列键时不合法的前缀同样返回它；CacheKeyQuery.PageSize 为 1 到 MaxPageSize（1000），默认 100，越界不在构造时抛出，ListKeysAsync（返回 Result<CacheKeyPage>）以 CACHING_VALIDATION_003 返回、不访问后端（ADR-0084）。
  • ICacheChangeFeed 的处理器在写入的调用里同步执行，不应阻塞或抛出；本实例的订阅者同步收到通知，其他实例经后端转发、不回送给发出者；跨实例通知尽力而为，可能丢失。
错误码含义
CACHING_VALIDATION_001缓存键或幂等键不合法
CACHING_VALIDATION_002条目选项不合法（远程插件按操作集校验时返回，适配器原样传出；.NET 侧在调用插件之前抛 ArgumentException）
CACHING_VALIDATION_003键列表的每页条数越界（CacheKeyQuery.PageSize 不在 1～1000，参数 pageSize、max；HTTP 400）
CACHING_VALIDATION_004键前缀不合法：列键时不合键的文法，或按前缀删除时为空或不合文法（参数 prefix、max；HTTP 400）
CACHING_UNAVAILABLE_001存储不可达或操作失败
CACHING_UNAVAILABLE_002内存缓存已达容量上限（健康项 Degraded 的原因）
CACHING_CONFLICT_001分布式锁被占用（AcquireAsync 返回；TryAcquireAsync 只返回无值）
CACHING_CONFLICT_002同一幂等键的调用仍在处理中
CACHING_CONFLICT_003幂等记录不能回放给本次调用：键被另一个调用用过，或记录里的响应无法还原
