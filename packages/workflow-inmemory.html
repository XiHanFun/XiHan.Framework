XiHan.Framework.Workflow.InMemory ​

工作流的默认实现，提供 workflow.execution@1：有界内存的定义、实例与书签存储，进程内实例锁，单进程轮询到期书签。适用于单实例部署、开发与测试；Profiles.Full 已经包含它。

项内容
包 IDXiHan.Framework.Workflow.InMemory
环层Ring 3（实现）
能力提供 workflow.execution@1（role: default）；依赖 kernel.hosting@1
特性入口InMemoryWorkflowFeature（清单 ID xihan.workflow.inmemory）
配置节XiHan:Workflow（引擎选项）、XiHan:Workflow:InMemory
依赖XiHan.Framework.Workflow.Abstractions、XiHan.Framework.Persistence.Abstractions（只读拒绝的错误码与消息键）；无第三方依赖
AOT兼容
稳定性Preview

概述 ​

引擎、目录、任务服务与内置活动都来自抽象包，本包实现四个存储契约：

类型做法
InMemoryWorkflowDefinitionStore、InMemoryWorkflowInstanceStore、InMemoryWorkflowBookmarkStore有界内存表，保存与返回都是深拷贝（读己之写，调用方改不到存储里的对象）；容量满时写入返回 WORKFLOW_UNAVAILABLE_002，不淘汰旧数据
InMemoryWorkflowInstanceLock每个实例一个进程内信号量，没人用时回收；等待超过 LockTimeout 返回 WORKFLOW_TIMEOUT_001

特性被能力求解选中提供 workflow.execution 时，把四个契约指向本包的实现并调用 AddWorkflowEngine；被 Workflow.Database 顶替时只注册本包自己的具体类型。特性启动时按 PollIntervalSeconds 起 DueBookmarkPoller 的循环，每次取 BatchSize 条到期书签逐条恢复；应用不在服务状态（启动中、排空中）的周期什么也不做、不记告警；停止时等进行中的轮询结束。

何时使用 ​

  • 单实例部署、开发环境、测试、演示：零外部基础设施。
  • 实例需要跨重启保留，或部署多个实例：换 Workflow.Database。

安装与启用 ​

bash
dotnet add package XiHan.Framework.Workflow.InMemory --prerelease

当前是预览版，安装要带 --prerelease；从源码或本地包源引用见快速上手。Profiles.Full 已经装配本包；不用组合包时单独装配：

csharp
using XiHan.Framework.Hosting.AspNetCore;
using XiHan.Framework.Workflow.InMemory;

var builder = WebApplication.CreateBuilder(args);
builder.AddXiHan(xihan => xihan.UseFeature<InMemoryWorkflowFeature>());

配置 ​

键类型缺省说明
XiHan:Workflow:InMemory:MaxDefinitions整数 ≥ 11000定义（所有版本）上限
XiHan:Workflow:InMemory:MaxInstances整数 ≥ 110000实例上限
XiHan:Workflow:InMemory:MaxNodeInstances整数 ≥ 1100000节点实例上限
XiHan:Workflow:InMemory:MaxBookmarks整数 ≥ 1100000书签上限
XiHan:Workflow:InMemory:PollIntervalSeconds正数1到期书签的轮询周期
XiHan:Workflow:InMemory:BatchSize整数 ≥ 1100每次轮询最多恢复的书签数

值写错即启动失败：解析不了抛 ArgumentException，超出取值范围抛 ArgumentOutOfRangeException，消息带出配置键与原值。引擎选项（锁超时、波次上限、子流程深度、保留期等）在 XiHan:Workflow，见 Workflow.Abstractions。

json
{
  "XiHan": {
    "Workflow": {
      "RetentionDays": 30,
      "InMemory": { "MaxInstances": 10000, "PollIntervalSeconds": 1, "BatchSize": 100 }
    }
  }
}

主要类型 ​

类型说明
InMemoryWorkflowFeature特性：注册存储与锁，被选中时装配引擎；启动与停止轮询器
InMemoryWorkflowDefinitionStoreIWorkflowDefinitionStore 实现
InMemoryWorkflowInstanceStoreIWorkflowInstanceStore 实现
InMemoryWorkflowBookmarkStoreIWorkflowBookmarkStore 实现
InMemoryWorkflowTransactionIWorkflowTransaction 实现：在调用里即可加入，没有事务；只读的调用里写入以 PERSISTENCE_UNEXPECTED_001 拒绝
InMemoryWorkflowInstanceLockIWorkflowInstanceLock 实现
InMemoryWorkflowOptions容量、轮询周期与批量

使用示例 ​

不需要额外代码：装配特性后注入 IWorkflowDefinitionCatalog、IWorkflowEngine、IWorkflowTaskService 使用，写法见工作流。测试里想立即推进定时与超时，可以从容器取 DueBookmarkPoller 手动轮询一次：

csharp
using XiHan.Framework.Workflow.Abstractions.Engine;

public sealed class WorkflowClock(DueBookmarkPoller poller)
{
    // 返回本次恢复的书签数
    public ValueTask<int> TickAsync(CancellationToken cancellationToken) => poller.PollOnceAsync(100, cancellationToken);
}

行为与限制 ​

  • 进程重启后，定义、实例、书签全部丢失；代码里创建并发布定义的应用每次启动要重新发布。
  • 容量满时写入失败（WORKFLOW_UNAVAILABLE_002），不会淘汰旧实例；长期运行的应用配置 XiHan:Workflow:RetentionDays 自动清理已结束的实例。
  • 实例锁只在本进程内互斥，多个实例各用一份本包时彼此看不到对方的数据。
  • 没有事务：引擎的写入立即生效，调用方回滚不撤销（实例锁照样持有到调用结束）；要求"写申请并发起流程"原子的应用用 Workflow.Database。
  • 只读的调用（操作契约只读：get / list 或声明了只读）里，引擎、任务服务、定义目录的写入在取锁、执行活动之前返回 PERSISTENCE_UNEXPECTED_001（HTTP 500），与数据库实现相同（ADR-0099）；不需要装持久化，特性自己登记持久化的消息目录，拒绝的消息照样翻译。
  • 按分区（平台、每个租户一个）存放，平台与租户互不可见，与数据库实现语义一致。
  • 待办查询由书签存储与实例存储连接完成（先筛书签，再取运行中实例的定义名、标题与关联 ID），分页与计数在内存里做；两步之间没有事务。
  • 定义列表与实例列表的排序（排序项 Sorts，可多个，ADR-0102、ADR-0104）在内存里做：文本按序数比较（区分大小写，大写字母排在小写之前；数据库按列的排序规则，结果可能不同），状态按生命周期的先后（ADR-0103），没发布的定义与没结束的实例的空时间当作最小，标题按前 256 个字符；接上次序键（定义：名字升序、版本降序；实例：创建时间降序、写入先后降序）即是全序。
  • 本包不注册健康项。
  • 通过 Workflow.Conformance 的存储、引擎与任务套件。
