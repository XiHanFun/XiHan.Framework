# XiHan.Framework 5.0 GA 公共 API 审查（P5-05）

> 审查日期：2026-11-11 · 基线：`dev` @ `c401eca9c`（5.0.0-preview.2）
> 范围：`framework/src` 83 个包，约 1.07 万行 PublicAPI、996 个公开类型（Stable 252 / Preview 718 / Experimental 21）
> 方法：先机械扫描 PublicAPI 文件，再分 6 组读源码做设计审查；标「已核实」的条目经第二遍复核源码
> 路径前缀省略 `framework/src/XiHan.Framework.`
> 状态：R1～R7 已定（ADR-0131、0142、0152～0154）；第 1～7 批已完成（ADR-0135～0167），剩 5.0.0 版本提交里的 PublicAPI 转移；每批完成后在本文对应条目后标注提交

## 零、按 ADR-0131 的划分

`Preview` / `Experimental` 可以在 5.x 小版本经豁免破坏，所以 GA 前必须改的只有四类：

1. **生成器写进下游程序集的形状**：2.1 全部（`Expose`、`OperationContract` 是 `Stable`）。
2. **安全与正确性缺陷**：2.2 全部（所涉类型多为 `Preview`，但属于缺陷，不等小版本）。
3. **原语层**：2.3 全部（整体冻结，不适用豁免）。
4. **`Stable` 层**：2.4 中的 `IPermissionGrantStore`、`ITenantStore`、`UnitOfWorkOptions` / `IUnitOfWork`、`IAuditSink`、`IdempotencyRecord`；第三节中的 `AuditEvent`、`AuthorizationRequest`、`HealthSnapshot`、`OperationResponse`、Domain 接口的空字符串规则、`MessageDelivery`、`MessageSubscription`、`IMessageLocalizer`、`ITenantResolver`、`ProblemResponse`、`MapXiHanOperations`、`HttpRouteConvention.Derive` 布尔重载；以及 R4 指出的 `Stable` → `Preview` 依赖（要么一起升 `Stable`，要么改签名）。

其余条目所涉类型是 `Preview`，可以留到 5.x；但 GA 前改不需要登记豁免，代价更低。2.7 的改 internal 对下游基本无影响，建议 GA 前一并做。计划把某个 `Preview` 类型在 GA 时升为 `Stable`（见第五节）的，它的条目也必须 GA 前改完。

## 二、GA 前必须改

### 2.1 写进下游程序集的形状（下游一编译就永久冻结）

> 状态（2026-11-11）：已处理，见 ADR-0136。`Expose.All` 冻结为 5.0 的五个协议；`OperationContract` 改为只收 ID 的构造加初始化器；`GeneratedOperations` 改为 internal，`GeneratedEntities` 保持公开（EF Core 的 DbContext 常在另一个项目里跨程序集调用 `ApplyGeneratedEntities()`）。

- **`Expose.All` 被生成器硬编码为 31**（已核实）：`Kernel/Operations/Expose.cs:51`、`Kernel.Generators/OperationGenerator.cs:37`。5.x 新增协议后，旧程序集里的「全部」不含新协议。改法：RFC 定义 All 的语义（冻结为现有 5 个，或作通配），生成器输出符号名。
- **`OperationContract` 构造函数带 5 个可选参数，被生成代码调用**（已核实）：`Kernel/Operations/OperationContract.cs:26`、`OperationGenerator.cs:284`。ADR-0041 已经追加过一次参数，GA 后再追加会让已编译程序集 `MissingMethodException`。改法：`OperationContract(string id)` + init 属性，跨字段校验移到登记时。
- **生成的 `GeneratedOperations` / `GeneratedEntities` 是 public**：`OperationGenerator.cs:263`、`Persistence.Generators/EntityGenerator.cs:208`。会进入下游库的公开 API。改法：默认 internal，MSBuild 开关可选 public。

### 2.2 安全与正确性缺陷（不论 R1 结论都该先修）

> 状态（2026-11-11）：第 1、2、4 条已修，第 3 条复核后不成立。

- **公开的 `StartAsync` 接收引擎专用字段**（已核实）：`Workflow.Abstractions/Instances/WorkflowStartRequest.cs:65-80` 的 `ParentInstanceId`、`ParentNodeInstanceId`、`Depth` 被原样写进实例（`Engine/WorkflowEngine.cs:1661`）。同租户调用方可以伪造父链接，子实例结束时经 `NotifyParentAsync` 恢复别人的子流程书签；`Depth` 只校验上限（`:173`），负数能绕过 `MaxSubWorkflowDepth`。改法：`internal init`。**已修**：`1c491767a`（ADR-0132），`InstanceId` 一并改为 internal。
- **`ActivityContext.Instance` 交出引擎随后要写回的实例**（已核实）：`Workflow.Abstractions/Activities/ActivityContext.cs:49`，注释写「只读视图」，实际是带 22 个公开 setter 的 `WorkflowInstance`，自定义活动改了会被持久化；`ActivityContext` 本身也没有 sealed。改法：只读视图类型。**已修**：`2c3049891`（ADR-0133）。`NodeInstance` 同样问题，一起改成只读视图；`WorkflowOutcomeContext`、`AssigneeResolution` 随之改。`ActivityContext.Variables` 仍可写，留作 5.x 的 `Preview` 改形。
- **Jwt 与 OIDC 的方案名都是 `Bearer`，同时装上时静默取 DI 里第一个**：`Security.Jwt/JwtAuthenticationHandler.cs:26`、`Security.OpenIdConnect/OpenIdConnectAuthenticationHandler.cs:25`、`Security.Abstractions/Authentication/AuthenticationMiddleware.cs:70`。改法：启动时发现重复方案名即失败。**复核后不成立**：两个特性都只提供 `security.authentication`。同时装上又没有选择时，内核启动就抛出 `KernelErrors.AmbiguousProvider`（`Kernel/Capabilities/CapabilityResolver.cs:172`）；按 `XiHan:Providers:security.authentication` 选了一个，另一个成了被顶替的节点，不装配（`Kernel/Hosting/AppBuilder.cs:232`）。只有应用自己另外登记同名处理器时才会重名，那是应用的配置错误，不改。
- **Plugins 跨包 `InternalsVisibleTo`**（已核实）：`Plugins.Protocol` 对 OutOfProcess / Wasm / Conformance 开放 internal。NuGet 依赖是「≥」，应用单独升级 Protocol 会运行时 `MissingMethodException`，APICompat 不检查 internal。改法：生成代码以源码链接编进各宿主包，或改精确版本依赖。**已修**：`a0766bb40`（ADR-0134），用精确版本依赖；Conformance 对两个宿主的 internal 依赖一并处理，架构测试守护。

### 2.3 原语层（只增不改，发布后永远改不了）

> 状态（2026-11-11）：已处理，见 ADR-0137、ADR-0138。`Binding`、`CapabilityRequirement`、`ConfigContribution` 的可选构造参数也一并改成初始化器。`InvocationContext.Items` 只修并发安全、保持通用键值袋（BasicApp 与测试把它当 `HttpContext.Items` 那样用），没有换成强类型袋。

- `Primitives/Manifests/PipelineContribution.cs:15-36`：清单模型里唯一的位置记录，Middleware 只读、Stage 可 init，Deconstruct 的 Before/After 可空与属性不一致。改成照 `Binding` 的非位置形式。
- `CapabilityDeclaration.cs:50`、`CapabilityRequirement.cs:69` 的 `TryParse` 失败时 out `null!`，改 `[NotNullWhen(true)] out T?`。
- `InvocationContext.Items` 是非线程安全的 `IDictionary<object, object?>`，派生上下文共享同一个；Baggage 校验后仍引用调用方字典（`InvocationContext.cs:25,48,121,130,208`）。改法：`ContextItemKey<T>` 下沉到 Primitives，Items 改强类型袋，Baggage 复制成只读。
- `Error.Unexpected` 参数顺序 `(…, inner, details)` 与构造函数、`Literal` 的 `(…, details, inner)` 相反（`Error.cs:162`）。

### 2.4 Stable / 核心接口的形状

> 状态（2026-11-11）：已处理（第 5 批）。授予存储按主体批量读取（ADR-0139）；租户存储以 `Result` 报告故障并分页（ADR-0140）；`UnitOfWorkOptions` 改初始化器、`IUnitOfWork` 交出 `Options`（ADR-0141）；调度器交出只读视图 `JobView` / `JobRunView`（ADR-0148）；`IBlobStoreProvider.CreateAsync` 与同型的 `IDataSourceProvider.CreateAsync` 返回 `Result`（ADR-0150）；`IAuditSink.WriteAsync` 写明不抛出，不改返回类型（ADR-0147）；`IdempotencyRecord` 改 internal（ADR-0142）。

- **`IPermissionGrantStore.GetGrantsAsync` 只收单个主体**（已核实）：`Security.Abstractions/Permissions/IPermissionGrantStore.cs:20`，`PermissionChecker.cs:124` 按角色逐个往返。改为接收 `IReadOnlyList<GrantSubject>`。
- **`ITenantStore.ListAsync` 不分页、超过 `MaxListedTenants` 静默截断**（已核实）：`MultiTenancy.Abstractions/Tenants/ITenantStore.cs:25`、`MultiTenancy.Database/Tenants/DatabaseTenantStore.cs:103`。工作流到期轮询依赖它，超出的租户永远不被轮询。`FindAsync` 存储故障时抛异常、中间件返回 500，而分片解析器同样故障返回 `UNAVAILABLE_002`。
- **`UnitOfWorkOptions` 半位置半 init，`IUnitOfWork` 逐字段镜像选项**：`Persistence.Abstractions/UnitOfWork/UnitOfWorkOptions.cs:15,41`、`IUnitOfWork.cs:28,36`。改成 init 记录，`IUnitOfWork` 只暴露 `Options`。
- **应用面拿到存储记录**（已核实）：`IJobScheduler.RunsAsync` 返回带 14 个 setter 的 `JobRunRecord`（`Scheduling.Abstractions/Schedulers/IJobScheduler.cs:109`），`JobStatus.Job` 是带内部字段的 `JobRecord`。另做只读视图，`*Record` 只留给 `IJobStore`。
- **`IBlobStoreProvider.CreateAsync` 用异常表达可恢复失败**：`ObjectStorage.Abstractions/Stores/IBlobStoreProvider.cs:27-29`，同接口的 `ProbeAsync` 返回 `Result`。改为 `ValueTask<Result<IBlobStore>>`。
- **`IAuditSink.WriteAsync` 失败语义未定**：`Kernel/Diagnostics/AuditMiddleware.cs:131-138` 靠捕获异常，Stable 的 Provider 接口。文档写死「不得抛出」或改返回 `Result`（待确认）。
- **`IdempotencyRecord` 是内部存储格式却是 Stable 公开位置记录**（已核实，只在本包使用）：`Caching.Abstractions/Idempotency/IdempotencyRecord.cs:24`。改 internal。

### 2.5 读取没有上限（GA 后再加 limit 就破坏 Provider）

- 租户：见 2.4。

### 2.6 批量契约没写进公开文档

> 状态（2026-11-11）：已处理。工作流批量语义写进 `IWorkflowEngine` 与 RFC-0021，空集合不开事务（ADR-0149）；调度器批量语义写进 `IJobScheduler` 与 RFC-0013，开始后取消不丢已完成项的结果（ADR-0148）。`MaxBatchSize` 不加：批量优先第 8 条规定抽象不强加上限。引擎里以单元素数组调存储的循环是实现细节，不影响公开形状，留作后续重构。

- 工作流：整批一个事务、失败项不写入只记在 internal 的 `WorkflowScope.cs:159`；中途取消直接抛（`WorkflowEngine.cs:833`）；空集合、重复 ID、条数上限都没规定。
- 调度：引擎在批量循环中途 `ThrowIfCancellationRequested`，已生效的项结果丢失；`SaveJobsAsync` / `DeleteJobsAsync` 只返回一个 `Result` 却没说是否原子；引擎在循环里用单元素数组调存储（`JobSchedulerEngine.cs:439/497/526`），绕过了 `BatchFirstTests`。
- 写进接口文档与 RFC，并进一致性套件；加 `MaxBatchSize` 常量。

## 三、建议 GA 前改

> 状态（2026-11-11）：位置记录已按 R3 改完（规则进 RFC-0001，ADR-0142）：`Stable` 的 12 个类型见 ADR-0142，`Preview` 的 25 个见 ADR-0151，调度的 5 个见 ADR-0148。空字符串规则已定（ADR-0145）；`IMessageLocalizer` 收窄为三个原语（ADR-0146）；`ITenantResolver` 可以拒绝调用（ADR-0143）；`MapXiHanOperations` 返回约定构建器（ADR-0144）。本节其余条目（命名与形状不一致、可选参数、只读注册表等）归第 6 批。

> 状态（2026-11-11，第 6 批）：已处理，见 ADR-0155～0166。
> - 命名：`HybridObjectCache`、`InMemoryMessageLocalizer`，Provider 选项统一 `UserName` / `ConsumerGroup`；订阅表装配后只读（ADR-0155）。
> - 缓存：前缀以 `Result` 报告（ADR-0156）；`LockHandle` 改抽象基类（ADR-0165）。
> - 可选参数：收进选项记录，规则写进 RFC-0001，`App.CreateContext` 与 `DomainEventBuffer` 照此改，工具链包例外；`IJob.RunAsync` 去掉重复的令牌，`LeaderLease.ReleaseAsync` 带令牌并返回 `Result`（ADR-0157）。
> - 可选管理接口：授予（ADR-0158）与租户（ADR-0160）；缓存失效统一为 `Invalidate(ids)` 加 `InvalidateAll()`。
> - 审计按资源查询、细节为 JSON 值（ADR-0159）。
> - 调度：计划的缺失用 null、运行查询可按来源过滤、主机信息异步；配置文档与密钥映射复制调用方字典（ADR-0161）。
> - 工作流：待办排序项，状态序号公开一份（ADR-0162）。
> - 对象存储：分片覆盖标志必填，文件系统存储只经工厂创建（ADR-0163）。
> - 持久化：雪花 ID 只经分解得到，命令超时为 `TimeSpan`（ADR-0164）。
> - AI：护栏方向与检查上下文，知识库检索请求与批量裁剪（ADR-0166）。
> - 复核后不改：触发器的英文自由文本错误已不存在；`IngestAsync` 的逐项结果已按 R7 同序对齐。
>

### 内核与原语
- 会演进的位置记录：`AuditEvent`、`AuthorizationRequest`（Security/Action 只读、Resource 可 init，`with` 行为不一）、`HealthSnapshot`、`OperationResponse`、`FeatureStatus`、`PluginSource`。
- 空字符串表示缺失：匿名主体 Id 是空串（`Principal.cs:22`）；`IMultiTenant.TenantId`、`IHasConcurrencyStamp` 是非空 string，逼每个实体写 `= string.Empty`；`ResourceName` 公开构造不校验。所有下游实体都实现这些 Domain 接口，事后改可空性就是破坏，现在就要在 RFC 写明规则（待确认）。
- 可选参数过多：`App.CreateContext`（7 参、CT 不在末位）、`TestHost.StartAsync` / `InvokeOperationAsync`、`TestManifests.Create`、`DomainEventBuffer(capacity = 256)`。
- `Hosting.AspNetCore` 的 `AddXiHan` 是 Preview、`UseXiHan` 是 Stable，入口不一致。

### 工作流
- 约 13 个请求类型是位置记录：`UserTask*`、`ExternalTask*`、`WorkflowJump`（已追加过 `ActorId`）、`WorkflowMigration`、`WorkflowVariableUpdate`。
- `UserTaskQuery` 只有 `bool Descending`，定义与实例查询用的是 `Sorts`。
- 状态排序规则 InMemory 与 Database 各写一份 `WorkflowStatusOrder`，新增状态时旧 Provider 会抛异常。
- ~~`IWorkflowEngine.ResumeAsync(bookmarkId)` 是单条操作，能直接消费用户任务书签、绕过任务服务的事件（是否绕过操作者校验待确认）~~：已核实并修正（ADR-0171）。

### 调度、配置、可观测
- `JobTriggerStatus`（7 参）、`JobTriggerRequest`、`JobRun`、`JobOutcome`、`JobStatus` 是位置记录，且已缺字段（`Transient`、`RunAs`；`JobTriggerResult` 不带 RunId）。
- `JobSchedule` 用 `TimeSpan.Zero` / `default` 表示「没有」，改可空。
- `JobRunQuery.Trigger` 是触发器名，`JobRunRecord.Trigger` 却是来源枚举；查询不能按来源过滤。
- `LeaderLease.ReleaseAsync()` 不收 CancellationToken、不返回结果，与 `LockHandle.ReleaseAsync(CancellationToken)` 不一致。
- `JobRegistry` / `JobTypeRegistry` / `JobCalendars` 构建后仍可 `Add`，`Jobs` 返回活视图。
- 触发器错误是英文自由文本（`JobSchedulerEngine.cs:1122`），违背 RFC-0010。
- `IHostMonitor` 全是同步方法、无 CancellationToken，网络盘挂起会卡住请求线程。
- `IJob.RunAsync(run, context, ct)` 的 CancellationToken 与 `context.CancellationToken` 重复。
- `ConfigurationDocument`、`SecretsConfigurationOptions.Mappings` 直接保存调用方字典。

### 持久化、租户、审计、本地化
- `IMessageLocalizer`（Stable）8 个成员里 5 个由 `Resolve` 推出，两个实现各复制一遍；改成扩展方法。
- `ITenantShardResolver.Invalidate(string? tenantId = null)` 用 null 表示全部，无批量形式；AI 的 `IAIProviderCatalog.Invalidate` 同型。
- 租户写入：InMemory 是单条同步、不失效分片缓存，Database 是批量；Abstractions 没有统一契约。
- `AuditQuery` 缺 `Resource` 过滤；`AuditInvocationExtensions` 返回可变原始字典，`AddAuditDetail(object?)` 往返类型随 Provider 不同。
- `EntityColumnMapping`（5 参位置记录）、`SnowflakeId`（可构造出值与分量不一致的实例）、`SqlSugarDiffLogData`（位置记录还带服务定位器）。
- `SqlSugarPersistenceOptions.CommandTimeoutSeconds` 是 int，同类型其他时长是 `TimeSpan`。
- `Localization.InMemory.MessageLocalizer` 不带机制前缀，与 `DatabaseMessageLocalizer` 不对称。
- `ITenantResolver.ResolveAsync` 只能返回 `Maybe`，自定义解析器想拒绝只能抛异常（待确认）。

### 安全、缓存、消息
- 授予管理没有抽象：InMemory 单条同步、撤销不存在返回 false；Database 批量异步、返回 NOT_FOUND。加可选接口 `IPermissionGrantManager`。
- 缓存分页命名 `Limit/Continuation` 与其他组 `PageSize/ContinuationToken` 不一致；`Prefix` 不合法在 init 里抛、`RemoveByPrefixAsync` 抛异常并返回裸 long。
- `LockHandle` 构造是 internal，公开的 `IDistributedLock` 包外实现不了；锁不续约，`LeasedWorkerIdSource` 释放再获取有竞态窗口。
- `MessageDelivery`、`MessageSubscription` 是 Stable 位置记录，投递 ID、重投标记、并发预取是可预见的新字段。
- `PermissionGrantRecordStore.ListAsync`：`tenantId` 为 null 表示不过滤（与全组「null 表示全局」冲突），skip/take、超限抛异常、返回 Task。
- `MessageSubscriptions` 返回内部 List，「装配后只读」未执行。
- `Caching.Hybrid.HybridCache` 与 BCL 的 `Microsoft.Extensions.Caching.Hybrid.HybridCache` 同名，同时 using 报 CS0104。
- 三个消息 Provider 不同形：`UserName` / `User`、同步 `CheckConnection()` / `ProbeAsync`、`GroupId` / `GroupName`。

### 对象存储、AI、协议、宿主、插件
- 会演进的位置记录：`BlobMetadata`、`BlobPage`、`McpToolAnnotations`（缺 MCP 规范已有的 `openWorldHint`、`title`）、`McpTool`、`ProblemResponse`（Stable，9 参含 2 个可选）、`HealthResponse`、`FeatureHealth`、`OutOfProcessPluginStatus`、`WasmPluginStatus`、`ParsedCommandLine`、`OpenApiServer`、`OpenApiDocumentSource`。
- `MapXiHan*` 返回类型三种：`MapXiHanOperations` 返回 int（Stable），应用没法统一加端点约定；统一返回 `IEndpointConventionBuilder`。
- `BlobMultipartUpload` 重建时 `overwrite` 默认 true，忘传就从「不覆盖」静默变「覆盖」。
- `IKnowledgeStore.SearchAsync` 用位置参数、`MinScore` 下推不到存储；`TrimAsync` 单篇；`IngestAsync` 逐项结果不带 DocumentId。
- `IAIGuardrail` 只能检查输入，没有方向与上下文。
- `FileSystemBlobStore` 公开构造后不调 `InitializeAsync` 配额就失效。

## 四、可留到 5.x

- `NacosOptions.Tenant` 空串表示公共命名空间；限值有的是字段有的是属性；`PurgeRunsAsync` 返回 int、`CountRunsAsync` 返回 long；时区一处是字符串 ID 一处是 `TimeZoneInfo`。
- `TenantInfo.Properties` / `TenantShard.Properties` 保存调用方字典引用。
- `IIpRegionResolver` 只有同步单条；Conditions 的 9 参位置记录、接口方法可选参数（升 Stable 前改）。
- `WorkflowVariables.Get<T>` 分不清不存在、转换失败与默认值；`IWorkflowInstanceLock.AcquireAsync` 的参数名与 RFC-0021「锁键不透明」矛盾。
- `IPluginHost.UnloadAsync` 无批量；`Describe` 返回 `T?`；`Plugins.InProcess` 与 `Plugins.Protocol` 各有一个同名 `PluginErrors`。
- Task / ValueTask 混用：`TablePage.Total` 是 int 而 `CountAsync` 是 long；`EnsureTransactionAsync`；`OperationResponseWriter`；`RunXiHanCommandLineAsync`。
- `TimeProvider` 注入形参名 `clock` / `timeProvider` 不统一；容量选项命名 `MaxEntries` / `LocalCapacity` / `CacheSize` / `MaxQueuedMessages` / `MaxGrants` 不统一。

## 五、稳定性级别调整

> 状态（2026-11-11，第 7 批）：已按本表调整，见 ADR-0167：161 个类型升 `Stable`（另加 `WebApplicationBuilder.AddXiHan`，与 `UseXiHan` 一致），24 个降 `Preview`，4 个降 `Experimental`，21 个成员单独标注较低级别。与本表不同的几处：
