# XiHan.Framework 边角问题待办

> 日期：2026-11-26 · 基线：`dev` @ `8ec4c1394`
> 来源：第四～六轮各路改动交回的「要提给用户」，去重后删掉了已经处理的与第七轮正在做的
> 路径前缀省略 `framework/src/XiHan.Framework.`；SDK 的位置写仓库名

这份清单记各轮改动顺带发现、没有列成选项的边角问题，每条写问题、位置、可能的修法或待定的取舍与出处。拿它挑下一批要做的；它不是承诺，列在这里不等于要做。做掉或决定不做的条目直接删掉，理由写进提交说明或 ADR。

## 对象存储

- **文件系统里以空格结尾的内容类型写不回**：ADR-0295 之后、ADR-0308 之前写进文件系统存储的这类内容类型照旧读出，原样写回（复制对象时 `new BlobPutOptions { ContentType = head.ContentType }`）抛 `ArgumentException`，`ObjectStorage.FileSystem/FileSystemBlobStore.cs`。可选：读出时去掉结尾的空格、给一次性迁移，或维持现在的升级须知（ADR-0308，第五轮）
- **S3 缺长度照旧兜底**：读取与 `Head` 的应答缺 `Content-Length`、列举的对象缺 `<Size>` 时取 SDK 的值或 0（`entry.Size ?? 0`），`ObjectStorage.S3/S3BlobStore.cs`。修法：照 ADR-0313 当不合规的应答返回 `OBJECTSTORAGE_UNAVAILABLE_001`（ADR-0313，第六轮）
- **S3 列出分片不查重复编号**：10000 片之内应答重复交出同一编号时照收，只有累计超过 10000 片才失败，`S3BlobStore` 列出分片的分页。修法：同一编号出现两次即不合规的应答（ADR-0313，第六轮）
- **S3 条件写入探测拿空 ETag 去完成**：探测里上传分片的应答缺 `ETag` 时照样以空 ETag 发 `CompleteMultipartUpload`，`ObjectStorage.S3/S3ConditionalWriteProbe.cs`。修法：与发起缺上传标识一样按尚未确认处理（ADR-0313，第六轮）
- **写入结果的修改时间是本机时钟**：S3 的 `PutObject` 应答没有修改时间，`BlobMetadata.LastModified` 取本机时钟；如实表示「没有」要把这个 `Stable` 的 `required DateTimeOffset` 改成可空，是 Stable 的破坏，`ObjectStorage.Abstractions/Blobs/BlobMetadata.cs`（ADR-0313，第六轮）

## 消息

- **框架事件设不了 `dataschema`**：领域事件、调度与工作流的框架事件发布时都不带 `dataschema`，要的只能自己构造 `MessageEnvelope`。修法：发布选项或事件元数据里给出模式（ADR-0305，第四轮）
- **`dataschema` 的空值两种读法不对称**：结构化 JSON 里 `dataschema` 为空串不合法，binary 的空 `ce-dataschema` 头等于没有（沿用两边原有的读法），RFC-0009「信封」、`protocol/cloudevents.md`、`Protocols.CloudEvents/Inbound/CloudEventsHttpBinding.cs`。待定：统一成哪一种（ADR-0305，第四轮）

## 插件与协议

- **protobuf 字符串字段宽松编解码**：进程外插件 gRPC 上的 protobuf `string` 字段（如 `Error.details`）由 Google.Protobuf C# 宽松编解码，孤立代理项不报错，`Plugins.OutOfProcess`、`Plugins.Protocol`。不换字符串字段的编解码修不了，代价大（ADR-0312，第五轮）
- **错误细节与 `Result` 的写出不严格**：`PluginJson.SerializeDetails`、`ResultJson.Write` 照 System.Text.Json 的缺省把孤立代理项写成 U+FFFD，不在 RFC-0001「写出与转交」列出的范围内，`Plugins.Protocol/Mapping/PluginJson.cs`、`Kernel/Json/ResultJson.cs`。待定：并不并进「写出与转交」、失败语义（ADR-0315，第六轮）
- **Wasm 下发绑定的孤立代理项没验证**：`Binding.value` 与属性有孤立代理项时 Google.Protobuf 的 JSON 写出器抛 `ArgumentException`，Wasm 运行时的配置步骤接不接得住没验证，`Plugins.Wasm`。修法：补用例，确认按配置失败、退避重试处理（ADR-0315，第六轮）
- **会话令牌按字典查找**：`PluginSessions` 用字典查会话令牌，不是定时比较；令牌高熵，风险低，`Plugins.OutOfProcess/Callbacks/PluginSessions.cs`。可选：按令牌的哈希查找再定时比较（第六轮 misc6）

## 工作流

- **表达式还有两处取两遍文本**：数组与对象作文本实参时量规模与写文本各取一遍；`contains(数组, x)` 的元素量与比较各取一遍，`Workflow.Abstractions` 的表达式求值。修法：照 `7eed229d0` 取一次复用（第六轮 misc6）
- **回填与定义编辑之间有窗口**：`DatabaseWorkflowBackfill` 改写定义行不加锁，与同时进行的定义编辑之间有短事务窗口，现在只在文档里建议没人编辑时运行，`Workflow.Database/DatabaseWorkflowBackfill.cs`。修法：目录写定义也取锁（ADR-0304，第四轮）
- **`Workflow.Database` 没有架构版本**：没有架构版本与迁移机制，查询列回填只能定成「应用升级后调用」。待定：要不要引入架构版本与迁移（ADR-0304，第四轮）
- **引擎与任务套件只在 PostgreSQL 上跑**：存储与回填四种库都有门控类，引擎（42 条）与任务（9 条）一致性套件在 SQL Server、MySQL、Oracle 上没有，`framework/test/XiHan.Framework.Workflow.Database.Tests`。修法：照 PostgreSQL 补门控类，留意 Oracle 分片的时长（第五轮 workflow4）
- **待确认：算出的数字去掉结尾的零**：表达式算出的数字写进变量时不带结尾的零（`1.5 + 1.5` 存成 `3`），是代理为了让计量与存不存储无关自加的，RFC-0021「值」（ADR-0303，第四轮）
- **待确认：`isNullOrEmpty` 不读数字**：`isNullOrEmpty` 读数字由全文改成不读，改了 ADR-0303 的规则，是代理自定的，RFC-0021「长度与上限」（ADR-0309，第五轮）

## 绑定

- **进程内宿主不接 `UseServiceBindingRoot`**：应用用 `UseServiceBindingRoot` 时要自己把同一个值传给 `InProcessPluginHost` 的构造参数，宿主不自动取，`Plugins.InProcess/InProcessPluginHost.cs`。待定：ADR-0301 备选 18、19 否决了自动对接，要不要重新考虑（ADR-0301，第四轮）
- **符号链接不限制在根目录之内**：绑定根目录里的符号链接按目标读，可以指出根目录，`Kernel.Hosting` 的 `BindingResolver`、RFC-0016 第 11 条。待定：ADR-0311 备选 9 以「由运营方挂载、信任边界同配置」暂不做（ADR-0311，第五轮）

## 命令行、MCP 与诊断输出

- **MCP stdio 宽松解码 stdin**：`McpStdioTransport.OpenInput` 以 `Encoding.UTF8` 打开 stdin，非法字节换成 U+FFFD，`Protocols.Mcp/Transports/McpStdioTransport.cs`。修法：按字节分行再严格解码，要改 `OpenInput` / `RunAsync` 的公开签名（Preview）（ADR-0312，第五轮）
- **`pack` 与 `migrate` 宽松读写文件**：`xihan pack` 读文件嵌进 ConfigMap、`xihan migrate` 读写源码都按宽松的 UTF-8，非法字节被改写，`Cli/Commands/PackCommand.cs`、`Cli/Migration/`。待定：报错还是按字节原样处理（ADR-0312，第五轮）
- **诊断输出宽松写出**：Problem Details、健康详情、`CommandLineFailure`、MCP 应答、OpenAPI 与 `migrate --report` 照写出器的缺省把孤立代理项写成 U+FFFD，`Hosting.AspNetCore`、`Hosting.CommandLine`、`Protocols.Mcp`、`Cli`。待定：要不要纳入「写出与转交」（ADR-0315，第六轮）

## 其他子系统

- **类型化序列化写成 U+FFFD**：领域事件、幂等记录、缓存、`WorkflowJson`、调度、审计、租户、对象存储旁路与向量库元数据的类型化序列化把孤立代理项写成 U+FFFD。待定：统一的失败语义（ADR-0315，第六轮）
- **远程缓存的键可能撞成一个**：RFC-0006 的缓存键文法不排除孤立代理项，两个只差在孤立代理项上的键到远端可能编成同一个，`RemoteCacheStore`。修法：文法拒收孤立代理项，或编码时报错（ADR-0315，第六轮）
- **读第三方文本宽松解码**：工作流 `Http` 活动的应答正文（`Encoding.UTF8.GetString`）与 Nacos 的 `ReadAsStringAsync` 把非法字节换成 U+FFFD，`Workflow.Abstractions/Activities/HttpActivity.cs`、`Configuration.Nacos/NacosConfigurationClient.cs`。待定：读第三方文本有没有失败语义（ADR-0312，第五轮）
- **写给外部服务的文本宽松编码**：工作流 `Http` 活动的请求正文、Kubernetes Lease 的 `holderIdentity`、AI 工具 `OperationAIFunction.SerializeArguments` 照缺省把孤立代理项写成 U+FFFD，`Workflow.Abstractions`、`Scheduling.Kubernetes`、`AI.Abstractions/Tools/OperationAIFunction.cs`（ADR-0315，第六轮）

## SDK

- **Rust 只用 `SystemTime`**：Windows 上表示不了 1601 年之前的时刻，两个平台写出的精度不同，`framework-sdk-rust` 的 `plugin::Envelope.time`。待定：引入 `time` / `chrono`，或公开内部的 `UtcTime`（ADR-0306，第四轮）
- **Go 的 `Envelope.Time` 用指针**：`*time.Time` 用 `%v` 打印看到的是地址，换成零值又分不出 `0001-01-01T00:00:00Z` 与没有，`framework-sdk-go` 的 `plugin.Envelope`。待定：保留指针还是换表示（ADR-0306，第四轮）
- **SDK 没有 `CHANGELOG.md`**：六个 SDK 仓库都没有，变更只记在文档站 `docs/sdks/*` 的「破坏性改动与迁移」。待定：要不要各自补（第四轮 SDK）
- **TS 已关闭客户端的先后**：`Host.invoke` 把客户端已关闭的核对挪到载荷编码之后；`Host.publish` 已关闭时编不成的那项仍报编码错误，全部编不成时报编码错误；`plugin/invocation.md` §5 没写这几种先后，`framework-sdk-typescript` 的 `Host`。待定：写进规范还是对齐别的 SDK（ADR-0312、ADR-0315，第五、六轮）
- **待确认：Java 编不成的文本用 WTF-8 表示**：`OperationRequest.of(String, String)` 与 `Envelope.Builder.data(String)` 编不成时照样建得出，载荷是 WTF-8，`hasUnencodableText()` / `hasUnencodableData()` 为真，发出时才失败；备选是构造时就失败，或新增 `Host.invoke(Context, String, String)`，`framework-sdk-java`（ADR-0312、ADR-0315，第五、六轮）
- **Java 读文本宽松**：`OperationResponse.payloadText()`、`Envelope.dataText()` 把孤立代理项读成 U+FFFD（展示用），`framework-sdk-java`（第五、六轮）
- **Java 本地目录缺消息键**：`messaging.envelope.invalid` 不在 `PluginMessages` 的本地目录（只收 `plugin-messages.json` 的键），`PluginMessages.catalog()` 渲染不出；交给宿主按键翻译不受影响，`framework-sdk-java`（ADR-0315，第六轮）
- **Python 没有收 `str` 的 `invoke`**：`Host.invoke` 的载荷只收 `bytes`。待定：要不要新增收 `str` 的接口，随之要严格编码（ADR-0312，第五轮）
- **手写的信封时间用例与向量重叠**：第五轮第二批的三个 SDK 原来手写的 `time` 用例与 `plugin/sdk-envelope-times.json` 重叠，都保留着。待定：要不要精简（ADR-0310，第五轮）
