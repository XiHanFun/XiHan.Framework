# XiHan.Framework 边角问题待办

> 日期：2026-11-27 · 基线：`dev` @ 69042313a
> 来源：第十轮各路改动与六个 SDK 交回的「要提给用户」；第九轮的条目已在第十轮全部做掉并删掉
> 路径前缀省略 `framework/src/XiHan.Framework.`；SDK 的位置写仓库名

这份清单记各轮改动顺带发现、没有列成选项的边角问题，每条写问题、位置、可能的修法或待定的取舍与出处。拿它挑下一批要做的；它不是承诺，列在这里不等于要做。做掉或决定不做的条目直接删掉，理由写进提交说明或 ADR。

## 内核与协议

- **XGI 入口写不出响应时 Span 与指标记成功**：编码在管道之后（RFC-0011 规则 10），实测 `xihan.outcome=success`、状态 `Unset`；ADR-0329 只加了 Error 日志。待定：Span 与指标是否也记失败（内核现在有余量），`Kernel` 的 `OperationInvoker`（ADR-0329，第十轮）
- **响应写出不再走源生成快速路径**：为让 64 层、最里层是可空值的响应照写，写出选项副本设了缺省编码器、按元数据写，比快速路径慢，代价没量；只生成快速路径（`GenerationMode = Serialization`）的上下文从照写变成写不出。待定：量一次写进 ADR，或找不绕开快速路径的修法（ADR-0329，第十轮）
- **MCP 的 `ServerVersion` 说明过时**：`Cli/Knowledge/configuration.json` 写「不写时为框架版本」，与 ADR-0209 不符；改它的真源后重跑 `Update-CliKnowledge.ps1`（ADR-0331，第十轮）
- **`MessagingOptions` 按值比较**：record 里的 `DataSchemas` 是字典、按引用比较，配了数据模式后两个内容相同的选项不相等（ADR-0332，第十轮）

## 标识

- **插件回调宿主时 SDK 写的元数据没核对**：ADR-0334 只管宿主写给插件；SDK 回调时把上下文的 Baggage 写进元数据（Go `plugin/status.go`），各语言写出器遇到孤立代理项怎样没核对，规范也没写（ADR-0334，第十轮）
- **调度的 `NodeId` 只拒空白**：`XiHan:Scheduling:NodeId` 与 `Workflow.Database` 的 `HolderId` 同为租约持有者标识，没拒收孤立代理项（ADR-0334，第十轮）
- **Wasm 中间件先于 Idempotency 阶段时报 500**：幂等键有孤立代理项时，排在 Idempotency 之前的 Wasm 中间件先以 `PLUGINS_UNEXPECTED_001`（500）结束，不是 `CACHING_VALIDATION_001`（ADR-0334，第十轮）
- **Wasm 客体写来的转义孤立代理项**：客体在 JSON 里写 `"text":"\ud800"` 时宿主读入仍得到孤立代理项，读入一侧规范没规定（ADR-0339，第十轮）

## 对象存储

- **AWS 的元数据上限按编码后算**：AWS 的 2 KB 上限按请求头里键与值的 UTF-8 字节计，RFC 2047 编码后变长，接近契约 2048 字节上限的非 ASCII 值在 AWS 上可能被拒（RustFS 收得下约 3.3 KB），没在 AWS 上实测，`ObjectStorage.S3`（ADR-0333，第十轮）
- **形如 encoded-word 的 ASCII 值在 AWS 上可能被解两次**：以 `=?` 开头、`?=` 结尾的纯 ASCII 值，Provider 编码后写出；若 AWS 先解码、存下原值再原样返回，读回时又被解一次（ADR-0333，第十轮）
- **一致性套件没有非 ASCII 元数据的往返**：`ObjectStorage.Conformance` 的 `BlobStoreConformance` 现在可以补（文件系统与 S3 两边都能过）（ADR-0322、0333，第十轮）
- **批量删除的错误项没有 `<Code>`**：`reason` 为 null；以前只有替身走得到，现在真实 SDK 也走得到，没另定规则（ADR-0333，第十轮）
- **别的客户端写进的原始非 ASCII 头**：不按 RFC 2047、直接写 UTF-8 字节的头，.NET 读回多半按 Latin-1 成乱码，没查（ADR-0333，第十轮）

## 消息

- **已有的空 `subject` 消息升级后读不出**：代理与发件箱里已有的 `"subject": ""` 消息按无法解码了结，更新日志写了升级须知；要不要给一次性的迁移办法待定（ADR-0332，第十轮）

## SDK

- **Go 关闭回调客户端之后的 `reason` 与另四家不同**：Go 没有自己的「已关闭」状态，`Serve` 退出时关连接，之后的回调由 grpc-go 报出 `Cancelled: grpc: the client connection is closing`（结果仍是 `plugins.host.unavailable`）；另四家是 `Unavailable: the host client is closed`，`framework-sdk-go`（ADR-0340，第十轮）
- **错误文案的替换没有共同向量**：六个 SDK 各写了用例（Go 对照 Python 跑了 22 万条），规范没有向量；可做 `plugin/error-text-writing.json`（UTF-16 输入用 JSON 转义、字节输入用十六进制，期望值由 .NET `Encoding.UTF8` 算出），进 `plugin` 档会让六个 SDK 的覆盖测试先失败（ADR-0339，第十轮）
- **Python 注解解析不了时只核对一层**：`check_json_names` 遇到 `get_type_hints` 抛 `NameError`（如定义在函数里的类型）时只核对那一层，嵌套的同名成员要到写出时才报，`framework-sdk-python`（ADR-0340，第十轮）

## 测试与工具

- **探测超时只能整个注册表一起放宽**：`SqlSugarConnectivityProbeTests` 的「先就绪」与「断开」两步共用注册表的探测间隔，现在都是 10 秒；要分开得给 `DataSourceRegistry`（Preview）加参数（ADR-0338，第十轮）
- **输出上限用例的根因仍待查**：重试用尽时现在会记下占句柄的进程，下次偶发时据此查（ADR-0327、0338，第十轮）
- **只能在 CI 上验证的**：Oracle 夹具的清池再试、探测用例的新超时、性能门禁的交替复测（ADR-0338，第十轮）
