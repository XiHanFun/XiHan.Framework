# ADR-0144 操作端点映射返回约定构建器

## 状态

已采纳。

## 日期

2026-11-11

## 背景

`MapXiHanOperations()`（`Stable`）返回映射的端点数（`int`），其他 `MapXiHan*` 返回的是 `IEndpointConventionBuilder`（`MapXiHanGrpc`、`MapXiHanMcp`、`MapXiHanOpenApi`、`MapXiHanCloudEvents`）。

应用想给全部操作端点统一加 ASP.NET Core 约定（CORS、限流、端点过滤器、输出缓存），这时拿不到任何构建器，只能逐个端点去找，或者在框架之外另包一层路由组。端点数只在测试里用过。GA 之后再改返回类型就是破坏。

## 决策

- `MapXiHanOperations()` 返回 `IEndpointConventionBuilder`：
  - 操作端点映射进一个空前缀的路由组（`MapGroup(string.Empty)`），返回这个组。
  - 路由模板、元数据与路由冲突检查都不变。
  - 组的约定在端点构建时才应用，所以映射之后再加的约定也作用于每个操作端点，不影响组外的端点。
- 需要端点数的测试改为从 `EndpointDataSource` 数带 `OperationDescriptor` 元数据的端点。新增测试：约定作用于每个操作端点，并且不影响其他端点。

## 影响

- 用到返回值（端点数）的代码改为从 `EndpointDataSource` 统计；只调用不取返回值的代码不用改。
- `Protocols.Http` 是 `Stable`，GA 前修改，不需要登记豁免（ADR-0131）。
