# ADR-0202 宿主调用插件带会话令牌

## 状态

已采纳（`spec/plugin/handshake.md` §4、`spec/plugin/plugin.proto` 的 `Plugin` 服务注释、`spec/plugin/invocation.md` §7 修订；运行器新增用例 `session`）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-18（`plans/5.0-安全审查.md`），中危，这里复现确认。

- 会话令牌 `XIHAN_PLUGIN_SESSION` 只用在一个方向：插件回调宿主时带，宿主核对。宿主调用插件不带任何凭据。
- 插件端点只靠「本机连接」隔离。本机其他用户、同一 Pod 的边车容器能连上插件的 TCP 回环端口，或权限不严的 Unix 套接字。连上后就能冒充宿主，以任意主体与租户调用插件：元数据里的 Baggage 就是插件看到的调用上下文。
- 宿主把回调套接字直接放在共享的临时目录下（`/tmp/xihan-host-*.sock`），不符合 `handshake.md` §4 要求的「目录 `0700`、文件 `0600`」。

复现：
- `PluginProtocolConformance.Calls_WithoutTheSessionToken_AreUnauthenticated`：修正前，示例插件接受不带令牌的握手。
- 示例插件开始校验令牌后，修正前的宿主发出的每个调用都被拒绝。宿主原先不带令牌，修正后带上。
- `CallbackEndpointTests`（Unix）：修正前套接字在共享的临时目录下。

## 备选

1. **宿主到插件改用 TLS 双向认证**：否决。要给每次启动签证书、分发信任根，本机通信的复杂度与收益不相称。令牌已经在两端手里。
2. **另发一个只用于宿主到插件的令牌**：否决。两端都知道同一个令牌，第二个令牌不增加隔离：能读到插件环境变量的人两个都读得到。
3. **同一个令牌双向使用，插件校验；本机端点收紧到私有目录**：采纳。

## 决策

1. **宿主**：调用 `Plugin` 服务的每一次 RPC（含 `Handshake`）都在元数据 `xihan-plugin-session` 里带会话令牌，由通道上的拦截器统一加，不逐个调用写。
2. **插件**：必须校验，按常数时间比较。缺失或不匹配以 gRPC `Unauthenticated` 拒绝，不执行。
   - 示例 `samples/EchoPlugin` 的 `SessionGuard` 是 .NET 的写法。
   - Go SDK 的校验在 `framework-sdk-go` 实现（2026-11-13，`4ec639a`：服务端拦截器，一元与流式调用都核对），`samples/EchoGoPlugin` 已升级，`EchoGoPluginConformanceTests` 照常跑这条用例。
3. **本机端点**：
   - Unix 域套接字放在本进程新建的私有目录里：名字随机、权限 `0700`，目录已经存在就不用（启动失败），套接字文件 `0600`。停止时连目录一起删，只删自己建的。
   - 命名管道只允许当前用户（Kestrel 的 `CurrentUserOnly`，写明不依赖缺省）。
   - TCP 只绑定回环地址，那里的隔离只靠令牌。
4. **一致性**：
   - C# 套件 `PluginProtocolConformance` 新增用例 8：不带令牌、带错令牌的握手都以 `Unauthenticated` 拒绝，带对了照常握手。可覆写的 `VerifiesSessionToken` 只用于 SDK 还没跟上时临时跳过。
   - Go 运行器 `xihan-conformance` 每次调用都带令牌，新增同义用例 `session`。

## 影响

- 自己实现协议的插件（不经 SDK）要补上令牌校验，否则一致性用例不过。宿主多带的元数据不影响老插件的运行。
- Go SDK 发布了校验令牌的版本，`samples/EchoGoPlugin` 已升级依赖、去掉 `VerifiesSessionToken` 的覆写（2026-11-13）。
- 公开 API：`PluginProtocolConformance.VerifiesSessionToken`、用例 `Calls_WithoutTheSessionToken_AreUnauthenticated`。
