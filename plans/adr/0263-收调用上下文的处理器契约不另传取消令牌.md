# ADR-0263 收调用上下文的处理器契约不另传取消令牌

## 状态

已采纳（`IMessageHandler.HandleAsync`、`IAuthenticationHandler.AuthenticateAsync`、`ITenantResolver.ResolveAsync` 去掉 `CancellationToken` 参数；三个接口都是 `Stable`，GA 前修改，不需要登记豁免；规范正文已补，见「影响」；本文里的 `IAuthenticationHandler` 与三个 `…AuthenticationHandler` 实现随后由 ADR-0264 改名为 `ICredentialHandler` 与 `…CredentialHandler`）。

## 日期

2026-11-24

## 背景

- 三个 `Stable` 契约同时收调用上下文与取消令牌：
  - `IMessageHandler.HandleAsync(MessageDelivery delivery, InvocationContext context, CancellationToken cancellationToken)`
  - `IAuthenticationHandler.AuthenticateAsync(AuthenticationCredential credential, InvocationContext context, CancellationToken cancellationToken)`
  - `ITenantResolver.ResolveAsync(InvocationContext context, CancellationToken cancellationToken)`
- 调用上下文自己带令牌（`InvocationContext.CancellationToken`，RFC-0003）。截止时间也在它上面：`DeadlineMiddleware` 把截止时间与调用方的取消链接成一个令牌，用 `WithCancellation` 派生上下文交给后面的阶段。
- 同一件事有两个入口，实现只看其中一个也能编译。参数与上下文不是同一个令牌时，只看参数的实现收不到截止时间，只看上下文的实现收不到调用方另传的取消。
- 同类契约已经不传：操作的处理器 `IOperation<TRequest, TResponse>.HandleAsync(request, context)`、中间件 `IPipelineMiddleware.InvokeAsync(context, nextStep)`、作业 `IJob.RunAsync(run, context)`（ADR-0157 决策 4：取消与超时一律看 `context.CancellationToken`）。这三个是 ADR-0157 漏掉的。
- 框架里调用这三个接口的地方共四处，传进去的都是上下文自己的令牌：

  | 调用方 | 原先传的令牌 | 上下文的令牌 |
  | --- | --- | --- |
  | `MessageDispatcher.DispatchAsync` | `ctx.CancellationToken` | 同一个（管道交给处理步骤的上下文） |
  | `AuthenticationMiddleware.InvokeAsync` | `context.CancellationToken` | 同一个 |
  | `TenantResolutionMiddleware` | `context.CancellationToken` | 同一个 |
  | `Hosting.AspNetCore` 的 `InvocationAuthenticationHandler` | `HttpContext.RequestAborted` | `HttpInvocation.CreateContext` 建上下文时给的就是 `httpContext.RequestAborted`，同一个 |

  第四处是绕过管道的端点认证（ADR-0051），不经 `DeadlineMiddleware`，上下文没有被派生过。
- 实现这三个接口的类型里，用到令牌参数的只有三处：`OpenIdConnectAuthenticationHandler`（取与刷新签发者元数据）与两个测试项目里的 `BlockingHandler`。进程外与 Wasm 插件的事件处理器（`PluginEventHandler`、`WasmPluginEventHandler`）原先就不看参数，把上下文原样交给宿主的 `DeliverAsync(delivery, context)`。

## 备选

1. **保留参数，文档写明两者是同一个令牌**：否决。约定写在文档里，编译器不管；自己调用这些接口的代码（测试、应用自己的宿主）仍然可以传两个不同的令牌。
2. **保留参数，调用方传的令牌与上下文的不一致时由框架链接或核对**：否决。框架自己的四处调用没有一处不一致，为不存在的情况加一次链接（每次调用一个 `CancellationTokenSource`）不值得；核对则是把编译期能消掉的问题留到运行期。
3. **反过来：留参数，上下文的令牌不作数**：否决。上下文的令牌是 RFC-0003 的规范性成员，截止时间靠它送达；操作、中间件与作业已经只看它。
4. **去掉参数，令牌只从上下文取**：采纳。

## 决策

1. 三个接口去掉 `CancellationToken` 参数：
   - `IMessageHandler.HandleAsync(MessageDelivery delivery, InvocationContext context)`
   - `IAuthenticationHandler.AuthenticateAsync(AuthenticationCredential credential, InvocationContext context)`
   - `ITenantResolver.ResolveAsync(InvocationContext context)`
2. 规则与 ADR-0157 决策 4 相同：取消与截止时间一律看 `context.CancellationToken`，它是唯一的真源。
3. 调用方手里另有一个令牌时，不在调用处并进去，而是在建上下文时就给对：`App.CreateContext(services, options, cancellationToken)` 传它，或对已有的上下文 `context.WithCancellation(linked)` 派生一个再传。框架的四处调用都已经是这样，没有需要补链接的地方。
4. 实现改从上下文取令牌：`OpenIdConnectAuthenticationHandler` 取与刷新元数据用 `context.CancellationToken`，并因此核对 `context` 不为 `null`。其余实现原先就不用令牌，只改签名。

## 理由

- 一次调用只有一个令牌，契约上就不该有两个位置放它。
- 四类处理器（操作、作业、消息、认证与租户解析）与中间件同一个形状，写过其中一种的人不用再记哪种要多传一个参数。
- 现在改不改变任何运行期行为（四处调用传的本来就是同一个令牌），GA 之后再改就是 `Stable` 的破坏。

## 影响

- 行为：不变。框架的调用点传的一直是上下文的令牌；`OpenIdConnectAuthenticationHandler` 对 `null` 上下文由原先在读元数据之外不报错，变为入口即抛 `ArgumentNullException`。
- 源码迁移：
  - 实现 `IMessageHandler`、`IAuthenticationHandler`、`ITenantResolver` 的类删掉最后一个参数，方法里的 `cancellationToken` 改为 `context.CancellationToken`。
  - 直接调用这三个方法的代码（多为测试）删掉最后一个实参；原先传的令牌与上下文的不是同一个时，改为建上下文时传它，或 `context.WithCancellation(token)`。
- 公开面：`Messaging.Abstractions`、`Security.Abstractions`、`MultiTenancy.Abstractions` 各一个接口方法；跟着改的实现有 `Messaging.Conformance` 的 `RecordingHandler`、`MultiTenancy.Abstractions` 的 `BaggageTenantResolver` 与 `ClaimTenantResolver`、`Security.InMemory` / `Security.Jwt` / `Security.OpenIdConnect` 的三个认证处理器。
- 同形的第四个契约一并收掉：`Hosting.AspNetCore` 的 `IInvocationAuthenticationFilter.AuthenticatedAsync(principal, context, cancellationToken)`（`Preview`）改成 `AuthenticatedAsync(principal, context)`。调用方原先传的是 `HttpContext.RequestAborted`，与上下文的令牌是同一个，行为不变；实现删掉最后一个参数。
- 规范（已补，规范指针 `c90faf8`）：
  - RFC-0009「投递」第 2 条写明处理器的形状 `HandleAsync(delivery, context)`，取消与截止时间在上下文的令牌上。
  - RFC-0008「认证」第 2 条、RFC-0007「解析」第 1 条各补同一句。
  - RFC-0001「可选参数」之后可补一条通用规则：收调用上下文的契约不另收取消令牌。
