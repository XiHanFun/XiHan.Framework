# ADR-0154 分页与逐项结果统一形状

## 状态

已采纳（规则见 `rfcs/0001-primitives.md`「稳定性级别」的「分页」与 `conventions/batch-first.md` 第 4 条）。

## 日期

2026-11-11

## 背景

API 审查 R7 指出：分页与批量结果各有几套写法，调用方换一个子系统就要重新认一遍。

- 偏移分页有两套名字：
  - 持久化的 `EntityQuery`、`TableListQuery` 用 `Skip` / `Take`。
  - 调度的 `JobRunQuery`，工作流的定义、实例、待办查询用 `Skip` / `Limit`。
- 偏移分页的总数类型不一：`TablePage.Total` 是 `int`，工作流的页是 `long`。
- 续页分页有两套名字：
  - 审计、租户、对象存储与调度状态用 `PageSize` / `ContinuationToken`。
  - 缓存键列表用 `Limit` / `Continuation`，页的成员是 `Keys`。
- 页里的元素名不一：审计页叫 `Events`，其余叫 `Items`。
- 三个页（`CacheKeyPage`、`TablePage`、`AuditPage`）还是位置记录。
- 批量的逐项结果有三种：
  - 与入参同序的 `IReadOnlyList<Result>` / `Result<T>`：调度、工作流、消息、定义目录。
  - 带键的结果记录：`BlobPutResult`、`BlobDeleteResult`、`JobTriggerResult`，以及三个数据库 Provider 的 `TenantRecordResult`、`MessageTranslationResult`、`PermissionGrantResult`。
  - `IReadOnlyList<bool>`：缓存删除。

## 决策

1. **偏移分页**用于管理查询，要能跳页、要总数：
   - 查询：`Skip`、`Take`，上限常量 `MaxTake`。
   - 页：`Items`、`long Total`。
   - `JobRunQuery`、`WorkflowDefinitionQuery`、`WorkflowInstanceQuery`、`UserTaskQuery` 的 `Limit` / `MaxLimit` 改为 `Take` / `MaxTake`。
   - `TablePage.Total` 改为 `long`。
   - 名字跟持久化与 LINQ 一致，`Stable` 的 `EntityQuery` 不动。
2. **续页分页**用于存储列举，面向大集合与后端游标：
   - 查询：`PageSize`、`ContinuationToken`，常量 `MaxPageSize` 与 `DefaultPageSize`。
   - 页：`Items`、`ContinuationToken`。
   - `CacheKeyQuery` 的 `Limit` / `Continuation` / `MaxLimit` 改为 `PageSize` / `ContinuationToken` / `MaxPageSize`，新增 `DefaultPageSize`（100）。
   - `CacheKeyPage` 的 `Keys` / `Continuation` 改为 `Items` / `ContinuationToken`，`AuditPage.Events` 改为 `Items`。
3. **越界的参数名与成员名一致**：
   - 缓存键列表的 `CACHING_VALIDATION_003` 参数改为 `pageSize`、`max`。
   - 错误常量改为 `CachingErrors.ListPageSizeInvalid`，码值不变。
   - 消息键改为 `caching.inspector.page_size_invalid`。
   - 运行历史与工作流三个查询的分页错误，参数 `limit` 改为 `take`，十个语言文件同步。
4. **结果页改为初始化器形状**：`CacheKeyPage`、`TablePage`、`AuditPage` 不再是位置记录。
5. **逐项结果只有一种形状**：与入参等长同序的列表，第 i 项对应第 i 个入参。
   - 可能逐项失败时，元素是 `Result` / `Result<T>`。
   - 只会整批成功或整批失败时，元素是值本身，如缓存删除的 `bool`。
   - 删掉六个带键的结果记录：
     - 对象存储写入返回 `IReadOnlyList<Result<BlobMetadata>>`，元数据里本来就有键；删除返回 `IReadOnlyList<Result<bool>>`。
     - 批量触发返回 `IReadOnlyList<Result>`。
     - 租户、翻译、授予的数据库存储写入与删除返回 `IReadOnlyList<Result>`。
   - RFC-0001 里「位置记录可用于 `(Key, Outcome)` 形逐项结果」的说法一并去掉。
6. **批量读取的两种形状写进命名表**：
   - 按键读取的 `GetMany` 返回与入参同序的 `Maybe` 列表。
   - 按标识取实体的 `FindMany` 只返回找到的实体，不保证顺序。

`WorkflowPurgeRequest.Limit` 是一次清理的条数上限，不是分页，不改名。

## 影响

- 源码迁移：
  - `new UserTaskQuery { …, Limit = 20 }` → `new UserTaskQuery { …, Take = 20 }`，`MaxLimit` → `MaxTake`。
  - `new CacheKeyQuery { Limit = 200, Continuation = token }` → `new CacheKeyQuery { PageSize = 200, ContinuationToken = token }`；`page.Keys` / `page.Continuation` → `page.Items` / `page.ContinuationToken`。
  - `auditPage.Events` → `auditPage.Items`。
  - 构造这三个页的 Provider 改用初始化器，例如 `new AuditPage { Items = events, ContinuationToken = next }`。
  - 读逐项结果的 `result.Outcome` 改为直接用列表元素；要键时按下标取入参，如 `uploads[i].Key`。
  - 实现 `IBlobStore` 的 Provider 改两个批量方法的返回类型。
- 按 `Details["limit"]` 读分页错误参数的客户端改读 `take` 或 `pageSize`。
- 改动的类型都是 `Preview`；GA 前修改，不需要登记豁免（ADR-0131）。
