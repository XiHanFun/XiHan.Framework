# ADR-0207 插件工作目录缺省按用户分开

## 状态

已采纳（实现的缺省值，规范没有规定工作目录的位置，不改规范）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-37（`plans/5.0-安全审查.md`），低危。

- 两种插件宿主没有配置 `WorkDirectory` 时，工作目录根是临时目录下名字固定的 `xihan-plugins` / `xihan-plugins-wasm`，每个插件一个子目录，经 `Configure` 交给插件。
- Unix 的临时目录所有用户共享。别的用户可以抢先建一个同名目录，或一个指向别处的链接。宿主随后把插件的数据写进别人能读的目录，或写到链接指向的地方。

复现：`PluginWorkDirectoriesTests.DefaultRoots_ArePerUser_NotAFixedNameInTheSharedTemp`、`WasmWorkDirectoryTests`。修正前缺省根就是临时目录下的固定名字。

## 备选

1. **每次启动一个随机目录**：否决。插件的工作目录可能要跨重启保留，随机目录还会在崩溃后留在临时目录里越积越多。
2. **放进用户目录（`LocalApplicationData`）**：否决。容器里常常没有可写的用户目录（只读根文件系统、`HOME=/nonexistent`），临时目录通常是唯一可写的位置。
3. **按用户分开，Unix 上核对私有**：采纳。

## 决策

1. **缺省的根**：`<临时目录>/xihan-plugins-<用户名>`、`<临时目录>/xihan-plugins-wasm-<用户名>`。用户名里字母、数字、`.`、`_`、`-` 以外的字符换成 `_`。
2. **Unix 上核对缺省的根**：
   - 不存在就以 `0700` 新建。
   - 存在就必须是真实目录（不是链接）、权限正好是 `0700`，否则启动插件时抛出 `InvalidOperationException`，提示删掉它或配置 `WorkDirectory`。
   - 临时目录有 sticky 位，核对过的目录别的用户替换不了。属主不另核对：别人建的 `0700` 目录本用户写不进去，失败而不是泄露。
3. **配置了 `WorkDirectory` 时**：根的权限由运营方负责，只确保它存在。
4. **子目录**：每个插件的工作目录在 Unix 上以 `0700` 新建，已存在的保留。
5. **Windows**：临时目录本来就按用户分开、只给本用户，只建目录。
6. 共用实现是 `Plugins.Protocol` 的内部类型 `PluginWorkDirectories`。

## 影响

- 升级后缺省的工作目录换了位置，插件留在旧目录里的数据不会自动搬过去。要保留的，把 `WorkDirectory` 配回旧位置，或手动搬移。
- 公开 API 不变（`ResolveWorkDirectory` 的返回值变了）。
