# ADR-0277 子系统一致性档补向量

## 状态

已采纳（framework-spec 已在 `dev` 上落地，十一个档各一个提交：`8b79d74` messaging、`28a5f31` multitenancy、`e17244b` objectstorage、`12ae349` scheduling、`2f0574a` localization、`0fe1ab2` configuration、`1eb8e85` persistence、`9ca664d` auditing、`c7a29e1` workflow、`f8eaf45` observability、`dce62fc` ai，另有 `a47dab5` 更新一致性技能；本仓库的规范指针已更新到 `3d3a139`；38 个文件的 .NET 回放已写进各子系统的测试项目，回放入口见「影响」）。

## 日期

2026-11-24

## 背景

规范的一致性档表（`conformance/profiles.json`，RFC-0024）有十八个档。`core`、`plugin`、`host`、`wasm`、`caching`、`security` 与 `provider:caching.distributed@1` 有向量；十一个子系统档——`persistence`、`multitenancy`、`messaging`、`localization`、`objectstorage`、`scheduling`、`configuration`、`auditing`、`workflow`、`ai`、`observability`——的 `vectors` 是空数组。

这带来三件事：

1. **声称符合这些档无从核对**。一个实现认领 `messaging` 档时，规范给不出任何可回放的数据，能对照的只有 .NET 各子系统的一致性套件（`XiHan.Framework.*.Conformance`）。那是 C# 写的行为测试，继承基类、实现夹具才能跑，别的语言用不了。
2. **纯规则没有人盯**。这些 RFC 里有相当一部分规范性内容与存储、代理、时钟无关：名字与键的文法和上限、cron 的下一次触发、退避间隔、Tenant 阶段的裁定、索引名的推算、雪花标识的位布局、区域的协商。它们只写在正文里、只实现在 .NET 里，正文与实现已经有出入（见「影响」的出入清单），ADR-0276 处理的缓存键长度单位就是同一类问题在 `caching` 档上的样子。
3. **覆盖测试形同虚设**。.NET 的 `SpecVectorCoverageTests`（ADR-0242、ADR-0243）认领 `plugin` 之外的全部档，但这十一个档没有向量，认领了也没有东西要回放。

## 备选

1. **不补向量，把各子系统的一致性套件移植成黑盒运行器的用例**：否决。运行器以宿主身份驱动进程外插件，能驱动的只有插件协议上看得见的行为；子系统的存储、代理要真实的后端，运行器跑不了。纯规则也不需要运行器，数据文件就够。
2. **向量照 .NET 的现状写**：否决。规范是事实源、.NET 是参考实现；把 .NET 的做法逐条编进向量，等于把正文没有写的实现细节（分块时去首尾空白、时间的宽松解析、properties 认冒号作分隔符）变成各语言必须照抄的规范。这次的口径是：向量只收正文已经写明的规则，期望值由 .NET 算出来核对；正文没有写而 .NET 有自己做法的地方不收，逐条记在各 RFC「一致性」一节，留给以后单独决定。
3. **每个档凑够一定数量的向量**：否决。有的档（`persistence`、`observability`）规范性内容绝大部分要有数据库或所在的机器才能验证，可向量化的纯规则只有一两条；为了数量去发明正文里没有的规则，比没有向量更糟。少而准，剩下的写明靠什么核对。
4. **一个子系统一个大文件**：否决。实现的覆盖测试按文件认回放、按文件登记缺口；一个文件一条规则（或一组紧密相关的规则），实现可以逐个回放、逐个登记缺口。文件名（不带目录）全仓唯一，沿用 ADR-0276 把 `caching/keys.json` 改名为 `cache-keys.json` 的理由。
5. **工作流的表达式小语言这次一起做**：这次不做。它是 `workflow` 档里最适合向量化的部分，但各内置函数的语义、decimal 除法与数字转文本的写法正文没有逐条写出，Go 一致性模块还要有一个独立实现的求值器才能回放；要先把正文补全，单独一轮。
6. **各代理上的名字（RabbitMQ 的队列、Kafka 的主题与消费组、Redis 的键）做成向量**：这次不做。它们只约束提供那个代理的实现，认领 `messaging` 档而只有内存代理的实现无从回放；要不要为代理另设 Provider 档，另行决定。
7. **「选项里的凭据」（RFC-0014）的成员名分类做成向量**：否决。那是 .NET 记录的 `ToString()` 约定，成员名是 .NET 的属性名，别的语言没有对应物；仍由架构测试 `CredentialRedactionTests` 核对。

## 决策

1. 十一个子系统档各补上向量，共 38 个文件，放在 `conformance/vectors/<档名>/`，写进 `profiles.json` 对应的档：

   | 档 | 向量文件 | 覆盖的规则 |
   | --- | --- | --- |
   | `messaging` | `topics.json`、`envelope-extensions.json`、`instance-ids.json`、`outbox-backoff.json`、`cloudevents-envelopes.json` | 主题文法与死信主题；扩展属性名、扩展与 Baggage 键的对应；实例标识文法；发件箱的退避与进死信的时机；信封的结构化 JSON 编码 |
   | `multitenancy` | `tenant-ids.json`、`tenant-resolution.json`、`tenant-shards.json` | 租户 ID 文法；Tenant 阶段的裁定（声明、Baggage、默认租户、平台调用、文法与存储的核对次序）；从租户属性推出分片 |
   | `objectstorage` | `container-names.json`、`blob-keys.json`、`blob-metadata.json`、`blob-content-types.json`、`blob-ranges.json`、`multipart-parts.json`、`store-definitions.json` | 容器名、对象键与保留前缀、元数据、内容类型的文法与上限；范围读取；分片编号与完成清单的次序；命名实例的名字与定义的相等 |
   | `scheduling` | `job-names.json`、`cron-expressions.json`、`retry-delays.json`、`event-topics.json` | 名字文法；cron 的各种写法与下一次触发（含时区与夏令时）；重试的等待与取值范围；事件主题 |
   | `localization` | `locale-names.json`、`locale-negotiation.json`、`catalog-resolution.json` | 区域名的文法与规范形式；协商与回退链；目录的合并、冲突与查找 |
   | `configuration` | `secret-names.json`、`remote-documents.json` | 密钥名文法；远程配置文档的展平与 Nacos 的内容版本 |
   | `persistence` | `index-names.json`、`snowflake-ids.json` | 索引名的推算；雪花标识的位布局 |
   | `auditing` | `exclusions.json`、`event-selection.json` | 排除列表的项与匹配；事件的选择、结果与主体、租户的归属 |
   | `workflow` | `workflow-names.json`、`status-order.json`、`keyword-matching.json`、`workflow-event-topics.json` | 三条名字文法；状态的次序；关键字的折叠与匹配；事件主题 |
   | `observability` | `host-usage.json` | 使用率与速率的三条公式、空值的条件、内存与磁盘的已用与使用率、采样间隔的范围 |
   | `ai` | `ai-names.json`、`tool-names.json`、`knowledge-chunks.json`、`provider-defaults.json`、`prompt-templates.json` | 名字文法；操作工具名的推算；分块、记录 ID 与默认集合；默认 Provider 名；提示词模板的渲染 |

2. 向量只收正文已经写明、输入输出确定、不依赖具体存储或时钟的规则。期望值按正文写，再逐条与 .NET 参考实现的输出对照；两者不一致的不收（不把 .NET 的行为编进向量，也不在没有决定的情况下改正文）。每个 RFC 的「一致性」一节列出向量文件，并列出没有收的写法与原因。
3. 只在一处写死了以前不作规定的行为：RFC-0009「信封」写明结构化 JSON 文档不合法的情形（不是 JSON 对象、`specversion` 不是 `1.0`、`id` / `source` / `type` 缺失或为空字符串、`time` 读不成时刻、扩展属性名不合文法、`data_base64` 不是 Base64）。以前只在 `protocol/cloudevents.md` 列了规范版本、必填属性、时间、扩展名四类的名目。六种情形 .NET 现在都拒绝，没有行为要改。
4. Go 一致性模块为每个文件实现对应的规则并回放（`conformance/rules` 里一档一个文件），`xihan-conformance vectors` 与 `go test` 都跑到；cron 的解析与下一次触发是与 .NET 独立的实现，回放同一份向量。一致性模块新增测试：向量文件名（不带目录）全仓唯一。
5. `persistence` 与 `observability` 两个档在 RFC 的「一致性」一节写明：向量之外的规范性内容靠什么核对（`Persistence.Conformance` 的行为套件；可观测性没有行为套件，读的是所在机器，由各实现按平台写用例）。
6. 规范的版本：新增向量文件、把向量加进已有的档是 MINOR（RFC-0024「版本」第 3 条、「一致性档」第 4 条），`CHANGELOG.md`「未发布」每个档记一条。

## 理由

- 向量是各语言都读得了的数据文件，一条规则写一次、所有实现回放同一份；子系统档有了向量，「认领某个档」才有可核对的含义。
- 口径定在「正文已经写明」，是因为这轮的目的是让已有的规则有人盯，不是借补向量的机会扩张规范。.NET 与正文的出入由此被逐条找出来、摆上台面，而不是悄悄变成规范。
- 期望值由 .NET 算出而不手算，沿用规范仓库一贯的做法；这次还多了一层：能按正文的公式直接算出的（退避、重试、雪花标识、工具名）两边各算一遍对照，防止「算出来的就是错的」。
- cron 在 Go 里独立实现并通过全部 44 条用例（含四个时区、夏令时的跳过与重复），说明正文加向量已经足以让另一种语言写出一致的实现。

### 正文与 .NET 的出入（都没有收进向量，待定）

| 位置 | 正文 | .NET 现状 |
| --- | --- | --- |
| RFC-0009「信封」：`time` | CloudEvents 1.0，即 RFC 3339 | `CloudEventsFormat.Decode` 用 `DateTimeOffset.TryParse`：空格代替 `T`、只有日期、偏移不带冒号、首尾空白都读得出；没有偏移时按**本机时区**读（同一份文档在不同时区的机器上读出不同的时刻）；秒以下超过七位四舍五入。与 ADR-0276 处理的 `xihan-deadline` 是同一类问题 |
| RFC-0009「信封」：`data_base64` | 「其他数据放 `data_base64`」 | 文档不写 `datacontenttype` 而带 `data_base64` 时读成内容类型 `application/json` 的非 JSON 数据，再 `Encode` 抛出 `FrameworkException`（读得出、写不回） |
| RFC-0009「信封」：`data` 与 `data_base64` 同时出现、扩展属性的非字符串值、重复成员 | 没有写 | `data` 优先、不报错；数字与布尔保留原文，`null`、对象、数组读成空字符串；重复成员取最后一个（信封不过 RFC-0001「JSON 文本」的共同检查） |
| RFC-0012「标识」：对象键「1 到 1024 个字符」 | 没有说单位 | 按 UTF-16 码元计；S3 的键上限是 1024 个 UTF-8 字节。与缓存键（ADR-0276 决策 1）同类，保存的文件名（255 个字符）同此 |
| RFC-0012「标识」：内容类型 | `type/subtype` 可跟 `;` 起头的参数 | 正则还允许媒体类型与 `;` 之间有空格、`;` 之后为空 |
| RFC-0022「工具」：超长的工具名 | 「前 55 个字符 + `_` + 哈希」 | 先去掉前缀结尾的 `_` 再接 `_` 与哈希：前 55 个字符正好以 `_` 结尾时得到 63 个字符的名字，正文的写法会得到两个连着的 `_` |
| RFC-0022「知识库」：固定窗口分块 | 「空白块丢弃」 | 每一块还去掉首尾的空白（`"ab cd ef"` 按 3 个字符切得到 `ab`、`cd`、`ef`，照正文是 `ab␠`、`cd␠`、`ef`） |
| RFC-0022「聊天」：提示词模板 | 只写了占位符与转义 | 缺少参数是 `AI_VALIDATION_001`，占位符名字两侧的空白去掉，没有闭合的 `{` 原样写出 |
| RFC-0014「Nacos Provider」：文档格式 | JSON 按 `:` 展平、数组按下标、`null` 保留；properties `a.b=c` → `a:b`、`#` / `!` 注释 | JSON 的布尔写成 `True` / `False`，照收注释与尾逗号，只差大小写的重复键取最后一个；properties 把 `:` 也认作分隔符，键值两侧去空白 |
| RFC-0013 cron | 列出了能写的写法 | 月名与星期名不区分大小写，段之间可以是制表符或多个空格，单个值带步长（`10/15`）从该值取到段的最大值，年份 1970–2099，`L-n` 的 n 不超过 30 |
| RFC-0009「发件箱」：退避 | `RetryDelay × 2^(尝试次数 − 1)`，不超过 `MaxRetryDelay` | 指数截在 30：`MaxRetryDelay` 大于 `RetryDelay × 2^30` 时（如 1 毫秒与 30 天）停在 `RetryDelay × 2^30`，到不了上限。向量的用例都在两者一致的范围内 |
| RFC-0010「解析」：回退链 | 「同一键先注册的目录优先」 | 先按区域、再按目录：后注册的目录有请求区域时，优先于先注册的目录里的回退区域 |
| RFC-0023「平台读取路径」 | 只给了读哪个文件的哪一项 | `/proc/stat` 的空闲含 `iowait`、总计取前八列等取法只在代码里 |

这些出入每一条要么改正文（写明）、要么改 .NET，决定之后再补向量。

### 六个 SDK

不受影响。Go SDK 认领 `core`、`plugin` 与 `provider:caching.distributed@1`，TypeScript、Rust、Java、Python、PHP 认领 `core` 与 `plugin`，都不认领子系统档；它们的覆盖测试只核对认领的档要求的向量。Go 一致性模块只新增导出的类型与函数，`go.mod` 没有变。

### 文档

- 文档站 `docs/appendix/spec.md`：一致性档一节现在可以写「每个子系统档都有向量」，向量表补上十一个目录；各子系统页的「一致性」可以提到对应的向量。
- 规范仓库的 `conformance/README.md`、各 RFC 的「一致性」一节与 `CHANGELOG.md` 已随提交更新。

### 没有做的

- 工作流的表达式小语言（备选 5）。
- 各代理上的名字（备选 6）。
- 计划的文本形式（RFC-0013 的 `every 00:10:00 x5` 等）：正文只给了例子，没有给出间隔与时刻的写法；它是存储里持久化的格式，值得补全正文后做成向量。
- 连接串的脱敏（RFC-0005「运行时数据源」的「机密」）：正文只给了范围。
- 生成的实例标识里机器名的归一化（RFC-0009「订阅方式」第 6 条）：正文写了规则，但 .NET 没有可用给定机器名调用的入口。
- 预签名的有效期与文件名、列举与审计查询的每页条数：只是数值范围，没有单独做文件。
