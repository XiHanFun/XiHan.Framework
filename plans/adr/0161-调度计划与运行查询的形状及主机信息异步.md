# ADR-0161 调度计划与运行查询的形状、主机信息异步读取、配置复制调用方字典

## 状态

已采纳（RFC-0013、RFC-0014、RFC-0023）。

## 日期

2026-11-11

## 背景

API 审查第三节「调度、配置、可观测」一组：

- **`JobSchedule` 用零值表示「没有」**：`Interval` 对非间隔计划是 `TimeSpan.Zero`，`At` 对非一次性计划是 `default`。零间隔与「没有间隔」分不清，违背「缺失用 null」（RFC-0001）。
- **运行查询的 `Trigger` 与记录的 `Trigger` 不是一回事**：
  - `JobRunQuery.Trigger` 是触发器名，`JobRunRecord.Trigger` 却是触发来源枚举（按计划、手动、恢复、重试）。
  - 同名不同义，还导致查询不能按来源过滤，如「只看手动触发的运行」。
- **`IHostMonitor` 全是同步方法、不收令牌**：读磁盘时碰到挂起的网络盘，会卡住调用方的请求线程，调用方也没法放弃等待。
- **配置保存调用方的字典**：
  - `ConfigurationDocument` 与 `SecretsConfigurationOptions.Mappings` 直接留着传入的字典，调用方之后改它，已经发布的文档或选项就跟着变。
  - 只差大小写的两个配置键在 `IConfiguration` 里是同一个键，构造时不报。
- 审查列出的另一项「触发器错误是英文自由文本」复核时已不存在：引擎记的是错误码与按默认区域渲染的消息，不改。

## 决策

1. **`JobSchedule` 不适用的字段为 `null`**：
   - `Interval` 改为 `TimeSpan?`，只对间隔计划有值；`At` 改为 `DateTimeOffset?`，只对一次性计划有值。
   - 推算下一次与文本形式按模式匹配取值，文本格式不变。
2. **运行查询与记录同名**：
   - `JobRunQuery.Trigger` 改名 `TriggerName`。
   - 新增触发来源集合 `Triggers`（`IReadOnlyList<JobTrigger>?`，空视同未限定，写法同 `States`）。
   - 数据库实现在 SQL 里过滤，单个来源用等值，多个用 `IN`。
   - 一致性套件核对单个与多个来源。
3. **`IHostMonitor` 异步并收令牌**：七个方法改为 `ValueTask<…> Read…Async(CancellationToken)`。
   - 运行时信息不会阻塞，直接返回。
   - 内存、磁盘、网卡与首次的硬件探测放到线程池执行，调用方取消即不再等待；已经开始的系统调用无法中断，会在后台自行结束。
4. **配置复制调用方的字典**：
   - `ConfigurationDocument` 与 `SecretsConfigurationOptions` 构造时把键值复制成不区分大小写的只读副本（`FrozenDictionary`）。
   - 只差大小写的重复键抛 `ArgumentException`；`Mappings` 里的密钥名不能是 `default`。

## 影响

- 源码迁移：
  - 读 `schedule.Interval` / `schedule.At` 的代码改为判空，或按 `Kind` 取 `.Value`。
  - `new JobRunQuery { Trigger = "nightly" }` → `new JobRunQuery { TriggerName = "nightly" }`；按来源过滤写 `Triggers = [JobTrigger.Manual]`。
  - `monitor.ReadDisks()` → `await monitor.ReadDisksAsync(cancellationToken)`，其余六个方法同样改；最小 API 的处理器可以直接返回 `ValueTask`。
  - 依赖「改原字典能改到文档或选项」的代码改为重新构造。
- 实现 `IJobStore` 的 Provider 补上 `Triggers` 过滤；实现 `IHostMonitor` 的改为异步签名。
- 改动的类型都是 `Preview`；GA 前修改，不需要登记豁免（ADR-0131）。
