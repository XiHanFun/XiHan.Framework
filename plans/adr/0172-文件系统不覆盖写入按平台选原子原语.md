# ADR-0172 文件系统不覆盖写入按平台选原子原语

## 状态

已采纳（RFC-0012「Provider」修订 `ObjectStorage.FileSystem` 一条；修正 ADR-0168 决策 1 在 Windows 上的做法）。

## 日期

2026-11-12

## 背景

ADR-0168 让 `FileSystemBlobStore.CommitAsync` 的不覆盖提交在各平台都「先以 `FileMode.CreateNew` 独占创建空的占位文件，再以替换方式把临时内容改名到内容路径」。Linux CI 通过，但在 Windows 上本地跑全量测试时，一致性用例 `Put_WithoutOverwrite_IsAtomicUnderConcurrentWriters` 偶发失败：8 个写入方一个也没成功。

- 七个是 `OBJECTSTORAGE_CONFLICT_001`，占到位的那一个是 `OBJECTSTORAGE_UNAVAILABLE_001`，原因 `UnauthorizedAccessException`。
- Windows 上替换式改名（`MoveFileEx` 带 `MOVEFILE_REPLACE_EXISTING`）要求目标此刻没有被别的句柄打开。其余写入方正在对同一路径做 `CreateNew` 与 `File.Exists` 探测，这些探测会短暂打开目标，替换因此以拒绝访问失败。
- 单独跑这个用例，修正前约每 3 到 5 次失败一次。CI 只有 Linux 运行器，所以没有暴露。
- Unix 的 `rename(2)` 替换与目标是否被打开无关，ADR-0168 的做法在 Unix 上成立。
- ADR-0168 本来就写明 Windows 的不替换改名是一次原子操作，问题只出在 Unix 上的 .NET 实现。

## 备选

1. **替换失败时有限次重试**：否决。重试次数与间隔没有依据，探测随时可能再来，只是把失败概率压低。
2. **占位后把内容复制进占位文件，不再改名**：否决。不覆盖写入的磁盘 I/O 翻倍，只为绕开一个平台的语义。
3. **按平台用各自的原子原语**：采纳。

## 决策

1. **Windows 上不覆盖的提交用不替换的改名**：`File.Move(temporary, dataPath, overwrite: false)`，目标已存在即 `OBJECTSTORAGE_CONFLICT_001`。
2. **其他平台保持 ADR-0168**：先独占创建占位文件，再以 `rename` 替换。
3. 一致性用例不变：16 轮、每轮 8 个写入方，「恰好一个成功、其余都是冲突」同时覆盖两种失败（Unix 上两个成功、Windows 上没有成功者）。

## 影响

- 行为：Windows 上并发的不覆盖写入恢复为恰好一个成功；ADR-0168 之后偶发的「没有一个成功」不再出现。ADR-0168 尚未发布，所以发布版本里没有出现过这个问题。
- Unix 上行为不变。
- 公开 API、错误码、配置键不变；`CommitAsync` 是内部方法。
