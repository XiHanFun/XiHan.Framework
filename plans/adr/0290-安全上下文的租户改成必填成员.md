# ADR-0290 安全上下文的租户改成必填成员

## 状态

已采纳（内核的 `SecurityContext.Tenant` 改成 `required`，框架内没写租户的构造处补上 `Tenant = null`；规范不变）。

## 日期

2026-11-25

## 背景

- ADR-0288 把 `SecurityContext` 改成初始化器形状：`Principal` 是 `required` 的 `init` 成员，`Tenant` 是可选的 `init` 成员（缺省 `null`）。它的备选 3 讨论过把 `Tenant` 也标 `required`，当时否决，理由是无租户是安全上下文的常态（`Anonymous`、单租户应用的每一次调用、Tenant 阶段之前的每一个上下文）。
- ADR-0288 自己记下了留下的风险：换主体时另建上下文而忘了带上已有的租户，得到的是不带租户的上下文，编译器不提醒。改成初始化器之前，位置构造 `new SecurityContext(principal, tenant)` 的第二个参数必须写出来，这个错误写不出来；改成可选成员之后，`new SecurityContext { Principal = principal }` 编译通过，租户悄悄丢了。
- 丢了租户不是小事：Tenant 阶段之后再换主体的代码（认证处理器、插件宿主、应用自己的中间件）会让这次调用以无租户继续，租户隔离、按租户的授予与审计的租户都跟着变。框架自己的两处（`AuthenticationMiddleware`、`InvocationAuthenticationHandler`）是显式带上 `Tenant = context.GetSecurity().Tenant` 的，靠的是作者记得。
- ADR-0267 给 `BindingValue.Value` 定过同样的规则：没有主值是合法状态，但要构造方明说，不能是忘了写，所以可空的 `Value` 也标 `required`。仓库所有者定下 `SecurityContext.Tenant` 照这个先例改。

## 备选

1. **维持可选成员，只靠成员的文档提醒**（ADR-0288 的做法）：否决。这正是要去掉的风险；文档提醒拦不住忘了写。
2. **加一个分析器，在 `new SecurityContext { … }` 不写 `Tenant` 时报警**：否决。语言已经有 `required`，编译器在每个构造处直接报错（CS9035），不必另造规则、另写诊断与测试。
3. **加工厂方法**（`SecurityContext.For(principal, tenant)`，两个参数都必给）：否决，理由同 ADR-0288 备选 4：初始化器已经带着成员名，工厂是第二条构造途径，也是要守到下个大版本的 `Stable` 签名。
4. **`Tenant` 改成不可空，用一个「无租户」的哨兵值**：否决。RFC-0001「缺失用 `null`」：可选的值缺失时用 `null`，不用默认实例；读租户的代码（`context.GetSecurity().Tenant is { } tenant`）也都按 `null` 判断。
5. **`PermissionGrant.TenantId` 与 `AuthorizationRequirement.Resource` 一并改成 `required`**：这次不做。它们在位置构造时代就可以不给（两参的构造是平台授予、单参的构造是不针对具体资源，ADR-0197），ADR-0288 备选 3 的那部分理由仍然成立；仓库所有者这次只定了安全上下文。

## 决策

1. `SecurityContext.Tenant` 改成 `required TenantContext? Tenant { get; init; }`：可以是 `null`（无租户），但每个构造处都必须写出来。`Principal` 照旧是 `required` 且不能为 `null`。
2. `SecurityContext.Anonymous` 写成 `new() { Principal = Principal.Anonymous, Tenant = null }`，值不变。
3. 以后给 `SecurityContext` 加成员仍只加可选的初始化成员（ADR-0288 决策 6）；`Tenant` 是这一条之外唯一的例外，因为它是改成初始化器之前就必须写出的成员。
4. 框架内没写租户的构造处补上 `Tenant = null`，共 28 处：
   - 正式包 2 处：`SecurityContext.Anonymous`，`Plugins.Protocol` 的 `PluginIdentity.CreateContext`（新建的回调上下文还没有租户，租户由 Tenant 阶段按 Baggage 解析，补了注释说明）。
   - 测试 26 处：`Security.Abstractions.Tests` 16、`MultiTenancy.Abstractions.Tests` 5、`Kernel.Tests` 3、`Caching.Abstractions.Tests` 2。
   - 已经写了 `Tenant` 的 11 处不变（正式包 2：`AuthenticationMiddleware` 与 `InvocationAuthenticationHandler` 带上已有的租户；测试 9）。
   - 示例、基准、源生成器与分析器都不构造这个类型；`with` 的写法（`SetTenant` 里的 `with { Tenant = tenant }`、`existing with { Principal = … }`）不受影响，`with` 不要求重写 `required` 成员。
5. 形状守护测试（`Kernel.Tests` 的 `SecurityTests.ContextRecords_HaveNoPositionalConstructorOrDeconstruct`）里 `SecurityContext` 的必填成员集合改成 `Principal`、`Tenant`。

## 理由

- 安全上下文是每次调用都带着的类型，租户是它承载的两个事实之一；换主体时漏带租户是安全相关的错误，应当在编译期而不是在审计记录或越权里发现。
- `required` 加可空正好表达「可以没有，但要明说」：无租户是常态，所以值可以是 `null`；忘了写不是常态，所以要报错。与 `BindingValue.Value`（ADR-0267）同一种写法，使用者只记一条规则。
- 无租户的构造处多写一个 `Tenant = null`，代价是每处十几个字符；框架内 28 处，大多在测试里。
- 在 5.0.0 之前改，不需要豁免登记（ADR-0131）。

## 影响

- **公开 API 与迁移**：`SecurityContext.Tenant` 多了 `required` 修饰。PublicAPI 文件不记 `required`，`PublicAPI.Unshipped.txt` 同步后没有变化；尚无基线，不需要 `CompatibilitySuppressions.xml`。

  | 原先 | 改成 |
  | --- | --- |
  | `new SecurityContext { Principal = p }` | `new SecurityContext { Principal = p, Tenant = null }`，或真正的租户 `Tenant = t` |
  | `new SecurityContext { Principal = p, Tenant = t }` | 不变 |
  | 换主体：`new SecurityContext { Principal = p }`（漏带租户） | `new SecurityContext { Principal = p, Tenant = existing.Tenant }`，或 `existing with { Principal = p }` |

  - 目标类型推断的写法同理：`SecurityContext security = new() { Principal = p }` 补上 `Tenant`。
  - 漏写 `Tenant` 是编译错误 CS9035（必需成员未在对象初始值设定项中设置）。升级后逐个看报错的构造处：新建的、本来就没有租户的写 `Tenant = null`；从已有的上下文换主体的写 `Tenant = existing.Tenant` 或改用 `with`。
  - 二进制兼容：按旧签名编译的程序集不用重新编译也能运行（`required` 只在编译期起作用）；重新编译时才报错。
- **行为不变**：运行时的值、相等比较、`ToString()` 与校验都与原先相同。
- **序列化**：框架不序列化 `SecurityContext`，没有哪个 `JsonSerializerContext` 直接或间接带着它（全部正式包、测试、示例与基准里都没有以它或带着它的 `AuthorizationRequest` 为根或成员的 `[JsonSerializable]`；主体与租户跨进程走 Baggage 的 `xihan.principal` / `xihan.tenant`）。应用自己拿 `System.Text.Json` 序列化它的：写出不变；读回时缺了 `Tenant` 成员抛出 `JsonException`（以前读成 `null`），显式的 `"Tenant": null` 读成无租户。
- **规范**：不用改。RFC-0007 与 RFC-0008 只写了 `SecurityContext.Tenant`、`SecurityContext.Principal` 这些成员名，不涉及形状与是否必填。
- **测试**：形状守护测试核对 `SecurityContext` 标了 `required` 的成员正好是 `Principal` 与 `Tenant`；原先「租户不给就是无租户」的断言改成写明 `Tenant = null`。
- **文档**：文档站 `packages/kernel` 里「`Tenant` 不给即无租户」一句与更新日志待改。
