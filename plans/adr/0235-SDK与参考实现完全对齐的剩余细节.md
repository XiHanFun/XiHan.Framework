# ADR-0235 SDK 与参考实现对齐的剩余细节

## 状态

已采纳（补充 ADR-0233；`spec/rfcs/0001-primitives.md`、`0002-manifest.md`、`0003-invocation-context.md`、`0004-pipeline-stages.md`、`0010-localization.md`、`0011-operations.md`、`conventions/baggage-keys.md`、`manifest/manifest.schema.json` 随之修订，新增向量 `primitives/trace-context.json`、`manifest/manifests.json`、`pipeline/ordering.json`、`operations/payload-reasons.json`，`kernel-messages.json`、`message-templates.json`、`wire-encoding.json` 增加用例）。

## 日期

2026-11-16

## 背景

ADR-0233 之后，六个 SDK 都回放了同一批向量并通过。逐项核对后，仍有三类问题：

1. 规范没写到的边界，各 SDK 写法不同：
   - 处理器抛出异常用哪个消息键，Java 甚至没有翻译。
   - 派生上下文时给了不合法的 Baggage 值，有的保留原值，有的去掉键。
   - 「调用开始时截止时间已过」在哪里判断。
   - 小写格式说明符算不算数。
   - 范围外的浮点、负零、`NaN` 怎么写。
   - 载荷不合法的 `reason` 遇到特殊成员名怎么写。
   - JSON 里的重复成员算不算合法。
   - `traceparent` 的版本 `ff`。
   - `activation: []` 是什么意思。
   - 管道的重复登记在登记时报还是排序时报。
2. 参考实现自己与规范不一致：
   - 清单读取：.NET 的 `ManifestReader` 成员名不区分大小写、忽略未知成员、把 `null` 当缺失、不校验操作 ID，与 Schema 的 `additionalProperties: false` 以及 ADR-0233 写进 RFC-0002 的严格读取不符。
   - 插件元数据的 `traceparent` 标志写死为 `01`，上游的「不采样」传不到插件。
   - `InvocationContext.WithBaggage` 不核对值，Wasm 中间件把插件给的 Baggage 值原样并进上下文，绕过了 ADR-0204 的值约束。
   - 空载荷的 `reason` 是英文短语 `the payload is null`，不是路径。
   - `Describe` 按参数给出的顺序列出参数，无序映射的语言排不出同样的文本。
3. 管道排序与打印、清单、追踪上下文、载荷错误的路径没有向量，各 SDK 只移植了 Go 的测试，没有和 .NET 对照过。

## 决策

规则一律以 .NET 的实测行为为准，在规范里写成条文并配向量；.NET 不符合规范的地方改 .NET。

- **未处理的异常**：
  - 处理器或中间件抛出的异常由调用器翻译为 `KERNEL_UNEXPECTED_001` + `kernel.invocation.unhandled_exception`，没有参数。
  - 异常本身是框架异常（带错误码的配置或编程错误）时，它的错误放进 `inner`。
  - 这一项进 RFC-0011 的错误表与 `kernel-messages.json`。
- **Baggage 值**：
  - 外部输入（载体入站、插件协议的元数据、Wasm 中间件返回的 Baggage、SDK 由映射构造上下文）里不合的成员丢弃，原有的同名值保留，与 W3C 忽略不合法成员一致。
  - 程序内逐项派生（`WithBaggage(key, value)`）给已登记的键一个不合的值，是编程错误，抛参数异常，与键不合文法时一样。幂等键仍然例外。
  - .NET 的 `WithBaggage` 补上这项核对，Wasm 中间件先过滤再派生。
- **截止时间已过才开始的调用**：
  - 宿主由 Resilience 阶段的截止时间中间件在入口按时钟判断。
  - 没有这个中间件的语言 SDK 由调用器在第一个中间件执行之前判断：截止时间已到即以 `KERNEL_TIMEOUT_001` + `kernel.invocation.deadline_before_start` 结束，管道不执行。
  - 构造上下文时不做这项判断。
- **格式说明符**：
  - `D`、`F`、`N` 不区分大小写。
  - `X` 与 `x` 分别给出大写与小写的十六进制数字。
  - 精度 0–99 必须支持，更大的不作规定。
- **浮点的文本形式**：
  - 1e-4 ≤ |x| < 1e17 时写最短往返的十进制，不用指数；整数值不带小数点。
  - 范围之外写最短往返的有效数字加 `E`、符号与至少两位指数（`1E+17`、`1.5E-07`、`5E-324`）。
  - 负零写 `-0`；`NaN`、`Infinity`、`-Infinity` 照 .NET 的不变文化。
  - `F` 与 `N` 不用指数，写出全部整数位（1e20 写 `F2` 得 `100000000000000000000.00`）。负数舍入成零时保留负号（-0.001 写 `F2` 得 `-0.00`）。
- **Describe**：参数按名字的序数顺序排列。.NET 原来按给出的顺序，改为排序；Go 原本就排序。
- **载荷不合法的 `reason`**：
  - 载荷是 `null`、不是对象或根上就不合时写 `$`。.NET 原来对 `null` 写英文短语，改为 `$`。
  - 某个值类型不符时，写它的路径，记法照 System.Text.Json 的实测：
    - 成员名含 `.`、空格、`'`、`/`、`"`、`[`、`]`、`(`、`)`、`\`、制表符、换行、回车、换页、退格、U+0085、U+2028、U+2029 之一时写 `['名字']`，名字原样。
    - 否则写 `.名字`，空名字是 `$.`。
    - 数组下标写 `[i]`。
  - JSON 语法错误时，各解析器报告的位置不同，只要求以 `$` 开头。
- **重复成员**：Result、Error 与清单的 JSON 里同一层出现重复的成员名，即不合法。
- **追踪上下文**：
  - 只接受 `^00-[0-9a-f]{32}-[0-9a-f]{16}-[0-9a-f]{2}$`，trace-id 或 parent-id 全零也不合法；不合法的当作没有给出。
  - 写出时版本是 `00`，标志只写采样位（`00` / `01`）。
  - 插件元数据与消息信封用同一个取法：有 Observe 阶段的 Span 时取它，否则取上下文，上下文没有标志时写 `01`。
  - .NET 新增原语 `TraceParent`（`TryParse` / `Format`），HTTP、消息与插件三处载体都改用它。
- **清单**：
  - .NET 的读取改为严格：成员名区分大小写、拒绝未知成员与重复成员、可选成员不收 `null`、`contributes.operations` 按操作 ID 文法校验。
  - `activation` 至少一项，空数组不合法。
  - 写出的清单与读入的按 JSON 值等价，成员顺序与缩进不作规定，宿主核对握手清单时按字段比较。
- **管道**：
  - 登记时报的错误：重复登记、未知阶段、约束主体未登记。
  - 排序时报的错误：约束目标未登记、有歧义、不在同一阶段、成环。
  - 打印格式与 .NET 的 `Dump()` 逐字相同。
- **仍然不作规定的**：
  - 精度超过 99 的格式说明符。
  - 数组与对象作为模板参数的文本。
  - `type_mismatch` 的 `expected` / `actual`：各语言的类型名。
  - JSON 语法错误的具体路径。
  - 清单写出的排版。
  - 它们要么只给人看，要么天生因语言而异，规范明确写出「不作规定」，SDK 不应依赖。

## 理由

- 宿主与插件之间按 .NET 的行为交互，以 .NET 的实测结果定规则，一个 SDK 与宿主对得上，就与别的 SDK 对得上。
- .NET 违反规范的几处里，清单与 Baggage 是安全约束的缺口：未知成员与大小写被宽松接受，插件能绕过值约束。追踪标志是传播错误，`reason` 与 `Describe` 是可移植性问题，都应当改 .NET，而不是把规范降到 .NET 的现状。
- 剩下不作规定的几项，要统一就得规定类型名或解析器内部状态，没有收益。

## 影响

- .NET 的行为变化：
  - `ManifestReader` 拒绝大小写不对、带未知成员、带重复成员或 `null` 的清单，以及不合文法的操作 ID 与空的 `activation`，写错的清单在读取时以 `KERNEL_CAPABILITY_006` 失败。
  - `InvocationContext.WithBaggage` 对已登记键的不合法值抛出 `ArgumentException`。
  - 插件收到的 `traceparent` 标志随调用的采样决定。
  - 空载荷的 `reason` 为 `$`。
  - `Describe` 按名字排序参数。
  - 新增公开类型 `TraceParent`。
- 各 SDK 按本 ADR 改齐，回放全部向量。
- 一致性：新增四个向量文件，运行器的 `vectors` 子命令与 `rules` 增加对应核对。
