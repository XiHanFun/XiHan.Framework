# ADR-0224 EF Core 多租户实体的全局查询过滤器

## 状态

已采纳（RFC-0005「索引与建表约定」一条修订）。

## 日期

2026-11-13

## 背景

5.0 安全审查「加固建议」（`plans/5.0-安全审查.md` 第四节）。

- EF Core Provider 的仓储在每次查询上显式加租户条件，没有全局查询过滤器。
- 工作单元的 `Context` 是公开的，作用域里注入的 `DbContext` 与仓储是同一个实例。直接在它上面写 LINQ 不带租户条件，读得到别的租户的行；文档的常见问题里也承认了这一点，要求调用方自己写条件。
- 这是一条容易漏掉的路径：报表、统计这类仓储覆盖不了的查询正是直接用 `DbContext` 写的。

复现：`EntityFrameworkCoreTenantFilterTests.DirectContextQueries_SeeOnlyTheUnitOfWorksTenant`。修正前，acme 的调用直接查询得到 acme 与 beta 两行。

## 备选

1. **只在文档里提醒**：否决，就是现状。
2. **把 `Context` 改为内部**：否决。直接用 `DbContext` 是 EF Core Provider 的卖点，应用要写仓储表达不了的查询。
3. **匿名的全局查询过滤器**：否决。会占掉应用自己的匿名过滤器，也没法只忽略租户这一个。
4. **命名的全局查询过滤器，按工作单元取租户**：采纳。

## 决策

1. `ApplyPersistenceConventions(Database)` 给每个多租户实体的继承根加名为 `xihan:tenant`（`ModelBuilderExtensions.TenantQueryFilter`）的查询过滤器。从属类型、共享类型实体与派生类型跳过。
2. 条件：上下文在 XiHan 工作单元里时，只留 `TenantId` 等于工作单元租户的行；不带租户的工作单元看不到任何多租户行（租户从不为空），与仓储同一规则。不在工作单元里的上下文（应用自己 `new` 的，或作用域里还没开工作单元）不过滤。
3. 取值：工作单元开始时把租户记到自己的 `DbContext` 上（弱引用表，上下文回收即回收）。过滤器引用建模时的上下文，EF Core 在每次查询时把它换成执行查询的上下文，所以各作用域各取各的租户。
4. 有意跨租户查询用 `IgnoreQueryFilters(["xihan:tenant"])`，只忽略这一个。框架自己的唯一键冲突检测本来就忽略查询过滤器。
5. 实体已有匿名过滤器时建模抛出 `InvalidOperationException`：EF Core 不能在同一实体上混用匿名与命名过滤器。

## 影响

- 依赖直接查询读到别的租户行的代码（多半是缺陷）读不到了；确实要跨租户的改用 `IgnoreQueryFilters`。
- 多租户实体上已经有匿名过滤器的应用，升级后建模失败。迁移：`HasQueryFilter("<名字>", …)` 给它起名。
- 公开 API：`ModelBuilderExtensions.TenantQueryFilter`。
