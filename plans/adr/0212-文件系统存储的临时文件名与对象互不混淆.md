# ADR-0212 文件系统存储的临时文件名与对象互不混淆

## 状态

已采纳（实现修正，契约不变）。

## 日期

2026-11-13

## 背景

5.0 安全审查 S-39（`plans/5.0-安全审查.md`），低危。

- `ObjectStorage.FileSystem` 写入先落临时文件，名字是目标路径加 `.xihan-tmp-` 与一个 GUID。
- 列举时跳过、启动扫描时删除的判定是「完整路径里含 `.xihan-tmp-`」。
- 这段文字全是键编码原样保留的字符，键里能写：
  - 键（或它的某个前缀段）含 `.xihan-tmp-` 的对象在列举里看不到，重启时被当作崩溃留下的临时文件删掉。
  - 根路径里含这段文字时，整个存储的对象都看不到，重启时全部删除。

复现：`FileSystemTemporaryFileTests` 的三个用例。修正前全部失败，根路径的用例重启后一个对象都不剩。

## 备选

1. **键文法禁止这段文字**：否决。键文法是所有 Provider 共用的契约，不能为一个实现的内部命名收窄。
2. **临时文件放到单独的目录**：否决。临时文件要与目标同目录，改名才是同一卷上的原子替换。
3. **换成键编码不会产出的字符，判定只看文件名**：采纳。

## 决策

1. 临时文件的名字片段改为 `~xihan-tmp-`。键的编码只产出小写字母、数字、`._-` 与 `%XX`，对象的文件名里不会出现 `~`。
2. 列举与启动扫描只看文件名，不看所在目录与根路径。
3. 旧版的临时文件（文件名以 `.xihan-tmp-` 加 32 位小写十六进制结尾）：
   - 内容目录里，没有元数据文件的在启动扫描时照旧删除；有元数据文件的是键恰好长这样的对象，保留。
   - 分片上传目录里的文件名都由本实现起，两种临时文件都直接删除。

## 影响

- 升级不需要迁移：旧版崩溃留下的临时文件在下次启动时清掉。
- 公开 API 不变。
