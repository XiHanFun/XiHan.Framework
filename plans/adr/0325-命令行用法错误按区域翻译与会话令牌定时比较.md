# ADR-0325 命令行用法错误按区域翻译与会话令牌定时比较

## 状态

已采纳（规范 `protocol/commandline.md`「操作映射」的失败、`plugin/handshake.md` §4 与 RFC-0017 的状态行已改；本仓库 `Hosting.CommandLine`、`Protocols.Mcp`、`Plugins.OutOfProcess` 实现，`Plugins.Wasm` 补用例；新增公开方法 `CommandLineFailure.WriteAsync(CommandContext, Error, int?)`（`Preview`）；错误码、消息键与配置键不变）；2026-11-27 由 ADR-0337 修订：「待定」的备选 11 定为采纳，Wasm 启动阶段的失败也排退避重启（见文末「修订」）。

## 日期

2026-11-27

## 背景

待办「边角问题」里的三条，仓库所有者已拍板，都要做：

1. **命令行的用法错误总是缺省区域**：`invoke` 的用法错误（没给操作 ID、`--json` 不是对象、`--timeout` 或 `--authorization` 不合法等）、找不到暴露给命令行的操作（`HOSTING_NOTFOUND_001`）、未知命令（`HOSTING_NOTFOUND_002`）与 `mcp` 命令的会话选项不合法，都在建调用上下文之前就返回。`CommandLineFailure.WriteAsync` 没有调用上下文时按 `LocalizationOptions.DefaultLocale` 翻译 stderr 的 `detail`，同一条命令行里的 `--locale` 只对发起了的调用生效：`app invoke orders.get --timeout abc --locale zh-CN` 的提示是英文，`app invoke orders.get --name x --locale zh-CN` 的失败是中文。
2. **会话令牌不是定时比较**：`PluginSessions` 以令牌为键查 `ConcurrentDictionary`，查找的比较不是常数时间。`plugin/handshake.md` §4 要求插件一侧按常数时间比较宿主带来的令牌，六个 SDK 都照做（`subtle.ConstantTimeCompare`、`timingSafeEqual`、`MessageDigest.isEqual`、`hmac.compare_digest`、`hash_equals` 与 Rust 手写的比较）；宿主一侧规范没写，.NET 也没做。
3. **Wasm 的绑定有孤立代理项没有用例**：ADR-0321 让下发给插件的绑定主值或属性值有孤立的代理项时组装配置请求即失败（`reason` 为 `binding '<名>' has a lone surrogate and cannot be encoded as UTF-8`），gRPC 与 Wasm 两种载体走同一处 `PluginConfigureRequests`，用例只在进程外一侧。所有者要求给 `Plugins.Wasm` 补用例，确认按配置失败、退避重试。

## 备选

命令行（第 1 条）：

1. **新增 `CommandLineFailure.WriteAsync(CommandContext, Error, int?)`**：采纳。命令环境里有标准错误、服务与命令行选项，按 `--locale` 选区域；没有发起调用的失败都改用它，原来的重载（带调用上下文）不变。
2. **给原方法加一个 `string? locale` 参数**：否决。改 `Preview` 的签名要按 ADR-0131 登记豁免；另加一个以 `string?` 代替 `InvocationContext?` 的重载，现有调用里传 `null` 的就有了歧义（CS0121）。
3. **命令执行期间按 `--locale` 安装 `MessageScope`**：否决。帮助与 `--help` 之后的弃用提示也会跟着变，规范写明它们按默认区域；`detail` 走的是 `IMessageLocalizer.Localize(error, locale)` 的显式区域，不是 `key.L()`，装作用域也管不到它。
4. **`--locale` 不合法时报用法错误**：否决。发起调用时不合法的 `--locale` 不进 Baggage、照常调用（`CommandLineInvocation`），没有发起调用的失败另起一条规则，同一条命令行会因为别的选项写错而多报一个错。
5. **新重载的 `exitCode` 可选**：否决。PublicAPI 分析器 RS0026 不许两个重载都带可选参数；按 KIND 映射时传 `null`。

会话令牌（第 2 条）：

6. **按令牌的 SHA-256 查找，再与签发的令牌 `CryptographicOperations.FixedTimeEquals`**：采纳。字典的键是散列，散列的比较泄露不了令牌（对方定不了散列的前缀）；对得上的候选再常数时间比较原令牌，耗时只取决于长度。查找仍是 O(1)，容量与清理不变。
7. **逐个会话做常数时间比较**：否决。每次回调 O(插件数)，比较的次数随插件数变；散列查找没有这个代价。
8. **带密钥的 HMAC 作键**：否决。令牌是 32 字节随机数，不可逆的散列就够，多一个密钥要管它的生命周期。
9. **按 UTF-8 还是按 UTF-16 码元取字节**：按码元（`MemoryMarshal.AsBytes`），不经编码：元数据里交来的任何字符串都有确定的键，孤立的代理项也不会被换成别的字符再去比。

Wasm（第 3 条）：

10. **照实测补两条用例**：采纳。`WasmPluginBindingTests` 先按所有者说的写了「启动时配置失败、推过 1 秒的退避就重试」，实测不过：Wasm 宿主启动阶段的失败不在后台重试，下一次调用按需再试（ADR-0260 第 4 条记下的载体差异，ADR-0067 也写过 Wasm 的握手失败不重试）；只有运行期崩溃之后的重建按 `lifecycle.md` §6 退避，重建时的配置失败接着退避。两条用例分别核对这两条路径，配置失败的原因都照 ADR-0321 的 `reason`。
11. **让 Wasm 宿主在启动阶段失败后也排退避重启**（与进程外一致）：这次不做，提请所有者决定。它改的是 ADR-0260 明确留下的差异，行为也随之变：退避期间的调用从「按需再试一次」变成 `PLUGINS_UNAVAILABLE_001`；`lifecycle.md` §6 写的是进程外的说法（「终止进程」），`wasm.md` §5 只写了陷阱后的重建，要不要把启动阶段的失败写进 `wasm.md` 也要一并定。

## 决策

1. **规范**：
   - `protocol/commandline.md`「操作映射」的失败：没有发起调用就返回的失败（用法错误，以及 `invoke` 的 `HOSTING_NOTFOUND_001`）的 `detail` 同样按 `--locale` 翻译：合法的区域名规范化后与调用一样协商出启用的区域（RFC-0010「协商与宿主」），没给或不合法时是默认区域；`mcp` 命令的会话选项不合法也是这样；帮助的文案仍按默认区域。
   - `plugin/handshake.md` §4：宿主校验回调的会话令牌同样按常数时间比较，不以令牌本身作散列表的键，先按令牌的密码学散列找候选、再与签发的令牌常数时间比较，令牌作废之后即不匹配。RFC-0017 状态行同日再写明一条，对应 ADR 加上本 ADR。
2. **命令行**（`Hosting.CommandLine`）：
   - `CommandLineFailure` 新增 `WriteAsync(CommandContext command, Error failure, int? exitCode)`：区域取 `CommandLineInvocation.FindLocale`（internal，`--locale` 合法时交出规范形式，与写进 Baggage 的是同一个值），经 `LocalizationOptions.Negotiate` 协商；没有时按默认区域；不写 `traceId`。原重载与新重载共用一处写出。
   - `InvokeCommand` 的四处、`CommandLineRunner` 的未知命令、`Protocols.Mcp` 的 `McpStdioCommand` 的会话选项改用新重载。`xihan` 工具（`Cli`）自己按 `--locale` 设默认区域，不改。
3. **会话令牌**（`Plugins.OutOfProcess` 的 `PluginSessions`，internal）：字典的键改成令牌 UTF-16 码元的 SHA-256（十六进制），值是签发的令牌与运行时；`TryResolve` 查到候选后 `FixedTimeEquals` 比较原令牌；`Revoke` 只移除原令牌对得上的会话（比较删）。签发、作废的时机与容量不变。
4. **Wasm 用例**（`Plugins.Wasm.Tests` 的 `WasmPluginBindingTests`）：
   - `Binding_WithALoneSurrogate_FailsTheConfigureStep_AndTheNextCallTriesAgain`（主值、属性值两例）：宿主启动后插件 `Failed`、`PLUGINS_UNEXPECTED_001` + `plugins.process.failed`、`phase` 为 `configure`、`reason` 照 ADR-0321，错误里没有值，重启 0 次，宿主 `Degraded`；下一次调用拿到同一个配置错误（不是插件不可用）；改正绑定之后的那次调用配置并启动，插件 `Ready`。
   - `Binding_WithALoneSurrogate_FailsTheRebuildAfterACrash_AndIsRetriedWithBackoff`：插件起来之后把绑定改成有孤立代理项的值、调用一次让它陷阱；推过 1 秒的退避，重建在组装请求时失败、原因相同、重启 1 次，之后的调用是 `PLUGINS_UNAVAILABLE_001`（仍在退避里，不抢跑）；改正之后推过 2 秒的退避，重建成功、插件 `Ready`、重启 2 次。
   - 新增夹具 `WatPlugin.ExpectingBindingAndTrapping`：照 `ExpectingBinding` 核对绑定，`xihan_invoke` 是 `unreachable`。
5. **测试**（命令行与会话令牌）：
   - `CommandLineRunnerTests.FailuresBeforeTheInvocation_AreLocalizedByTheLocaleOption`（`zh-CN`、`ja-jp`、`zh`、`de-AT` 四例，分别协商成 `zh-CN`、`ja-JP`、`zh-CN`、`de-DE`）：未知命令、没给操作 ID、未暴露的操作、`--json` 不是对象、`--timeout` 与 `--authorization` 不合法六种，`detail` 是那个区域的文案、不是 `en-US` 的，都没有发起调用。改之前四例都失败（英文）。
   - `CommandLineRunnerTests.FailuresBeforeTheInvocation_UseTheDefaultLocale_WithoutAValidLocaleOption`：没给、不合法与空的 `--locale` 都按默认区域。
   - `McpStdioTests.Command_InvalidOptions_AreReportedInTheLocaleOfTheLocaleOption`：`mcp --timeout 0 --locale zh-CN` 的用法错误是中文。
   - `PluginSessionsTests`（新增）：两个运行时各自的令牌查到各自；错的、空的、截短的、加长的、换了大小写的、前面多空格的与带孤立代理项的令牌查不到；任意一个位置只差一个字符的令牌查不到；作废不认识的与只差一个字符的令牌什么都不动，作废之后原令牌查不到、另一个照旧，再签发的是新令牌。这几条在改之前也通过（行为不变，比较是否常数时间测不出来）。

## 影响

- **公开 API**：`Hosting.CommandLine` 新增 `CommandLineFailure.WriteAsync(CommandContext, Error, int?)`（`Preview`）。其余不变；`PluginSessions` 是 internal。没有新的错误码、消息键与配置键。
- **行为**：
  - 命令行没有发起调用的失败的 `detail` 按 `--locale` 翻译，以前是默认区域；错误码、退出码与 JSON 的形状不变，仍然没有 `traceId`。
  - 回调的会话令牌查找每次多算一次 SHA-256（几百纳秒），结果不变。
  - Wasm 不变，只补用例。
- **规范**（规范工作区已提交）：`protocol/commandline.md`、`plugin/handshake.md` §4、RFC-0017 状态行，两处都是 MINOR（写明以前不作规定的行为；不改线上的内容）。向量不变。
- **六个 SDK**：不受影响。SDK 没有命令行宿主；插件一侧的令牌校验本来就按常数时间比较（只有一个令牌，不查表）。
- **文档**：`Hosting.CommandLine`、`Plugins.OutOfProcess`、`Plugins.Wasm` 的 README 已同步（Wasm 一页改正了「配置失败按退避重建时再试」的说法：启动时的配置失败是下一次调用再试）。
- **待定**：Wasm 宿主启动阶段的失败要不要也按退避重试（备选 11）。

## 理由

- 同一条命令行写的 `--locale`，用户期待的是同一种语言；没有发起调用只是失败得早，不该换一种语言。用与调用相同的规范化与协商，两种失败才是同一种语言。
- 会话令牌是插件冒充不了宿主、本机其他用户冒充不了插件的唯一凭据，两侧的比较都应是常数时间；散列查找加原令牌比较是常见的做法，不改容量与清理。
- 用例照实测写：所有者要的「按配置失败」成立、原因与进程外相同；「退避重试」只在崩溃之后的重建成立，启动阶段是按需再试，这条差异留给所有者决定，不在补用例时顺手改掉。

## 修订（2026-11-27）

「待定」里的备选 11 由 ADR-0337 定下：所有者拍板采纳，Wasm 宿主启动阶段的失败也排退避重启，与进程外一致，发现阶段的握手失败仍不重试；规范写进 `plugin/wasm.md` §5（启动阶段的失败一条）。随之：

- 决策 4 的第一条用例改为 `Binding_WithALoneSurrogate_FailsTheConfigureStep_AndIsRetriedWithBackoff`：退避期间的调用是 `PLUGINS_UNAVAILABLE_001`，推过退避重试、原因相同、重启 1 次，改正之后下一次退避的重建成功、重启 2 次。「下一次调用拿到同一个配置错误」「改正绑定之后的那次调用配置并启动」两句不再成立。第二条（崩溃之后的重建）照过、不改。
- 备选 10 里「启动阶段的失败不在后台重试，下一次调用按需再试」与「影响」里 Wasm README 的那句说明（「启动时的配置失败是下一次调用再试」）已经过时，README 改成「启动时与崩溃之后重建时的配置失败都按退避再试」。
