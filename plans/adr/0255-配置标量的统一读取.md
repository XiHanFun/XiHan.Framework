# ADR-0255 配置标量的统一读取

## 状态

已采纳（内核新增 `ConfigurationValues`，`Preview`；各包选项类的 `FromConfiguration` 改用它，公开面不变；规范不变）。

## 日期

2026-11-24

## 背景

- 各包的选项类逐键读配置、显式解析，不用 `Bind`（零反射、AOT 友好）。这条做法是对的，但「读一个秒数 / 整数 / 布尔 / 枚举」这件事每个包各写了一份私有函数：全仓 57 个 `FromConfiguration`，至少 24 个文件自带 `ReadSeconds` / `Seconds` / `Integer` / `ReadPositive` / `ReadBool` / `ParseEnum` 之类，其余内联。内核自己就有四份。
- 副本之间已经分叉：
  - **装不下的秒数**：只有少数几处判 `double.IsFinite`。其余遇到 `Infinity`、`1e400`，或有限但装不进 `TimeSpan` 的数（`1e300`），在 `TimeSpan.FromSeconds` 抛 `OverflowException`，消息里没有配置键。
  - **整数写法**：约三分之二用 `NumberStyles.None`，三分之一用 `NumberStyles.Integer`。同样的 `" 10"` 或 `"+5"`，有的包收，有的包拒。
  - **空串**：多数当非法，`OutboundAddressOptions` 与 `CloudEventsProtocolOptions` 当成没写。前者管的是「放不放开内网地址」。
  - **越界的异常类型**：多数抛 `ArgumentException`，工作流三个选项类抛 `ArgumentOutOfRangeException`。
  - **枚举**：`Enum.TryParse` 收数字文本，只有 `WebAuthnOptions` 显式排除。
  - **消息**：`but the value is`、`but was`、`got` 三种写法，有的键带引号有的不带。
- 这些差异没有哪一处是有意为之的设计，只是各写各的。

## 备选

1. **用 `ConfigurationBinder.Bind`**：否决。反射绑定，与零反射、AOT 的约束相悖，写错的值也不会带着配置键失败。
2. **用链接文件共享一份内部实现**：否决。`src` 下没有这个机制（ADR-0134）。
3. **放在 `Primitives`**：否决。原语层没有任何引用，`IConfiguration` 进不去。
4. **放在内核，公开**：采纳。所有包都依赖内核，内核已经引用 `Microsoft.Extensions.Configuration.Abstractions`。用友元的话二十多个包都要以确切版本引用内核。
5. **整数统一成 `NumberStyles.None`（更严）**：否决。会让现在能启动的配置（值两侧带空白、带正号）启动失败。统一成 `NumberStyles.Integer` 只放宽，不收紧，也与 `Microsoft.Extensions.Configuration` 自己的绑定一致。
6. **空串统一成「没写」（更松）**：否决。测试里明确把空串当非法（如 `XiHan:Workflow:HttpTimeoutSeconds`），「写了值就必须合法、不按缺省处理」是多数选项类文档里写明的规则。收紧的只有原先宽松的那两个类。

## 决策

1. 内核 `XiHan.Framework.Kernel.Hosting` 新增静态类 `ConfigurationValues`（`Preview`）：
   - `ReadSeconds(configuration, key)`、`ReadSeconds(configuration, key, allowZero)`
   - `ReadInt32(configuration, key, minimum)`、`ReadInt32(configuration, key, minimum, maximum)`
   - `ReadInt64(configuration, key, minimum)`、`ReadInt64(configuration, key, minimum, maximum)`
   - `ReadBoolean(configuration, key)`
   - `ReadEnum<TEnum>(configuration, key)`
2. 规则：
   - 键不存在返回 `null`，调用方回落到缺省值。写了值（含空串）就必须合法。
   - 不合法一律抛 `ArgumentException`，消息是 `'<完整配置键>' must be <应当是什么>, but was '<原值>'.`。传进来的是配置节时，配置键取节的路径加上键。
   - 数字按不变文化解析。整数用 `NumberStyles.Integer`。秒数用 `NumberStyles.Float`，必须有限、为正（或允许零时非负）、不超过 `TimeSpan.MaxValue`。
   - 布尔只认 `true` / `false`，不分大小写。
   - 枚举按成员名匹配，不分大小写，不收数字文本。
3. 各包选项类的 `FromConfiguration` 改用它，删掉自己的私有读取函数。选项的公开面、配置键、缺省值、取值范围都不变。各键原有的范围（下界、上界、是否允许零）原样传给统一函数；统一函数表达不了的校验（如两个键之间的关系、字符串文法）留在各包。

## 理由

- 配置写错是启动期最常见的问题，报错要让运维一眼看出是哪个键、应当写什么。这件事不该由五十多处各自保证。
- 统一之后，「这种写法收不收」只有一个答案，新增选项类不会再带来第 N 种写法。

## 影响

- **放宽**（原先拒绝、现在接受）：原先用 `NumberStyles.None` 的整数键，现在接受两侧的空白与前导的 `+`。
- **收紧**（原先接受、现在拒绝并带配置键）：
  - `XiHan:Security:Outbound:AllowLoopback`、`AllowPrivateNetwork` 与 `XiHan:Protocols:CloudEvents` 下的布尔、整数、枚举键写成空串。
  - 枚举键写成数字（如 `FailurePolicy = 1`）。
  - 秒数键写成 `Infinity`、`NaN` 或装不进 `TimeSpan` 的数：原先多数是不带配置键的 `OverflowException`，现在是带配置键的 `ArgumentException`。
- **异常类型**：工作流三个选项类的越界由 `ArgumentOutOfRangeException` 变为 `ArgumentException`。
- **消息文本**：统一成一种写法。按消息文本断言的测试随之更新；消息不是契约，配置键仍在消息里。
- 迁移分两步落地：先是内核自己的四个选项类，随后是其余各包。
