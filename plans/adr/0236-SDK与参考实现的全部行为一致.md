# ADR-0236 SDK 与参考实现的全部行为一致

## 状态

已采纳（补充 ADR-0233、ADR-0235；`spec/rfcs/0001-primitives.md`、`0002-manifest.md`、`0010-localization.md`、`0011-operations.md`、`conventions/capability-ids.md`、`manifest/manifest.schema.json` 随之修订，新增向量 `primitives/json-text.json`，`manifest/manifests.json`、`operations/payload-reasons.json`、`message-templates.json`、`kernel-messages.json`、`wire-encoding.json`、`error-codes.json`、`baggage-keys.json`、`capability-requirements.json`、`trace-context.json` 增加用例；Go 一致性模块新增 `rules.CheckJSONText`）。

## 日期

2026-11-16

## 背景

ADR-0235 之后，六个 SDK 与 .NET 回放同一批向量都通过，但规范还留着几处「不作规定」，各 SDK 在这些地方做法不同：

- 清单读取失败的错误码与参数：.NET 是 `KERNEL_CAPABILITY_006`，`reason` 是 System.Text.Json 或参数异常的英文消息；六个 SDK 都没用这个码，也写不出同样的消息。
- 重复成员查多深：Go 与 Python 查整段文本，Java 不查 `Result.value` 里面。
- 请求解码时缺少成员、`null` 落到非整数类型、载荷里的重复成员：各语言跟着自己的类型系统走。
- 调用器里几种失败同时成立时先报哪个。
- 精度超过 99、数组与对象作为模板参数、`type_mismatch` 的类型名、JSON 语法错误的位置、清单写出的排版。

用户要求 SDK 与 .NET 的全部行为一致。逐项实测 .NET 时又发现几处 .NET 自己的问题：

- **报错的先后随声明方式而变**：源生成对带 `required`、`init` 成员或主构造函数的类型先读完构造参数、再填其余成员，`{"count":"x"}` 报缺少 `name`，换成 `[JsonRequired]` 或反射解析就报 `$.count`。
- **模板交给 .NET 的格式化**：浮点的 `D` 抛出 `FormatException`；负数的 `X` 按类型宽度写补码；`E2`、`0.00`、`yyyy-MM-dd` 只有 .NET 认；数组写成 `System.Int32[]`；`float` 与 `decimal` 的文本与线上读回来的不同；区域的符号来自 ICU，随版本与全球化不变模式变化，en-US 的无穷是 `∞`。
- **正则的 `$` 在结尾换行之前也算匹配**：`xihan.tenant\n`、带换行的 `traceparent` 都能通过。
- **清单的检查不全**：Schema 里 `contributes.health` 的文法与中间件名非空没有核对；写出在 Windows 上是 CRLF，非 ASCII 字符写成 `\uXXXX`。
- **其他**：能力依赖的版本接受前导零（`@01`）；插件协议的错误细节里 `ulong.MaxValue` 让写出抛异常，`NaN` 写不出。

## 决策

规则仍以 .NET 的行为为基准，但凡结果取决于平台内部（解析器、格式化库、ICU 数据、类型声明方式）的，改为在规范里写死、.NET 照规范实现，不再交给平台。

- **JSON 文本的共同读取检查**（RFC-0001「JSON 文本」）：
  - 适用于 Result 与 Error 的线上编码、操作载荷与清单。
  - 语法按 RFC 8259，嵌套不超过 64 层；字符串必须是合法的 Unicode，不接受非法 UTF-8 与孤立的代理项；BOM 是语法错误。
  - 任何一层都不能有重复成员，名字按转义还原后比较。
  - 语法错误优先，位置只写 `$`；重复成员写第一处重复的路径。
  - .NET 新增内部的 `JsonText.Check`，Go 一致性模块的 `rules.CheckJSONText` 是独立的第二份实现，两者回放同一份 `json-text.json`。
- **载荷解码**（RFC-0011 规则 2）：
  - 先过共同检查；载荷里的重复成员不再取最后一个。
  - 成员名区分大小写，未知成员忽略，数字不从字符串读；整数不接受小数点与指数，超出范围即不符；浮点上溢为无穷。
  - 字符串、数组、对象与任意 JSON 接受 `null`；整数、浮点、布尔不接受。
  - 声明为必填的成员缺少时，在所在对象结束时报该对象的路径。
  - 按文本顺序报第一处问题。
  - .NET 新增内部的 `JsonRequestShape`，按序列化元数据以这个顺序先查一遍，反序列化只在它认不出的类型（自定义转换器、多态）上报错，报错的先后不再随声明方式变化。
- **清单**（RFC-0002 解析规则 2 与「写出」）：
  - 读取的顺序是：JSON 文本 → 字面量 `null` → 按 Schema 逐项核对 → 跨字段约束。
  - 错误都是 `KERNEL_CAPABILITY_006`：`invalid_json` 与 `invalid` 的 `reason` 是路径；`empty` 没有参数；跨字段约束保留 `primitives.manifest.*` 的键与 `id` 参数。
  - 接口版本不带前导零、不超过 2147483647。
  - Schema 给中间件名补上 `minLength: 1`，.NET 补上 `health` 的文法检查。
  - 写出的排版写死：两空格缩进、LF、末尾不换行、成员顺序固定、列表总写，字符串只转义必须转义的字符。
  - .NET 的读取改由内部的 `ManifestShape` 按 Schema 逐项核对，写出改为手写。
- **模板**（RFC-0010「模板」）：
  - 值先归到可移植的值模型：空、布尔、字符串、64 位整数、双精度浮点、数组、对象。超出 64 位的整数、单精度与十进制小数都是双精度浮点。
  - 数组与对象写成紧凑 JSON，对象成员按名字排序。
  - 说明符只认 `^[DdFfNnXx][0-9]{0,2}$`，不适用或不认的一律按无格式写出，宿主也一样。
  - 区域只改变小数点与分组符，符号来自规范里 10 种内置区域的固定表，表外的区域按不变文化。`NaN` 与无穷不随区域变化。
  - .NET 的 `MessageTemplate` 改由内部的 `MessageValueText` 按这些规则写出，不再调用 `IFormattable`。
  - 插件协议的错误细节按同一模型读写：整数值的浮点带 `.0`，非有限值写成字符串，数组与对象读成列表与字典。宿主上 `Describe` 一个插件错误，与插件本地写出的文本相同。
- **线上编码**（RFC-0001「Result」）：重复成员在任何一层都不合法；数字按值模型往返，64 位范围内的整数要精确，整数值的浮点写出时仍是浮点。
- **调用器**（RFC-0011 规则 10）：
  - SDK 的三个内置步骤放在与 .NET 内置中间件相同的位置，都是 `Beginning`，归属 `xihan.kernel.core`：Observe 阶段翻译异常，Resilience 阶段核对截止时间，Validate 阶段解码。
  - ADR-0235 写的「在第一个中间件之前核对截止时间」比 .NET 早过了 Ingress 与 Observe 阶段，撤销。
  - 进入管道前只核对未登记与类型不符，顺序固定。
- **类型不符**：`kernel.operation.type_mismatch` 只带 `id`，去掉实现语言的类型名 `expected` / `actual`；10 种语言文件同步修改。
- **文法的匹配**（RFC-0001「文法的匹配」）：
  - 规范的正则都按整串匹配，结尾的换行不例外。
  - .NET 原语与内核的正则从 `$` 改为 `\z`；能力依赖与能力声明的版本拒绝前导零。
  - 各文法向量补上结尾换行的反例。

## 理由

- 「以 .NET 实测为准」只在结果由 .NET 自己的代码决定时成立。结果取决于 System.Text.Json 的内部路径、ICU 的数据或 `IFormattable` 的实现时，其他语言没有办法复现，.NET 自己在不同部署与不同声明之间也不一致。这时把规则写死在规范里，由 .NET 照着实现，才谈得上一致。
- 每处改动都选各语言能精确实现的规则：值模型只有七种值，说明符只有四个字母，区域只有两个符号，清单与载荷的错误都只写路径。
- `type_mismatch` 去掉类型名，以及清单错误改为只写路径，都是放弃一点给人看的信息，换来跨语言逐字相同。原因文本原本就是英文，也违反了 RFC-0010 不把文案写进代码的约定。

## 影响

- .NET 的行为变化：
  - 模板：不再认 .NET 的格式串（`{when:yyyy-MM-dd}`、`{n:E2}` 按无格式输出）。浮点的 `D` 不再抛异常；负数的 `X`、`float` 与 `decimal`、数组与对象的文本都变了。区域的数字符号改用规范的表，表外区域（如 `it-IT`）按不变文化。
  - 载荷：重复成员与孤立的代理项是 `KERNEL_VALIDATION_001`，语法错误的 `reason` 一律 `$`；带 `required` 的请求类型报错的先后改为文本顺序。
  - 清单：错误的 `reason` 从英文消息改为路径；`health` 的文法与中间件名非空开始核对；写出的文本改为 LF 与最少转义。
  - 文法：结尾带换行的键、ID 与 `traceparent` 不再通过；能力依赖的版本不接受前导零与超过 32 位的值。
  - 类型不符：错误只带 `id`。
- 各 SDK 按本 ADR 改齐，回放全部向量。
- 一致性：新增 `json-text.json`，运行器的 `vectors` 子命令列出它，`rules` 新增 `CheckJSONText`；`ParseCapabilityRequirement` 限 32 位；`CanonicalResult` 先过共同检查，数字保留原文。
- 后续：本次只把原语与内核里的正则改为 `\z`，其他包里以 `$` 结尾的正则按同一规则另行清理。
