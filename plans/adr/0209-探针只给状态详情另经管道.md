# ADR-0209 探针只给状态，详情另经管道

## 状态

已采纳（`spec/protocol/mcp.md`「生命周期与传输」两条修订）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-22（`plans/5.0-安全审查.md`），低危，加固。

- `MapXiHanHealth` 的三个探针绕过内核管道，谁都能访问。响应体列出每个特性的 ID 与状态、每个健康条目的描述与数据（插件、Provider、容量用量），访问者能看出装配了什么。
- `MapXiHanHealth` 返回 `IEndpointRouteBuilder`，没法单独给某个探针加访问要求。探针本来也不能加：绕过管道的端点上的要求不会判定（ADR-0175）。
- MCP 的 `initialize` 与 `tools/list` 不要求认证。`serverInfo.version` 缺省是框架版本，告诉访问者该找哪个版本的已知缺陷。

复现：`WebHostTests.HealthEndpoints_ReflectApplicationState`。修正前探针的响应体里有 `features` 与 `contributions`。

## 备选

1. **探针改经管道、可加要求**：否决。Kubernetes 的探针不带凭据，应用未就绪时探针也必须可访问。
2. **探针按配置开关详情**：否决。缺省仍要选一个，选「给」就是原来的风险；开关也解决不了「详情要能加访问要求」。
3. **探针只给状态，详情另一个经管道的端点**：采纳。

## 决策

1. **探针**：`/startup`、`/ready`、`/live` 只写 `status` 与 `state`。`HealthResponse.Features` 与 `Contributions` 改为可空，探针不写出。
2. **详情**：新增 `MapXiHanHealthDetails()` / `MapXiHanHealthDetails(pattern)`（缺省 `/health/details`）。
   - 写出全部特性与健康条目，就绪时 200，否则 503。
   - 经内核管道，返回的约定构建器能加 `RequireXiHan*` 要求；应用未就绪时与其他端点一样是 503。
   - 框架不替应用决定谁能看，文档要求不要匿名开放。
3. **MCP**：
   - `serverInfo.version` 缺省取应用的版本：入口程序集的信息版本，去掉 `+` 之后的构建元数据，取不到为 `0.0.0`。
   - `tools/list` 仍不要求认证（匿名客户端要知道有哪些工具），不想公开就给整个端点加要求，凭据在外层认证。

## 影响

- 读探针响应体里 `features` / `contributions` 的监控要改读详情端点。
- 公开 API：`MapXiHanHealthDetails` 两个重载；`HealthResponse.Features`、`Contributions` 改为可空、不再 `required`。
