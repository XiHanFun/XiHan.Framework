# ADR-0246 插件回调的截止时间判断

## 状态

已采纳（`spec/plugin/invocation.md` §5 写明发出前第 ④ 步与回调途中的截止时间判断）。

## 日期

2026-11-19

## 背景

- `invocation.md` §5 规定，回调发出之前，回调上下文的「截止时间已过」按 `DeadlineExceeded`、「已被取消」按「`Cancelled`，回调上下文的取消信号已触发」。它没说「截止时间已过」按什么判断。回调途中截止时间到了该怎么结束，也没有写。
- 截止令牌（RFC-0003 第 1 条）由定时器触发，定时器走单调时钟；判断「已过截止时间」的时钟读数走墙上时钟。两者可能差几毫秒，令牌可能先到，也可能晚到。RFC-0004 已经写死：管道里截止时间步骤的归因只看令牌。
- 六个 SDK 的回调客户端各写各的。规范与六个 SDK 的 main 快进后，TypeScript 的 CI 偶发失败，循着这次失败在六个 SDK 里查出四类问题：
  - TypeScript：发出前与途中都只用 `Date.now()` 判断。截止信号由 Node 定时器触发，比墙上时钟先到时，发出前报成取消；途中还会抢先取消回调，grpc-js 报 `Cancelled`。
  - Python、PHP：回调上下文的取消信号一触发，就在本地取消回调。插件管道里截止时间步骤派生给处理器的信号，在截止时间也会触发，所以处理器里的回调只要途中到截止时间，结果都是 `KERNEL_CANCELLED_001`。Python 实测 20 次全错，PHP 6 次全错。PHP 的截止定时器另有一处：它若比墙上时钟先到，这次核对落空，之后不再核对，令牌不会按时触发。
  - Rust：发出前与途中被放弃时，都只按 `SystemTime::now()` 决定报超时还是取消。
  - Java：发出前只按 `Instant.now()` 判断；途中已经按令牌区分。
  - Go：发出前先看令牌再看时钟；途中只有 `ctx` 一个来源。没有问题。

## 备选

1. **只看令牌**：与 RFC-0004 一致。但发出前的核对与调用器进入时的核对（RFC-0011 规则 10）同类，是「要不要开始」的判断，本来就读时钟。令牌晚到的那段间隙里，时钟已过截止时间的回调还会发出去，再由 gRPC 立即以截止时间结束，白白多一次请求。否决。
2. **只看时钟**：就是 TypeScript、Rust、Java 原来的做法，令牌先到时把截止时间报成取消。否决。
3. **令牌已触发或按时钟已过，任一成立即截止时间已到**：采纳。六个 SDK 修复后都是这样。

## 决策

1. 发出前第 ④ 步：截止令牌已触发，或者按时钟已过截止时间，任一成立即截止时间已到，按 `DeadlineExceeded`。否则已被取消时，按「`Cancelled`，回调上下文的取消信号已触发」。
2. 回调途中：
   - 截止时间到了，结果是 `DeadlineExceeded` 那一行。可以交给 gRPC 库按同一个截止时间在本端中止；在本地中止时，同样按第 1 条判断截止时间已到。
   - 调用方取消、而截止时间未到时，在本地中止回调，按「`Cancelled`，取消信号已触发」。
   - 回调客户端不能只凭取消信号已触发，就把回调当作调用方取消。
3. 管道里截止时间步骤的归因不变，仍只看令牌（RFC-0004）。
4. 规范 `CHANGELOG.md` 记为 MINOR：写死以前不作规定的行为，与较早的对端照常互通。

## 理由

- 两个时钟谁先到都不能决定结果，所以任一成立即算到期，结果才不随时钟的先后而变。
- 发出前与调用器进入时同属「要不要开始」，读时钟与 RFC-0011 规则 10 一致；归因仍只认令牌，不把时钟判断带回管道。
- 途中的错误不在映射表本身，而在谁中止了调用：本地以「取消」中止，结果就落到取消那一行。所以要写的是「截止时间到了的结果」，不限定谁来中止。

## 影响

- 线上行为不变，宿主一侧没有改动。
- 六个 SDK 都已照此修复，每个都有先复现失败、再修复通过的用例；推到 dev 并快进 main 后 CI 全部通过：
  - TypeScript `b9f70fb`：内部函数 `isDeadlineSignalled`，读上下文自己的截止信号。
  - Python `9c58739`：截止时间已到时不在本地取消。
  - PHP `ae5816b`：按取消原因区分；新增内部类 `DeadlineTimer`，定时器先到时按剩下的时间重排。
  - Rust `1827667`：`abandoned` 先看截止令牌。
  - Java `6fa2823`：`refuse` 先看截止令牌。
  - Go：不用改。
- .NET 不认领 `plugin` 档，没有插件一侧的回调客户端，不受影响。
