# ADR-0178 S3 命名实例必须自带密钥

## 状态

已采纳（RFC-0012「Provider」修订命名实例一条）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-03（`plans/5.0-安全审查.md`），高危。

- `S3ObjectStorageFeature.CreateClient` 在 `AccessKey` 或 `SecretKey` 为空时调用 `new AmazonS3Client(config)`，即 AWS SDK 的默认凭据链：环境变量、共享配置文件、ECS 任务角色、EC2 实例角色。
- 命名实例的设置（`S3ObjectStorageOptions.FromSettings`）接受缺省的密钥；ADR-0117 写明这些设置可以由租户填写（例如 BasicApp 的存储配置）。出站地址策略帮不上忙，真实的 S3 端点是公网地址。
- 后果：能登记存储实例的租户管理员只填 `Region`、关掉 `ConditionalWrites`、不填密钥，就能经对象存储接口列举、读写宿主角色能访问的任何桶；`EnsureBuckets` 还能在宿主账号里建桶；预签名地址也以宿主的身份签。唯一的前提是宿主带着环境凭据，而这正是 AWS 上的常见部署。

复现：`S3NamedInstanceCredentialTests`。修正前，不带密钥的命名实例照常建出。

## 备选

1. **命名实例一律禁止环境凭据**：否决。运营方自己登记的多个桶（不经租户）用实例角色是合理的部署，应该能显式打开。
2. **实例设置里加一个「用环境凭据」的键**：否决。设置正是租户能填的部分，开关放在那里等于没有。
3. **命名实例必须给两项密钥，环境凭据只由运营方开关打开**：采纳。

## 决策

1. **`S3BlobStoreProvider.CreateAsync` 核对密钥**：
   - 只给一项密钥：总是拒绝。
   - 两项都没给：运营方没打开开关时拒绝。
   - 拒绝时以 `OBJECTSTORAGE_VALIDATION_003`（定义不合法）返回，原因说明要给两项密钥，或由运营方打开开关。
2. **运营方开关**：配置键 `XiHan:ObjectStorage:S3:NamedInstancesUseAmbientCredentials`，缺省 `false`，不是布尔值时构造 Provider 即抛出。
   - `S3BlobStoreProvider` 新增带 `IConfiguration` 的公开构造，容器按它建 Provider。
   - 原有的三参数构造保持「不允许环境凭据」。
   - 键不在实例设置的已知键里，实例设置打不开它。
3. **缺省实例不变**：缺省实例的配置是运维的，两项都空时照旧走凭据链。

## 影响

- 行为：没有密钥的 S3 命名实例不再建出。依赖实例角色的部署，由运营方打开开关；租户填写的实例要给出自己的密钥。
- 公开 API 只有新增：`S3BlobStoreProvider.AmbientCredentialsKey` 与带 `IConfiguration` 的构造。`S3BlobStoreProvider` 是 `Preview`，GA 前修改。
