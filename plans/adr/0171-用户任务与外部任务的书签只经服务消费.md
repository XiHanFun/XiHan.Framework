# ADR-0171 用户任务与外部任务的书签只经服务消费

## 状态

已采纳（RFC-0021「书签」修订 `ResumeAsync` 一条）。

## 日期

2026-11-12

## 背景

API 审查第 6 批留作后续的一项：`IWorkflowEngine.ResumeAsync(bookmarkId, inputs, expectedKey)` 能直接消费用户任务的书签，是否绕过任务服务的操作者校验待确认。核实结论：会绕过。

- 任务 ID 就是书签 ID。指派人校验只在任务服务里（`WORKFLOW_DENIED_001`），校验通过后以 `expectedKey = ActorId` 调引擎；引擎只在 `expectedKey` 非空时比对书签的键。
- 直接调 `ResumeAsync(taskId, inputs, null)`：
  - 不校验指派人。
  - `inputs` 里的 `actorId` 是调用方写的，`UserTaskActivity` 把它原样记进审批历史与已通过名单，能以别人的名义审批、凑会签阈值。
  - 结果不在允许范围时活动换一个新书签重新挂起，调用方收到成功，任务 ID 却变了。
  - 不发 `workflow.task.completed`。
- 外部任务同理：直接以 `outputs` 恢复 `External` 书签，不校验持锁的工作者（`WORKFLOW_DENIED_002`），不发 `workflow.external.completed`。
- 框架没有把 `ResumeAsync` 暴露成操作，风险在应用：把它做成通用的「恢复书签」接口开给最终用户，就能越权办理任务。RFC 与文档把它写成通用入口，没有说这两种书签必须走服务。
- 复核时还怀疑外部任务服务「先在锁内校验持锁、交还锁后再调引擎」之间有竞态窗口。不成立：实例锁由作用域持有到事务结束，交还只把锁标为空闲，引擎复用它，别的工作者在这期间领不到同一书签。

## 备选

1. **只写文档，说明 `ResumeAsync` 不要开放给最终用户**：否决。两种书签有身份校验与事件，引擎给出一条不经它们的路径本身就是契约缺口，不能只靠调用方自律。
2. **活动在恢复时自己校验 `inputs.actorId` 等于书签的键**：否决。`actorId` 本来就由调用方给，校验不出冒用；认领、结果校验与完成事件仍在服务里，引擎路径照样跳过。
3. **公开的 `ResumeAsync` 拒绝全部内置种类，只留应用自定义的书签**：否决。`Timer`、`Retry`、`NodeTimeout`、`Signal` 等没有身份校验，受信代码手动提前触发是合理用法；它们的消费方是引擎与轮询器，拒绝它们解决的不是这里的问题。
4. **公开的 `ResumeAsync` 拒绝 `UserTask` 与 `External`，两个服务与轮询器走引擎的内部入口**：采纳。

## 决策

1. **`ResumeAsync` 遇到 `UserTask` 与 `External` 书签返回 `WORKFLOW_CONFLICT_003`**，消息键 `workflow.bookmark.service_owned`（参数 `id`、`kind`）。
   - 先按分区查书签，别的分区的仍按不存在处理，不暴露它们是否存在。
   - 种类在书签的一生里不变，在取实例锁之前判定。
2. **引擎加内部入口 `ResumeOwnedAsync`**，任务服务、外部任务服务在各自校验之后用它消费书签；轮询器解锁到期的外部任务也用它。
   - 引擎以具体类型登记，`IWorkflowEngine` 转发到同一个作用域实例，三者在同一个包里，不新增公开 API。
3. **写明 `ResumeAsync` 是给受信代码的系统级入口**：不校验调用者身份，`inputs` 原样交给活动，应用不得直接开放给最终用户。`expectedKey` 保留给应用自定义的书签。
4. **一致性套件**（`WorkflowTaskConformance` 用例 9）：冒用指派人、传对期望的键、持有外部任务的锁都不能经引擎消费，书签与实例不变、不发完成事件；服务照常完成；锁到期的解锁不受影响。

## 影响

- 行为：直接以 `ResumeAsync` 办理用户任务或完成外部任务的代码改为返回 `WORKFLOW_CONFLICT_003`。
- 源码迁移：
  - 办理用户任务：`engine.ResumeAsync(taskId, inputs, actorId, ct)` → `tasks.CompleteAsync(new UserTaskCompletion(taskId, actorId) { Outcome = …, Comment = …, Variables = … }, ct)`。
  - 完成外部任务：`engine.ResumeAsync(taskId, new JsonObject { ["outputs"] = … }, null, ct)` → `external.CompleteAsync(new ExternalTaskCompletion(taskId, workerId) { Outputs = … }, ct)`，失败用 `FailAsync`。
- `IWorkflowEngine` 是 `Preview`，GA 前修改，不需要登记豁免（ADR-0131）。
- 公开 API 只新增消息键常量 `WorkflowMessages.BookmarkServiceOwned`；错误码不变。
