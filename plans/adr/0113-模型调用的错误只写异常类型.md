# ADR-0113 模型调用的错误只写异常类型

## 状态

已采纳（`spec/rfcs/0022-ai.md` 随之修订）。修订 ADR-0112「没有改的」一节：模型 Provider 的 `reason` 不再是异常消息。

## 日期

2026-11-04

本 ADR 记录第二十六批回灌（`ae-batch-backlog.md`，用户定「另立一批改」）的决定。

## 背景

ADR-0111、ADR-0112 让知识库存储的 `reason` 只写异常类型。模型 Provider 的 `AI_UNAVAILABLE_001` 是同一类问题：

- `IAIChat` 与知识库的嵌入调用把异常消息放进 `reason`，经 `Result` 返回给调用方，`ProblemResponse` 把它写进响应；
- 消息模板 `ai.model.unavailable` 里也有 `{reason}`，异常消息会跟着文案一起出去；
- Provider 可以自定义（落库目录、自写工厂），异常消息可能带端点地址或凭据片段。

修前用 `ModelErrorTests` 复现：`reason` 是 `POST https://llm-gateway.internal:8443/chat failed.`。

## 决策

1. 聊天与嵌入调用抛出时，`AI_UNAVAILABLE_001` 的 `reason` 是异常类型的全名。错误码、消息键、`provider` 与 `reason` 两个参数名都不变。
2. 完整异常进日志：每次失败一条 Warning，带 Provider 名与异常，类别是发起调用的组件（`AIChat`、`KnowledgeIngestor`、`KnowledgeRetriever`）。
3. 超时（`AI_TIMEOUT_001`）与调用方取消不算模型调用失败，不记这条日志。
4. 为此 `AIChat`、`KnowledgeIngestor`、`KnowledgeRetriever` 的构造增加 `ILoggerFactory`。这是公开签名变化，经容器解析不受影响。

## 影响

- 变的是 `reason` 的值：从异常消息变成类型全名，如 `System.Net.Http.HttpRequestException`。调用方看到的文案随之变化，排查时看日志。
- 流式调用不变：流开始之后模型端点的异常在枚举时原样抛出，不经这个错误。
- 直接从目录取 `IChatClient` 的调用不变，拿到的是 SDK 的原始异常。

## 没有改的

护栏抛出时的 `AI_UNEXPECTED_001`（`ai.guardrail.failed`）的 `reason` 仍是异常消息，这次的决定只覆盖模型调用。
