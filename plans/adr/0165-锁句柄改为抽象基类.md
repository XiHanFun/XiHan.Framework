# ADR-0165 锁句柄改为抽象基类

## 状态

已采纳（RFC-0006「分布式锁」）。

## 日期

2026-11-11

## 背景

API 审查第三节「缓存」一组：`IDistributedLock` 是 `Stable` 的公开接口，但它返回的 `LockHandle` 是密封类，构造是 `internal`。

- 框架之外实现不了这个接口：ZooKeeper、etcd、数据库行锁都无从交出句柄。
- 释放只执行一次的保证靠一个普通的 `bool`，并发释放时可能执行两次底层删除。

审查同时指出锁不能续约，雪花 ID 的工作节点租约（`LeasedWorkerIdSource`）只能先释放再获取，中间有被别的实例抢走的窗口。续约要在存储层有原子的「令牌匹配才延期」原语：`ICacheStore` 现在只有按值比较删除。Redis 用脚本可以做到，远程 Provider 的操作集（RFC-0019）要同步加一项，涉及跨语言协议，单独设计。

## 决策

1. **`LockHandle` 改为抽象基类**（仍是 `Stable`）：
   - 受保护构造收资源与令牌。资源不能是 `default`，令牌不能为空白。
   - 公开的 `ReleaseAsync(ct)` 不是虚方法，以原子交换保证只调用一次受保护的抽象方法 `ReleaseCoreAsync(ct)`，之后都返回 `false`。
   - `DisposeAsync` 以 `CancellationToken.None` 释放。
2. **框架的实现改为派生**：`StoreDistributedLock` 的句柄是内部派生类，释放按令牌比较删除锁条目，行为不变。
3. **续约留作后续一项**：
   - 以后在存储层加原子的比较后延期原语、远程操作集加对应操作。
   - 届时 `LockHandle` 加一个虚的 `RenewAsync`，缺省不支持，已有派生类不受影响。

## 影响

- 只经 `IDistributedLock.TryAcquireAsync` 拿句柄的调用方不用改。
- 包外实现锁的 Provider 派生 `LockHandle` 并实现 `ReleaseCoreAsync`。
- GA 前修改，不需要登记豁免（ADR-0131）。
