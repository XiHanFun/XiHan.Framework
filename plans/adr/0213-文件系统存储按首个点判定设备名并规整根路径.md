# ADR-0213 文件系统存储按首个点判定设备名并规整根路径

## 状态

已采纳（实现修正，契约不变）。

## 日期

2026-11-13

## 背景

5.0 安全审查 S-40（`plans/5.0-安全审查.md`），低危。

- 键的段编码成文件名时，Windows 设备名要打破。原先只比较整段与「去掉最后一个扩展名」后的部分：
  - Windows 看的是首个点之前，`nul.tar.gz` 与 `NUL` 等价，原先不编码，在 Windows 上写不进去（或写到设备上）。
  - 名单缺 `COM0` 与 `LPT0`。
- `RootPath` 原样取 `Path.GetFullPath`，以分隔符结尾时（`/var/blobs/`）保留结尾的分隔符。路径落在根内的判定拼出 `//` 前缀，任何对象路径都不匹配，每个操作都抛 `InvalidOperationException`。

复现：`FileSystemPathTests` 的两个用例。

## 决策

1. **设备名**：取段里首个点之前的部分与名单比较，名单补上 `com0`、`lpt0`。命中时编码首字符（`con.tar.gz` → `%63on.tar.gz`）。
   - 带上标数字的 `COM¹` 等与带 `$` 的 `CONIN$` 等含非安全字符，本来就会编码，不进名单。
2. **根路径**：`RootPath` 取完整路径后去掉结尾的目录分隔符（文件系统的根目录 `C:\`、`/` 除外）。根内判定的前缀按根是否以分隔符结尾决定补不补分隔符。

## 影响

- 编码与平台无关。Linux 与 macOS 上已有的这类键（`nul.tar.gz`、`com0` 等）换了文件名，升级后按键读不到、列举也跳过。要重新写入，或把内容文件与元数据文件的首字符改成编码后的 `%XX`。
- `FileSystemObjectStorageOptions.RootPath` 读出的值不再带结尾分隔符。
- 公开 API 不变。
