# ADR-0221 命令行遍历不跟随符号链接

## 状态

已采纳（`spec/migration/README.md`「命令形态」一条修订）。

## 日期

2026-11-13

## 背景

5.0 安全审查「加固建议」（`plans/5.0-安全审查.md` 第四节）。

- `xihan migrate` 递归枚举 `--path` 下的文件交给规则改写，`xihan setup` 递归找项目文件与 `.props` 判断框架版本。两处都跟随目录链接。
- 链接指向 `--path` 之外时，迁移会改写别处的文件（另一个仓库、系统目录里恰好匹配规则的文件）；文件链接同样会让改写落到链接的目标上。
- 目录链接指回祖先时遍历成环，一直走到路径过长才以 `IOException` 失败。

复现：`MigrationRunnerTests.Run_DoesNotFollowSymbolicLinks_OutOfTheTree`。修正前，遍历沿着指回项目目录的链接一路递归，以路径过长的 `IOException` 失败。

## 决策

1. `migrate` 跳过链接的目录与链接的文件，`setup` 的项目探测跳过链接的目录。
2. 判定用 `FileSystemInfo.LinkTarget`：只认符号链接与目录联接。不用重解析点属性，云盘（如 OneDrive）的占位文件也带这个属性，按它判定会漏掉正常的文件。
3. `--path` 本身是链接时照常处理：那是调用方明确给出的根。

## 影响

- 靠链接把别处的源码挂进项目、又希望 `migrate` 一并改写的仓库，要对链接的目标单独运行一次。
- 公开 API 不变。
