# ADR-0198 多租户实体的唯一索引含租户

## 状态

已采纳（RFC-0005「索引声明」与「标识生成」各一条修订）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-33（`plans/5.0-安全审查.md`），低危，这里复现确认。

- 共表的多租户实体，不含 `TenantId` 的唯一索引在所有租户之间唯一。
- A 租户新增一行，键撞上 B 租户的行，得到 `PERSISTENCE_CONFLICT_003`；换一个键就成功。调用方能逐个试出别的租户用过哪些键（邮箱、编号、别名）。
- 主键同理：调用方自选标识新增，撞上别的租户的行得到 `PERSISTENCE_CONFLICT_002`（EF Core 仓储的 `FindAsync` 与 SqlSugar 的按主键预查不分租户）。

复现：`EntityIndexesTests`。修正前，多租户实体上不含 `TenantId` 的唯一索引照常解析、照常建出。

## 备选

1. **自动把 `TenantId` 加进多租户实体的唯一索引**：否决。改了作者声明的列与索引名，两个 Provider 的库与代码对不上；确实要跨租户唯一的键也没法表达。
2. **撞键时报成与成功无法区分的结果**：否决。约束确实拒绝了写入，假装成功就是丢数据。
3. **唯一索引必须含 `TenantId`，跨租户唯一显式声明**：采纳。
4. **主键改成（租户，标识）的复合键**：否决。所有仓储、按标识的批量方法与实体目录都要改。主键的预言机只在调用方自选标识时存在，服务端生成的标识猜不出来。

## 决策

1. **唯一索引**：实体实现 `IMultiTenant` 时，唯一索引的列必须含 `TenantId`。
   - 确实要跨租户唯一的键写 `[EntityIndex(…, IsUnique = true, AcrossTenants = true)]`，接受撞键告诉调用方别的租户已有这个键。
   - `AcrossTenants` 只用在不含 `TenantId` 的多租户唯一索引上，别处写是声明错误。
   - 违反时 `EntityIndexes.Resolve` 抛 `InvalidOperationException`。两个关系型 Provider 在启动建模或建表时失败。
2. **主键**：仍在表内全局唯一，不分租户。规范写明：多租户实体的标识由服务端经 `IIdGenerator<TKey>` 生成，不取调用方自选的标识；调用方给的业务键放进含 `TenantId` 的唯一索引。

## 影响

- 破坏性变更：多租户实体上不含 `TenantId` 的唯一索引在启动时失败。
  - 迁移：把 `TenantId` 加进索引的列。确实要跨租户唯一时写 `AcrossTenants = true`。
  - 已有的库要按新的列重建索引：索引名随列变化，旧索引要自己删掉。
- 公开 API：`EntityIndexAttribute.AcrossTenants`。
- 框架自己的多租户实体（工作流定义）已经含 `TenantId`，不受影响。
- 主键的预言机靠约定避免，框架不拦截调用方自选的标识。
