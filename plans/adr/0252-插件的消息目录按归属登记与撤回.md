# ADR-0252 插件的消息目录按归属登记与撤回

## 状态

已采纳（规范 RFC-0010、RFC-0017、RFC-0018、`plugin/handshake.md` §3、`plugin/invocation.md` §1、`plugin/lifecycle.md`、`plugin/wasm.md`、`conventions/error-codes.md` 同步修订）。

## 日期

2026-11-23

## 背景

- 本地化器在构造时取容器里的 `IEnumerable<MessageCatalog>`，此后目录不变。
- 插件的消息目录随握手到来：
  - 配置阶段发现的插件，特性在 `Configure` 里 `AddMessageCatalog`，与宿主的同名目录合并为一份；
  - 运行期 `LoadAsync` 的插件，目录无处可去；首次握手失败、重试才成功的插件，宿主只记一条警告「宿主重启后生效」。
- 卸载不撤回目录。再加载新版本时，目录变了要重启宿主才生效。
- 结果是运行期加载的插件的失败文案、权限码显示名（`permissions.<码>.name`）、接口文档的标题都只能退回键与参数的描述。
- 协议适配器已经跟随操作登记表（ADR-0251），运行期加载的插件立即有路由、进文档，文档里的文案却缺着。BasicApp 的插件管理只走运行期加载，正好落在这个缺口上。
- 握手一节写的「目录名重复时宿主已有的优先并记警告」与实现不符：实现照 RFC-0010 合并，模板冲突即启动失败。

## 备选

1. **运行期加载时改写容器**：否决。容器建好之后不能再登记服务，本地化器手里的列表也不会变。
2. **本地化器加一个可变的「额外目录」列表，宿主直接往里写**：否决。两个本地化 Provider 各写一遍，归属、冲突与撤回的规则没有地方统一。
3. **抽象包里加按归属登记的目录登记表，本地化器从它读**：采纳。与操作登记表的 `AddRange` / `RemoveOwnedBy` 同一个形状，插件宿主以清单 ID 为归属。

## 决策

1. `Localization.Abstractions` 新增 `MessageCatalogRegistry`（`Stable`）：
   1. 容器里是单例，`AddMessageCatalog` 一并登记。
   2. `Catalogs` 是当前快照：注册的目录在前，按归属登记的目录在后，按登记顺序。
   3. `Add(owner, catalogs)` 以一个归属登记一组目录，全进或全不进。与已有的同名目录或同一组里的同名目录在同一键同一区域的模板不同时，整组不登记，抛出携带 `LOCALIZATION_CONFLICT_001` 的 `FrameworkException`。同名目录只核对、不合并成一份，撤回时各自离开。空的一组什么都不做；同一归属已有目录时再 `Add` 抛 `InvalidOperationException`。
   4. `RemoveOwnedBy(owner)` 撤回一个归属的全部目录，返回撤回的份数。
   5. 不提供变更令牌：本地化器每次查找读快照，不缓存。
2. `AddMessageCatalog(owner, catalog)` 在配置阶段按归属注册，不与同名目录合并。建立登记表时按归属成组登记，规则同 `Add`，冲突即启动失败。
3. 本地化器：
   1. `InMemoryMessageLocalizer` 与 `DatabaseMessageLocalizer` 各加一个接收登记表的构造函数，原来接收目录列表的构造函数保留，包一份自己的登记表。
   2. 两个特性以工厂按容器的登记表创建本地化器。
   3. 每次查找只取一份快照，同一次查找不会前后看到不同的目录。
4. 插件宿主（进程外与 Wasm）：
   1. 配置阶段发现的插件，目录以清单 ID 为归属注册（`AddMessageCatalog(owner, catalog)`）。
   2. 宿主附着到容器时取得登记表。运行期 `LoadAsync` 与首次握手失败后重试成功的插件，目录先于权限码与代理操作登记，三者全进或全不进：目录冲突时整个插件登记失败，返回 `LOCALIZATION_CONFLICT_001`；权限码或操作登记失败时目录一并撤回。
   3. 目录先于操作：操作一进登记表，接口文档随之重新生成（ADR-0251），这时文案已经能解析。
   4. `UnloadAsync` 先撤回代理操作与权限码，再撤回目录。配置阶段注册的同样撤回，再加载按新版本的目录重新登记。
   5. 重试成功的插件只剩订阅要重启宿主才生效，警告只说订阅。
5. 规范：
   1. RFC-0010 新增「归属目录」。
   2. `handshake.md` §3 第 6 条改为按归属登记、照 RFC-0010 核对冲突，删去「宿主已有的优先并记警告」。
   3. `invocation.md` §1 把目录写进一次登记与撤回，「不随卸载撤回」里只剩订阅与 gRPC 方法。

## 理由

- 运行期加载与配置阶段发现走同一套目录规则：同名核对、按归属撤回，不再有「重启后生效」的半状态。
- 查找顺序不变（同一键先找到的优先），按归属登记的目录排在后面，插件不能覆盖宿主已有的键。
- 冲突在登记时整组拒绝，与权限码重复、操作重名的处理一致（ADR-0080）。被拒的只是那个插件，宿主照常运行。
- 抛 `FrameworkException`、由插件宿主转成错误，与 `PipelineBuilder.UseOwned` 的做法一致；冲突是插件打包的问题，文案用英文。

## 影响

- `Localization.Abstractions`：新增 `MessageCatalogRegistry`、`AddMessageCatalog(owner, catalog)`（公开 API 只增）。
- `Localization.InMemory`、`Localization.Database`：本地化器各增一个构造函数，特性改用工厂登记。在容器里按类型自行登记本地化器的应用，会因两个构造函数参数个数相同而解析失败，改用工厂。
- `Plugins.Protocol`：`PluginContributions` 的登记与撤回带上目录登记表。
- `Plugins.OutOfProcess`、`Plugins.Wasm`：配置阶段的目录按归属注册；运行期加载、重试成功、卸载都登记或撤回目录；重试成功的警告只说订阅。
- 同名目录以前在容器里合并为一份，现在插件那份单独登记。容器里的 `MessageCatalog` 不再含插件的部分，要看插件的目录读 `MessageCatalogRegistry.Catalogs`。
- 文档：插件总览、进程外与 Wasm 包页、本地化抽象包页、本地化一章、远程缓存包页、OpenAPI 页同步。
