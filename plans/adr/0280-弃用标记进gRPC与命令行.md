# ADR-0280 弃用标记进 gRPC 与命令行

## 状态

已采纳（`Protocols.Grpc` 生成的 `.proto` 给 `Stability.Deprecated` 的操作的 `rpc` 写 `option deprecated = true;`；`Hosting.CommandLine` 调到弃用的操作时在 stderr 写一行本地化的提示，带 `--help` 的命令行指向弃用的操作时在帮助之后标出来；调用语义、stdout 与退出码都不变；`protocol/grpc.md`、`protocol/commandline.md` 已补。MCP 不做）。

## 日期

2026-11-24

## 背景

- ADR-0273 让 `Stability.Deprecated` 的操作在 OpenAPI 文档里带标准的 `deprecated: true`。弃用只在契约的稳定性上声明一次（`OperationContract.Stability`），各协议适配器都从 `OperationDescriptor.Contract` 读；那次只做了 HTTP，「影响」里列了别的协议可以怎样体现。这次做其中的 gRPC 与命令行。
- **gRPC 现在怎样暴露操作**（`Protocols.Grpc`）：
  - 运行期：`OperationMethodProvider` 经 `IServiceMethodProvider` 把操作表里的每个操作绑定成 `Method<byte[], byte[]>`，消息以字节数组进出，protobuf 的编解码按操作的 JSON Schema 在处理器里做。包不引用 `Google.Protobuf`，没有 `MethodDescriptorProto`，也没有 gRPC 反射服务。
  - 对外的描述只有一份：`ProtoFileBuilder` 从操作表生成的 `.proto` 文本，`GET /operations.proto` 发布，客户端用它跑 protoc 或 grpcurl。
  - 所以「方法描述」能落笔的地方只有这段文本。protobuf 为方法定了标准选项 `google.protobuf.MethodOptions.deprecated`，写在 `.proto` 里是 `rpc … { option deprecated = true; }`；各语言的 gRPC 生成器据此给生成的方法加弃用标记（C# 的生成器加 `[Obsolete]`，本机核对过，见「测试」；其余语言按各自生成器的做法，这里没有逐个核对）。
- **命令行现在怎样暴露操作**（`Hosting.CommandLine`）：
  - `help` 只列内置命令（`ICommand`：`help`、`graph`、`pipeline`、`operations`、`invoke`，以及 `Protocols.Mcp` 注册的 `mcp`）与一句简写的说明，不逐个列出操作；带 `--help` 的任何命令行打印的都是这同一份帮助。
  - 操作的列表是 `operations`：每行 `ID<TAB>稳定性<TAB>暴露<TAB>授权`，弃用的操作在稳定性一列本来就是 `Deprecated`。
  - 调用是 `invoke <operation-id>` 或简写 `<resource> <verb>`：成功把响应 JSON 写到 stdout，失败把一行 JSON 写到 stderr，退出码按错误 KIND。调到弃用的操作时没有任何提示。
  - `protocol/commandline.md`「进程约定」：日志只写 stderr，stdout 只有命令输出。
- 规范的一致性向量里，协议映射相关的只有 `context/http-deadline.json`（请求头到截止时间）与 `operations/payload-reasons.json`（载荷错误的文本），都表达不了「弃用的操作怎样映射」。

## 备选

1. **gRPC 给 `.proto` 里的 `rpc` 加一行注释（`// Deprecated`）而不写选项**：否决。注释只给人看，protoc 与各语言的生成器不认；标准选项就是为这件事定的，与 ADR-0273 选 OpenAPI 标准字段是同一个理由。
2. **gRPC 调用弃用的方法时在响应头或尾部元数据里带提示**：不做。任务只要求描述里可见；契约没有「何时移除」「换成哪个操作」的字段，现在能带的只有一个布尔，而客户端从生成的代码上已经看得到。HTTP 运行期的 `Deprecation` 头同样没有做（ADR-0273「影响」）。
3. **为了有 `MethodDescriptorProto` 而引入 `Google.Protobuf` 或 gRPC 反射服务**：否决。这个包的设计就是不依赖 `Google.Protobuf`、由 Schema 推线格式；为一个布尔选项引入描述符与反射是另一个量级的决定。规范里写明：实现另外发布方法描述时同一个选项也要带上，将来加反射服务时不会漏。
4. **不弃用的 `rpc` 也写成带花括号的形式（空的选项块）**：否决。没有弃用操作的应用，`.proto` 应当逐字节不变。
5. **`service` 里所有操作都弃用时给 `service` 也写 `option deprecated = true;`**：不做。服务名来自操作 ID 的资源段，不是契约里的一个对象，没有自己的稳定性；逐个方法已经标了。
6. **命令行在 `help` 里逐个列出操作并标注弃用的**：否决。帮助现在不列操作，应用可以有几百个操作，列表是 `operations` 的职责；为了标注弃用而把帮助改成操作清单，改的是另一件事。
7. **改 `operations` 的输出格式（加一列或加记号）**：否决。它是制表符分隔、给脚本读的，稳定性一列已经写着 `Deprecated`；加列会破坏按列取值的脚本。规范这次把这一列就是弃用的标注写明。
8. **命令行的提示写到 stdout**：否决。stdout 只承载命令输出，脚本把它接进管道或交给 JSON 解析；提示是给人看的诊断，属于 stderr。
9. **提示写成一行 JSON（与失败的那一行同形）**：否决。它不是失败，没有错误码；把它写成 `{"code":…}` 会让按「stderr 有一行 JSON 就是失败」处理的脚本误判。一句本地化的话，与日志一样是给人看的。
10. **提示只在成功时写，失败时不写（让 stderr 仍然只有一行）**：否决。提示每次执行写一次才可预期；stderr 本来就同时承载日志，「整个 stderr 是一行 JSON」从来不成立，取最后一行的脚本不受影响。规范写明提示在失败的那一行之前。
11. **用法错误（退出码 64）也写提示**：否决。载荷或选项不合法时没有发起调用；这时该看到的是用法错误本身。提示写在调用上下文建好之后，也正好能取到 `--locale`。
12. **提示用日志（`ILogger` 的 Warning）而不是直接写 stderr**：否决。日志的文案是英文、不本地化（代码规范），格式与级别由宿主的日志配置决定，应用把日志级别调高后提示就没了；这是面向人的文案，走消息键与调用方区域。
13. **给 `ICommand` 加弃用的成员，让自定义命令也能标弃用**：不在本 ADR。这次做的是操作的稳定性怎样映射到协议，`ICommand` 不是操作，没有稳定性。
14. **MCP 一并做**（`description` 前加一句、或放进 `_meta`）：不做，这一轮没有选。

## 决策

1. **gRPC**：`ProtoFileBuilder.Build` 写 `rpc` 时，`operation.Descriptor.Contract.Stability == Stability.Deprecated` 的写成

   ```proto
   // orders.archive
   rpc Archive (OrderRequest) returns (OrderReply) {
     option deprecated = true;
   }
   ```

   其余级别照旧以分号结束、不写选项。只改文本：方法照常绑定、照常调用，状态与尾部元数据不变。`Stability.Internal` 的操作照旧不发布。
2. **命令行，调用时**：`invoke`（含简写）调到弃用的操作时，在调用上下文建好之后、进管道之前，往 stderr 写一行 `CommandLineMessages.OperationDeprecated`（`hosting.commandline.operation_deprecated`，参数 `id`），按调用上下文的区域翻译（`--locale`，没有时是默认区域）。
   - 每次调用写一行；stdout 的输出与退出码不变。
   - 调用失败时这一行在失败的那一行 JSON 之前。
   - 用法错误（退出码 64）与未暴露的操作（退出码 3）没有发起调用，不写。
   - MCP 的 stdio 传输（`mcp` 命令）不经 `invoke`，不写。
3. **命令行，列表与帮助**：
   - `operations` 不改：弃用的操作稳定性一列是 `Deprecated`，规范把它写明为列表里的标注。
   - 带 `--help` 的命令行指向一个弃用的操作（`invoke <operation-id>` 或简写，判定与 `invoke` 相同：登记了、暴露给命令行、不是内部的）时，帮助之后空一行，再写同一句提示；按默认区域，与帮助的其余文案一样。其余情况的帮助一字不差。
4. **消息键**：新增 `hosting.commandline.operation_deprecated`，10 个区域文件都有；英文是 `Operation '{id}' is deprecated and will be removed in a future major version.`（RFC-0001：弃用的级别保留至少两个小版本，只在大版本移除）。
5. **规范**：`protocol/grpc.md`「操作映射」与 `protocol/commandline.md`「操作映射」各补一条，写法对齐 `protocol/http.md` 里 ADR-0273 的那一句。不新增向量文件。

## 理由

- 一个来源：弃用只在契约的稳定性上声明一次，这次是让 gRPC 与命令行把它翻译成各自的写法，不新增契约字段。
- gRPC 用标准选项，客户端重新生成后编译器就会提示；命令行没有标准，就在调用的那一刻告诉正在用它的人。
- 两处都只加不改：没有弃用操作的应用，`.proto`、帮助、stdout、stderr 与退出码都与以前逐字节相同。

## 影响

**公开 API（只增）**

- 新增常量 `XiHan.Framework.Hosting.CommandLine.CommandLineMessages.OperationDeprecated`。
- `ProtoFileBuilder`、`CommandLineRunner`、`InvokeCommand` 的签名不变。没有新的配置键与错误码。

**行为变化**（只影响已经声明 `Stability = Stability.Deprecated` 的操作）

- `.proto`：对应的 `rpc` 从 `rpc X (A) returns (B);` 变成带 `option deprecated = true;` 的块。
  - 由它生成的客户端会给对应的方法加弃用标记；把弃用警告当错误的客户端工程会在重新生成后报出来，这正是弃用要传达的。
  - 按行处理 `.proto` 文本（如用正则找以分号结束的 `rpc` 行）的脚本要认带花括号的形式。
- 命令行：调用弃用的操作时 stderr 多一行文字。
  - 取 stdout、看退出码的脚本不受影响。
  - 把整个 stderr 当成一行 JSON 解析的脚本，在调用弃用的操作且失败时会多读到一行；取最后一行即可。stderr 本来就同时承载日志。
  - `<resource> <verb> --help` 指向弃用的操作时，帮助末尾多两行。

**规范**

- `protocol/grpc.md`、`protocol/commandline.md` 各补一条，级别 MINOR。RFC-0011 不用改：稳定性本来就是契约的字段。
- 六个 SDK 是插件一侧，不发布 `.proto` 也不托管命令行，没有要跟的。

**测试**

- `GrpcProtocolTests`：弃用的操作的 `rpc` 带选项、不弃用的照旧以分号结束且全文只有一处 `deprecated`、弃用的方法照常调用成功；没有弃用操作时 `.proto` 里没有选项。夹具新增 `DeprecatedFeature`（`orders.archive`）。
- 生成的 `.proto` 另用 protoc（Grpc.Tools 自带的 libprotoc 35.1）编译核对过：语法合法，描述符里 `Archive` 的 `MethodOptions.deprecated` 为 `true`，其余方法没有选项；再经同一个包里的 `grpc_csharp_plugin` 生成 C# 代码，`Archive` 的服务端基类方法与四个客户端重载都带 `[ObsoleteAttribute]`，其余方法没有。这一步是手工核对，没有进测试（测试项目不引用 protoc）。
- `CommandLineRunnerTests`：调用弃用的操作 stderr 正好一行提示、stdout 与不弃用的操作只差操作 ID、退出码 0、`--locale zh-CN` 时是中文；调用失败时提示在前、失败的 JSON 在后、退出码按 KIND；用法错误不写提示；`operations` 的稳定性一列；`--help` 指向弃用的操作时帮助之后多一句，其余情况的帮助一字不差。夹具 `EchoFeature` 新增 `orders.archive`。

**文档**

- 包 README：`Protocols.Grpc`、`Hosting.CommandLine` 的主要特性各加一条。
- 文档站待改：`protocols/grpc.md` 与 `packages/protocols-grpc.md`（`.proto` 里的弃用选项）、`protocols/command-line.md` 与 `packages/hosting-commandline.md`（stderr 的提示、`--help`、`operations` 的稳定性一列）、`web/operations.md` 的 `Stability` 一行（现在只写了 OpenAPI）、更新日志。

**没有做的**

- MCP 的 tool 没有弃用的表达（备选 14）。
- gRPC 与 HTTP 的运行期都不在响应里带弃用的信号（备选 2）；契约没有移除日期与替代操作的字段。
- gRPC 没有反射服务，也不发布描述符（备选 3）。
- `ICommand` 自己没有弃用的表达（备选 13）。
