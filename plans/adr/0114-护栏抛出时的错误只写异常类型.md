# ADR-0114 护栏抛出时的错误只写异常类型

## 状态

已采纳（`spec/rfcs/0022-ai.md` 随之修订）。修订 ADR-0113「没有改的」一节：护栏抛出时的 `reason` 不再是异常消息。

## 日期

2026-11-04

本 ADR 记录第二十七批回灌（`af-batch-backlog.md`，用户定「也改掉」）的决定。

## 背景

ADR-0111 到 ADR-0113 让知识库存储与模型调用的 `reason` 只写异常类型。护栏抛出时的 `AI_UNEXPECTED_001` 还带着异常消息，`ProblemResponse` 不分错误类型，都会把标量细节写进响应。

护栏可以自写，比如调用内部的审核服务，异常消息可能带它的地址。修前用 `GuardrailErrorTests` 复现：`reason` 是 `Connection refused by moderation.internal:9000.`。

## 决策

1. 护栏抛出时，`AI_UNEXPECTED_001` 的 `reason` 是异常类型的全名。错误码、消息键 `ai.guardrail.failed`、`guardrail` 与 `reason` 两个参数名都不变。
2. 完整异常进日志，类别 `AIChat`：每次一条 Error，带护栏名。
   - 级别比模型调用失败的 Warning 高：模型端点不可达是外部条件，护栏抛出是护栏本身的缺陷，它本该以结果返回失败。
3. 护栏自己返回的失败不变，`reason` 仍是那个错误的文案：这是护栏作者写给调用方的内容，不是异常消息。
4. 取消照常抛出，不记日志。

## 影响

- 变的是 `reason` 的值：从异常消息变成类型全名。排查时看日志。
- 公开 API 不变。框架内置的关键词护栏不抛异常，只有自写护栏才走到这条路径。
