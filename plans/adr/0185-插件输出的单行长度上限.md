# ADR-0185 插件输出的单行长度上限

## 状态

已采纳（`spec/plugin/handshake.md` 修订宿主转发插件输出一条）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-27（`plans/5.0-安全审查.md`），低危。

- `PluginProcess` 用 `StreamReader.ReadLineAsync` 读握手行与之后的 stdout / stderr：读到换行符才返回，一行有多长就缓冲多长。
- 插件不可信。一行不带换行符写上几十 MB，宿主就把它整行装进内存，再原样写进日志；握手失败时，整行还被拼进错误的原因。
- 进程外插件已经隔离在子进程里，宿主的内存不应随插件的输出无界增长。

复现：`PluginOutputLimitTests`。修正前：
- 8 MiB 的一行输出原样记进日志（8388635 个字符）。
- 8 MiB 的握手行要等整行读完才判定。

## 备选

1. **按字节限制管道的读取速度**：否决。问题在单行的长度，不在速度。
2. **超长即终止插件**：否决。超长的日志行多半是插件自己的缺陷，不值得为它把插件停掉；握手行例外，超长就是不合法。
3. **一行最多保留固定的字符数，超出部分读掉丢弃**：采纳。

## 决策

1. 新增内部的 `PluginOutputReader`：按行读，一行最多保留 16384 个字符（`PluginProcess.MaxOutputLineChars`），超出的部分边读边丢弃、不进内存。行尾认 `\n`、`\r\n` 与单独的 `\r`，与 `StreamReader.ReadLine` 一致。
2. 普通输出：超长的行只记前 16384 个字符，另记一条告警（插件 ID 与上限），下一行照常读。
3. 握手行：读到上限即判定为不合法握手（`PLUGINS_VALIDATION_003`，原因只写超过了上限，不带内容），不等行尾。握手行与之后的 stdout 共用同一个读取器，缓冲里读多的部分留给下一行。

## 影响

- 行为：超过 16384 个字符的插件输出行被截断。插件的结构化日志（以 `{` 开头的 JSON 行）超长时截断后解析失败，按普通文本记录。
- 公开 API 不变。
- Wasm 插件的输出写在工作目录的文件里，由 S-19 另行处理。
