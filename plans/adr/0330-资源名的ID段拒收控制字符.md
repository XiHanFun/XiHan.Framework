# ADR-0330 资源名的 ID 段拒收控制字符

## 状态

已采纳（规范 RFC-0008「资源名」的 ID 段一条与状态行、向量 `security/resource-names.json` 与 Go 一致性模块的 `rules.IsResourceName` 已改；内核 `ResourceName`（`Stable`）的 ID 段文法收窄，签名不变；错误码、消息键与配置键不变）。

## 日期

2026-11-27

## 背景

ADR-0321 让资源名的 ID 段拒收孤立的代理项，「影响」里记下同类而没改的一条：ID 段的文法是「不含 `/` 与空白」（.NET 的 `[^/\s]`），空白之外的控制字符都照收，即 U+0000–U+0008、U+000E–U+001F、U+007F–U+0084 与 U+0086–U+009F（U+0009–U+000D 与 U+0085 是空白，已经拒收）。

资源名用于策略判定与审计，原样写进日志、审计记录与 JSON：

- 终端的转义序列（U+001B 起头）与退格（U+0008）能在查看日志时改写或伪造一行；U+0000 在一些存储与工具里截断文本。
- 两个只差在这些看不见的字符上的资源，在日志与审计里看着是同一个名字。

仓库所有者已拍板：ID 段拒收控制字符。

## 备选

1. **ID 段排除控制字符，定义为 U+0000–U+001F 与 U+007F–U+009F**：采纳。
   - 与 `conventions/baggage-keys.md` 里 Baggage 值的「控制字符」同一个定义，也就是 Unicode 的 `Cc` 类：.NET 的 `char.IsControl` 与正则的 `\p{Cc}`、Go 的 `unicode.IsControl` 都正好是这些码位。
   - 失败语义照 ID 段已有的不合法：构造与初始化器抛出 `ArgumentException`，`Parse` 抛出，`TryParse` 为假。
2. **只拒 C0（U+0000–U+001F）与 DEL**：否决。C1（U+0080–U+009F）同样是控制字符，U+009B 在一些终端里就是 CSI；各语言的判定函数都包括它们，只拒一半要另写一份判定。
3. **一并拒格式字符（`Cf`：零宽空格 U+200B、从右到左覆盖 U+202E 等）**：否决。向量里零宽空格是合法的用例；`Cf` 里的软连字符、零宽连接符在正常的文本里有用处；这次的范围是控制字符。
4. **.NET 把 `\p{Cc}` 并进 ID 段与整串的两个正则**：采纳。构造与解析同一条文法；孤立的代理项照旧由 `UnicodeText.HasLoneSurrogate` 另判。
5. **补向量**：采纳。不合法的补 U+0000、U+0001、U+0008（`\b`）、U+001B（带 `[31m` 的转义序列）、U+001F、U+007F、U+0080、U+009F 与 ID 段只有一个 U+0007；合法的补控制字符两侧的 U+007E 与 U+00A1。期望值由 .NET 实现算出（改之前这 9 条不合法的都被接受）。
6. **规范的级别**：MAJOR（`v1.0.0` 之前允许），与 ADR-0321 收窄 ID 段时相同：以前合法的资源名现在不合法。

## 决策

1. **规范**：RFC-0008「资源名」的 `id` 一条加上控制字符（U+0000–U+001F 与 U+007F–U+009F），状态行加一条，对应 ADR 加上本 ADR；向量 `security/resource-names.json` 补上备选 5 的用例并改 `$comment`；Go 一致性模块的 `rules.IsResourceName` 逐个字符判定时加上 `unicode.IsControl`，`conformance/README.md` 的向量说明同步。
2. **.NET**：`ResourceName` 的 ID 段正则改成 `^[^/\s\p{Cc}]+\z`，整串正则的 `id` 组同样，XML 文档同步。

## 理由

- 资源名是给人看、给审计查的标识，进来的那一刻就该拒收看不见、会改写显示的字符，不靠每个写日志的地方各自转义。
- 控制字符的定义仓库里已经有一处（Baggage 的值），沿用它，各语言都有现成的判定函数。

## 影响

- **公开 API**：签名不变；`ResourceName`（`Stable`）的 ID 段文法收窄。
- **对已有部署与代码的行为变化（升级须知）**：ID 段有控制字符的 `ResourceName` 构造与 `with` 抛出 `ArgumentException`，`Parse` 抛出，`TryParse` 为假；以前照收。框架自己不从外部输入拼资源名；应用从外部输入（实体 ID、文件名）拼 ID 段时，先去掉或编码控制字符（例如百分号编码），或先以 `ResourceName.TryParse` 核对。已经写进审计的旧资源名文本不受影响，只是不能再用它们构造或解析出 `ResourceName`，按资源过滤审计（`AuditQuery.Resource`）是文本精确匹配，照常可用。
- **规范**（规范工作区已提交）：RFC-0008「资源名」与状态行，向量 `security/resource-names.json`，Go 一致性模块的 `rules.IsResourceName`；MAJOR（`v1.0.0` 之前允许）。
- **六个 SDK**：SDK 里没有资源名的类型，不用跟（ADR-0321 同）；Go 一致性模块已随规范改好。
- **测试**：`ResourceNameVectorTests` 回放新的向量（改之前 9 条不合法的用例被接受）；新增 ID 段有控制字符的样例直接构造同样被拒、紧挨着的 U+007E 与 U+00A1 照常合法。
- **体积**：两个正则的字符类多一个 `\p{Cc}`，生成的代码几乎不变，计入 ADR-0329 的「体积」。
- **文档**：`Kernel` 的 README 已同步；文档站与更新日志由整合时补。
