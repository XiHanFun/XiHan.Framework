# ADR-0156 缓存键管理的前缀以结果报告

## 状态

已采纳（RFC-0006「键管理」）。

## 日期

2026-11-11

## 背景

API 审查第三节指出，缓存键管理（`ICacheStoreInspector` 与对象层的 `ICacheInspector`）对同一类输入错误有两种处理：

- 每页条数越界不在构造时抛出，由 `ListKeysAsync` 以 `CACHING_VALIDATION_003` 返回。理由是查询常由管理界面的请求绑定而来，越界是调用方可以改正的输入（ADR-0084）。
- 前缀不合法却在 `CacheKeyQuery.Prefix` 的初始化器里抛 `ArgumentException`。同样来自请求的输入，绑定时就抛出，宿主只能当成 500。
- `RemoveByPrefixAsync` 对空前缀或不合法前缀抛 `ArgumentException`，返回裸 `long`，同一个接口里 `ListKeysAsync` 却返回 `Result`。

## 决策

1. **前缀不在构造时抛出**：
   - `CacheKeyQuery.Prefix` 只拒绝 `null`（编程错误）。
   - `CacheKeyQuery.Validate()` 先核对前缀再核对条数，前缀不合法返回新错误码 `CACHING_VALIDATION_004`（`CachingErrors.PrefixInvalid`，消息键 `caching.inspector.prefix_invalid`，参数 `prefix`、`max`）。
2. **按前缀删除以结果报告**：
   - `ICacheStoreInspector.RemoveByPrefixAsync` 与 `ICacheInspector.RemoveByPrefixAsync` 返回 `ValueTask<Result<long>>`。
   - 先经新的 `CacheKeyQuery.ValidateRemovalPrefix(prefix)` 核对，空前缀与不合法前缀返回 `CACHING_VALIDATION_004`，不访问后端。空前缀的消息键是 `caching.inspector.prefix_required`。
   - 基础设施失败仍按缓存存储的约定抛出，与 `ListKeysAsync` 一致。
3. **一致性套件**：
   - 空前缀与不合法前缀删除都返回校验错误，前缀外的条目不受影响。
   - 不合法前缀列键返回校验错误。

不另设「前缀为空」的错误码：空前缀对删除就是不合法的输入，用不同的消息键区分。

## 影响

- 源码迁移：
  - `await inspector.RemoveByPrefixAsync(prefix, ct)` 的返回值改为 `Result<long>`，取数用 `.ValueOrThrow()` 或先判 `IsSuccess`。
  - 捕获 `ArgumentException` 的调用方改为读错误码。
  - 构造 `CacheKeyQuery` 时不再因前缀不合法而抛出。
- 实现键管理的 Provider：
  - 在 `RemoveByPrefixAsync` 开头调 `CacheKeyQuery.ValidateRemovalPrefix`，并改返回类型。
  - `ListKeysAsync` 已调用的 `Validate()` 自动包含前缀核对。
- 新错误码与两个消息键已登记，十个语言文件同步。
- 两个接口都是 `Preview`；GA 前修改，不需要登记豁免（ADR-0131）。
