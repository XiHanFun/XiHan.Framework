# ADR-0180 OIDC 缺省校验受众

## 状态

已采纳（RFC-0008「认证」OpenID Connect 第 5 条修订）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-05（`plans/5.0-安全审查.md`），中危。

- `OpenIdConnectAuthenticationHandler` 的校验参数是 `ValidateAudience = Audience is not null`：没配受众就不校验。
- 多个应用共用一个身份提供方时（Entra、Google、Auth0，或同一个 Keycloak realm 下的多个客户端），发给别的应用的 ID 令牌或访问令牌也由同一签发者签名。第三方应用拿到受害者的令牌后重放给 XiHan 的 API，会被接受，等于完全冒充受害者；该身份提供方的任何账号也都算「已认证」。
- JWT Provider 用的是应用自己的对称密钥，只有持密钥的一方能签发，受众不强制的风险低得多，不在本条范围。
- 不设算法白名单只是加固建议：Microsoft.IdentityModel 不会把 RSA 公钥当成 HMAC 密钥用。

复现：`Audience_IsRequired_UnlessValidationIsExplicitlyTurnedOff`。修正前，没有 `Audience` 的配置照常启动、不校验受众。

## 备选

1. **只在文档里提醒配置 `Audience`**：否决。安全相关的缺省值应该是安全的那一边。
2. **受众一律必填，不提供关闭的办法**：否决。签发者只为本 API 签发令牌的部署（专用的内部签发者），没有可填的受众或不需要受众；它们应该能显式说明这一点。
3. **缺省校验、`Audience` 必填，显式开关关闭**：采纳。

## 决策

1. **`OpenIdConnectOptions` 新增 `ValidateAudience`**（配置键 `XiHan:Security:OpenIdConnect:ValidateAudience`），缺省 `true`，不是布尔值时启动失败。
2. **`ValidateAudience` 为真时 `Audience` 必填**：
   - `FromConfiguration` 读完配置即核对，缺了抛 `ArgumentException`，启动失败。
   - 处理器构造时再核对一次（`EnsureAudience`），代码里构造的选项也绕不过去。
3. **处理器按 `ValidateAudience` 校验**：关掉时不校验受众，`Audience` 被忽略。

## 影响

- 行为：没配 `Audience` 的 OpenID Connect 部署启动失败。升级时填上本 API 的受众；确实不需要的，显式设 `ValidateAudience: false`。
- 公开 API 只有新增：`OpenIdConnectOptions.ValidateAudience` 与 `EnsureAudience()`。`Security.OpenIdConnect` 是 `Preview`，GA 前修改。
