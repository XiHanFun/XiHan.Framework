# ADR-0133 活动上下文交出实例的只读视图

## 状态

已采纳（规范 `rfcs/0021-workflow.md` 活动一条补充）。

## 日期

2026-11-11

## 背景

P5-05 的 API 审查发现：`ActivityContext.Instance` 的注释写着「只读视图；状态变更只经引擎」，实际交出的却是引擎正在修改、活动返回后会写回存储的 `WorkflowInstance`，它带 22 个公开 setter。`ActivityContext.NodeInstance` 同理，交出的是带 13 个 setter 的 `WorkflowNodeInstance`。`WorkflowOutcomeContext.Instance` 与 `AssigneeResolution.Instance` 转交的是同一个对象。

所以活动、结果处理器或指派规则只要改了 `Status`、`TenantId`、`ParentInstanceId`、节点实例的 `Attempt` 等字段，都会随引擎的这次写入一起持久化：

- 状态机被绕开。
- 实例被挪到别的分区。
- 子流程的回调去往别处。

恢复上下文里的 `WorkflowBookmark` 是已经消费（删除）的书签，改了不会写回，不在本次范围内。

## 备选

1. **交出深拷贝的快照**：类型不变，但每次执行活动都要拷贝整个实例，包括变量与汇合记录；活动做的修改被静默丢弃，比编不过更难发现。否决。
2. **交出只读接口，由 `WorkflowInstance` 实现**：可以强转回可写对象；接口以后加成员对实现者是破坏。否决。
3. **交出密封的只读视图类**：采纳。

## 决策

- 新增 `WorkflowInstanceView` 与 `WorkflowNodeInstanceView`（`Workflow.Abstractions.Instances`，`Preview`）：
  - 密封，构造函数为 `internal`，属性只读，委托给引擎正在修改的对象。视图跟随引擎的修改，不是快照。
  - 实例视图不含 `Variables` 与 `JoinStates`：变量经上下文的 `Variables` 读取，汇合记录是引擎的内部状态。
  - 节点实例视图不含 `Inputs`、`Outputs`、`State`：私有状态经上下文的 `State` 读写，输入与输出由引擎记录。
- 视图改动的位置：
  - `ActivityContext.Instance` / `NodeInstance` 改为视图类型。
  - `WorkflowOutcomeContext.Instance` 与 `AssigneeResolution.Instance` 随之改为 `WorkflowInstanceView`。
  - 引擎派生恢复上下文、暴露 `State` 时用新增的 `internal` 成员 `InstanceRecord` / `NodeInstanceRecord`。
- 测试 `ActivityContextTests` 核对上述四个上下文的 `Instance` / `NodeInstance` 类型都没有公开的 setter。

## 影响

- 只读取这些属性的扩展代码源码兼容（属性名与类型不变，`Title`、`IsFinal` 也在视图上）。以下几类写法编不过，需要改：
  - 写这些属性的代码。改用活动的输出与结果，或者引擎的公开操作。
  - 把它们当作 `WorkflowInstance` / `WorkflowNodeInstance` 传给别的方法的代码。改为传需要的字段。
  - 读实例 `Variables` 的代码。改用上下文的 `Variables`。
  - 读节点实例 `State` 的代码。改用上下文的 `State`。
- 框架与 BasicApp 的扩展代码只读取 `Id`、`DefinitionName`、`CorrelationId`、`StarterId`、`ParentInstanceId`、`TenantId`、`Attempt`，不受影响。
- `Workflow.Abstractions` 是 `Preview`，GA 前修改，不需要登记豁免（ADR-0131）。
- `ActivityContext.Variables` 仍是可写的 `WorkflowVariables`。它的注释写的是「写经输出合并」，直接写入也会进实例变量，但不跨越分区或状态机，列为 5.x 的 `Preview` 改形，不在本次范围。
