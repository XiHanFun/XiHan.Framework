# ADR-0217 没有授权能力时，带要求的契约与端点让启动失败

## 状态

已采纳（RFC-0008「授权」一条修订，`conventions/error-codes.md` 登记 `KERNEL_VALIDATION_006`）。

## 日期

2026-11-13

## 背景

5.0 安全审查 S-44（`plans/5.0-安全审查.md`），低危，加固。

- 授权要求有两个来源：操作契约的 `Permission` / `Policy`，端点上的 `RequireXiHanPermission` / `RequireXiHanPolicy` / `RequireXiHanAuthentication`。两者都由 Authorize 阶段的 `AuthorizationMiddleware` 判定，这个中间件由授权能力（`security.authorization@1`）的 Provider 挂上。
- 没有装配授权能力时，管道的 Authorize 阶段是空的。要求照样登记、照样写进上下文，却没有谁判定，操作与端点等于敞开。
- ADR-0121 已经写明这一点。应用忘了装配、或换 Profile 时丢了授权，表面上一切正常，直到有人发现权限从未生效。

复现：
- `OperationTests.OperationsRequiringAuthorization_FailTheBuild_WhenNothingRunsInTheAuthorizeStage`：修正前装配成功。
- `EndpointRequirementTests.EndpointRequirements_WithoutAnAuthorizationProvider_FailTheHostStart`：修正前宿主正常启动，匿名请求 200。

## 备选

1. **保持现状，只在文档里提醒**：否决。要求静默失效是最坏的失败方式，提醒挡不住遗漏。
2. **没有授权能力时一律拒绝要求授权的调用**：否决。错误要等到调用时才暴露，而装配时就已经能看出来。
3. **内核在 Authorize 阶段内置一个拒绝一切的中间件**：否决。内核不该知道授权的语义；授权 Provider 与它的排序也会因此变复杂。
4. **装配时核对，启动失败**：采纳。与权限码未登记（`KERNEL_VALIDATION_005`）、策略不存在（`SECURITY_VALIDATION_004`）同一个思路：配置错误在启动时一次列出。

## 决策

1. **操作契约**：内核在装配完成时核对。有操作的契约声明了权限码或策略，而 Authorize 阶段没有任何中间件，即抛出 `KERNEL_VALIDATION_006`（一次列出全部）。
   - 只看阶段里有没有登记中间件，不排序管道：顺序约束的错误仍在构建或打印管道时报告。
   - 判定者不限于框架的 `AuthorizationMiddleware`：应用或别的 Provider 在 Authorize 阶段放了自己的中间件，就由它负责。
   - 此后登记的操作（插件握手之后）经同一核对，声明了权限码或策略即登记失败（同码的校验错误，参数 `id`、`owner`），插件整体被拒。
2. **端点**：`UseXiHan()` 在宿主建请求管道时核对。容器里没有 `PolicyCatalog`（没有装配授权能力），而有端点挂了 `AuthorizationRequirement`，即抛出 `KERNEL_VALIDATION_006`，宿主启动失败。
   - 端点上的要求是 `AuthorizationRequirement`，只有授权能力的 `PolicyCatalog` 判定得了，所以这里看 `PolicyCatalog`，不看阶段。
3. **运行期写入的要求**：`RequireAuthorization` 在没有装配授权能力时抛出 `InvalidOperationException`，宁可失败不可放行。

## 影响

- 破坏性变更：
  - 声明了权限或策略、却没有装配授权能力的应用，从「正常启动、要求不生效」变为启动失败。迁移：装配 `Security.InMemory` 或 `Security.Database`；确实不需要授权的，去掉这些要求。
  - 测试里只要契约上的权限、不验授权的，在 Authorize 阶段挂一个放行的测试替身。框架自己的审计、Wasm 插件与内存安全的测试就是这样做的。
- ADR-0121 决策 6 里「没有装配授权能力时，要求只进入上下文、不被判定」不再成立：CloudEvents 入站端点挂了要求而没有授权能力时，宿主启动失败。
- 公开 API：`KernelErrors.AuthorizationMissing`、`KernelMessages.OperationAuthorizationMissing`（消息键 `kernel.operation.authorization_missing`，10 种区域）。
