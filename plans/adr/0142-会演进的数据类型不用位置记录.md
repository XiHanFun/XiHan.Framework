# ADR-0142 会演进的数据类型不用位置记录

## 状态

已采纳（规范 `rfcs/0001-primitives.md`「稳定性级别」修订）。

## 日期

2026-11-11

## 背景

API 审查的 R3 指出，公开位置记录约有 112 个，其中很多是会演进的请求、响应、状态与事件类型。位置记录有三个问题：

1. **加字段就破坏**：每加一个位置参数，构造与 `Deconstruct` 的签名都变，GA 之后就是二进制破坏。`FeatureHealth`、`UnitOfWorkOptions` 都已经在位置参数之外再追加了 `init` 属性。
2. **`with` 行为不一致**：位置参数在类型体里被重新声明成只读属性（为了校验），这个成员就不能 `with`，同一类型的其他成员却可以。`AuthorizationRequest` 的 `Security`、`Action` 只读，`Resource` 可以 `init`。
3. **必需成员多时读不清**：`ProblemResponse` 有 9 个位置参数，`HealthSnapshot` 有 3 个相邻的 `bool`，调用点看不出哪个值是哪个字段。

清单记录在 ADR-0137 已经改成「构造只收必需字段，可选字段走初始化器」，这次把同一规则推到内核、消息与宿主的 `Stable` 数据类型。

## 决策

- **规则写进 RFC-0001**：
  - 会演进或跨 Provider 边界的数据类型不用位置记录。
  - 构成身份的一两个必需成员经构造给出，其余成员一律走初始化器，必需的标 `required`；以后加字段只加可选的初始化字段。
  - 初始化器在设值时校验，`with` 也走这道校验。
  - 位置记录只留给封闭的小值，如 `TypedId`、`ResourceName`、`(Key, Outcome)` 形的逐项结果。
- **只留构造、其余走初始化器**：
  - `AuthorizationRequest(security, action)`，`Resource` 走初始化器。
  - `ContributorStatus(name, state)`，`Error` 走初始化器；`State` 可以 `with`，原有的 `with { State = … }` 用法保留。
  - `MessageSubscription(topic, mode)`。
  - `PluginSource(directory, permissions)`。
- **全部走 `required` 初始化器**：
  - `AuditEvent`：`Action` 不得为空白，`TraceId` 不得为 `null`。
  - `HealthSnapshot`。
  - `OperationResponse`：`Payload` 缺省为空。
  - `FeatureStatus`：`Error` 可省略。
  - `MessageDelivery`：四个成员的校验移到初始化器里。
  - `HealthResponse`、`FeatureHealth`：`Error` 可省略。
  - `ProblemResponse`：`Errors`、`Details` 可省略。
- **`IdempotencyRecord` 改为 internal**：它是幂等中间件自己的存储格式，只在本包里用，不应作为 `Stable` 公开。
- **框架内的构造机械改写**：
  - 共约 110 处。
  - 原来紧跟的初始化器一并并入。
  - 值为缺省的可选实参（`null`、空载荷）直接省掉。

## 影响

- 源码迁移：
  - `new AuditEvent(now, action, outcome, traceId) { … }` → `new AuditEvent { Timestamp = now, Action = action, Outcome = outcome, TraceId = traceId, … }`。
  - `new AuthorizationRequest(security, action, resource)` → `new AuthorizationRequest(security, action) { Resource = resource }`。
  - `new ContributorStatus(name, state, error)` → `new ContributorStatus(name, state) { Error = error }`。
  - `new MessageDelivery(topic, envelope, attempt, mode)` → `new MessageDelivery { Topic = topic, Envelope = envelope, Attempt = attempt, Mode = mode }`。
  - `new OperationResponse(outcome, payload)` → `new OperationResponse { Outcome = outcome, Payload = payload }`；失败响应照旧用 `OperationResponse.Failure(error)`。
  - `HealthSnapshot`、`FeatureStatus`、`HealthResponse`、`FeatureHealth`、`ProblemResponse` 同理，按属性名写初始化器。
  - 只用两参构造的 `MessageSubscription`、`PluginSource`，以及只用前两个实参的 `AuthorizationRequest`、`ContributorStatus`，调用点不用改；按大写参数名传参的（`Topic: …`）改成小写。
- 这些类型都不再有 `Deconstruct`，解构的写法改为读属性。
- JSON 形状不变：`HealthResponse` / `FeatureHealth` 的序列化按属性名，`ProblemResponse` 由 `WriteTo` 手写。
- 引用 `IdempotencyRecord` 的代码删掉即可，记录格式与回放行为不变。
- 这些类型都是 `Stable`（`PluginSource` 与 `ContributorStatus` 是 `Preview`），GA 前修改，不需要登记豁免（ADR-0131）。
