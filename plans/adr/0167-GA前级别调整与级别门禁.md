# ADR-0167 GA 前的级别调整与级别门禁

## 状态

已采纳（RFC-0001「稳定性级别」修订「`Stable` 不依赖不稳定的类型」与「可选参数」两条）。

## 日期

2026-11-11

## 背景

API 审查第 7 批「级别调整与冻结」：5.0.0 发版后 `Stable` 在整个 5.x 不能破坏，发版前要把级别定准，并让规则由编译器守住。审查第五节列出了要升 `Stable`、保持 `Preview`、降级与删除的对象；ADR-0131 定了两条规则，到这一批还没有工具检查：

- `Stable` 的签名不得引用 `Preview` / `Experimental` 类型，成员单独标注的级别不得高于所在类型。
- 公开方法不用可选参数（ADR-0157 写进 RFC-0001）。第 6 批只改了审查点名的几处，全仓库还有约 140 个公开签名带默认值，其中约 55 个在 `Stable` 类型上，包括 `Error` 的全部工厂、`PipelineBuilder`、`FeatureContext.AddMiddleware`、`ProblemResponse.FromError`。

先加诊断再调级别，一次构建就列出违例：调整前，审查点名的违例之外，还暴露出 `ProblemResponse` 引用 `SchemaViolation`（`Preview`）、`Persistence.Conformance` 的夹具实现 `Preview` 接口。

## 决策

1. **分析器新增三条诊断**（`Kernel.Analyzers`，错误级，只对框架包生效）：
   - XH0006：生效级别为 `Stable` 的公开类型与成员，签名不得引用 `Preview` / `Experimental` 类型。
     - 检查范围：基类、实现的接口、泛型约束、参数、返回值，以及属性、字段与事件的类型；泛型实参一并展开。
     - 引用其他程序集的类型时，级别读元数据上的标注。
   - XH0007：成员或嵌套类型单独标注的级别不得高于所在类型的生效级别。
   - XH0008：生效级别为 `Stable` 的公开方法、构造与索引器不得声明可选参数。
     - 不报：重写与接口实现照原声明；调用方信息参数（`CallerArgumentExpression` 等）由编译器填写。
     - 程序集名以 `.Testing`、`.Conformance` 结尾的工具链包例外。
     - `Preview` 升 `Stable` 时这条规则随之生效。
   - 生效级别取符号自身的标注，没有时逐层取包含类型的标注；没有任何标注的类型（BCL、第三方）不参与判定。
2. **级别按第五节调整**：161 个类型升 `Stable`，24 个降 `Preview`，4 个降 `Experimental`，21 个成员单独标注较低级别。
   - 升 `Stable` 的包与类型：
     - `Configuration.Abstractions`、`ObjectStorage.Abstractions` / `FileSystem` / `S3`、`Auditing.Abstractions`。
     - 七个默认实现与 `Caching.Redis`、`Messaging.RabbitMQ`、`Persistence.SqlSugar` 主体、`Observability.OpenTelemetry`。
     - 调度的应用面：`IJob`、`IJobScheduler` 及其扩展、作业定义、计划与日历、状态与运行视图、查询、`AddJob` / `AddJobType` / `AddJobCalendar`、错误码、消息键与能力 ID。
     - 工作流的定义模型、`WorkflowName`、`ActivityType`、状态枚举与 `WorkflowJson` 的定义部分。
     - 内核的健康贡献者三件、`IShadowAwareFeature`、`SchemaViolation`；`Redaction`；`TimeRange`、`DomainEventTracker`、`RegisteredEntity`。
     - `WebApplicationBuilder.AddXiHan`（`WebApplicationBuilderExtensions`）：签名只用 `Stable` 类型，挂载配置目录的语义已定（ADR-0075），与 `UseXiHan` 同为 `Stable`。
   - 降 `Preview`：三个 Profile（级别不高于组装的组件）、发件箱五个类型、全部一致性套件（套件随子系统演进加用例与夹具成员）。
   - 降 `Experimental`：`HttpActivity`、`WorkflowHttpClient`、`SqlSugarDiffLogData`、`SqlSugarReplicaOptions`。
   - 实现了 `Preview` 接口的实现类型随接口保持 `Preview`，所在包的特性与选项照样升 `Stable`。例如 `InMemoryCacheStore` / `RedisCacheStore` 实现键管理与检视，`InMemoryJobStore` 实现 `IJobStore`，`InMemoryPermissionGrantStore` 实现授予管理，`SqlSugarDataSource` 实现 `IDataSource`。
   - `Stable` 类型里个别成员引用不稳定类型的，成员单独标注较低级别：
     - `WorkflowJson` 的实例、书签、事件与故障方法为 `Preview`。
     - `SqlSugarPersistenceOptions.Replicas` / `DiffLog` 与 `SqlSugarPersistenceFeature.DiffLog` 为 `Experimental`。
     - `JobRunQuery.Matches(JobRunRecord)` 与调度的 `GetJobRegistry` 等四个登记表、引擎方法为 `Preview`。
3. **`SchemaViolation` 升级前改形**：路径与原因经构造给出，消息键与参数改为初始化器（R3），去掉两个可选构造参数。
4. **可选参数规则细化**：
   - 一两个可选值用重载补齐：至少有不带它们的短重载与参数齐全的长重载，中间一级按需要提供，短重载转调长重载。
   - 更多的可选值，或以后还会增加的，仍收进选项记录。
   - `CancellationToken` 不设默认值。
   - `Stable` 上的全部违例照此改成重载：`Error` 构造与七个工厂、`FrameworkException`、`MessageScope.Resolve`、`MessageTemplate.Describe` / `Format`、管道与特性上下文的登记方法、内核的登记表构造、`ProblemResponse.FromError`、端点约定、对象存储与调度的值类型和工厂、仓储登记、消息处理器登记、授权要求与授予、`PermissionChecker`。
   - 三个位置记录（`Ordering<T>`、`AuthorizationRequirement`、`PermissionGrant`）与 `DirectPublisher` 的主构造去掉默认值，另加短构造。
   - `OperationId.Validate`、`MessageTemplate.ValidateKey` 的参数名改为 `CallerArgumentExpression`，与另外三个 `Validate` 一致。
5. **发版工具**：
   - 新增 `framework/scripts/Ship-PublicApi.ps1`，在 5.0.0 的版本提交里执行，把各包未发布的符号移进 `PublicAPI.Shipped.txt`。
     - `*REMOVED*` 行从已发布文件删去对应符号。
     - 先核对全部包再写文件，任何一包不一致就一个文件都不改。
     - `-Check` 只报告不写。
   - ADR-0131 的另外三项改为在 5.0.0 发布之后落地：在此之前还没有可比较的已发布包，它们无从生效。
     - 基线版本：等 5.0.0 推到 NuGet 后设。
     - `Sync-PublicApi.ps1` 对非 `Stable` 符号写 `*REMOVED*`：判定已撤下符号的级别，要读基线程序集上的标注。
     - 豁免门禁：同样要读基线程序集上的标注。
     - 后两项与第一次破坏 `Preview` 的提交一起实现。
     - `Cli` 是 dotnet tool，设基线时不纳入。

## 影响

- 源码迁移：
  - 多数调用不用改：按位置传参的调用照常编译，只传必需参数的调用绑定到短重载。
  - 用命名实参跳过前面可选参数的调用要补上被跳过的参数，例如：
    - `Error.Unexpected(code, key, inner: e)` → `Error.Unexpected(code, key, null, e)`
    - `pipeline.UseAt<T>(stage, owner: id)` → `UseAt<T>(stage, Placement.End, id)`
    - `BlobUrlRequest.ForDownload(downloadFileName: name)` → `ForDownload(null, name)`
  - `new SchemaViolation(path, reason, key, args)` → `new SchemaViolation(path, reason) { MessageKey = key, Arguments = args }`。
- 二进制上这些都是破坏，GA 前修改，不需要登记豁免（ADR-0131）。
- 级别：
  - 降级发生在 GA 前，不违反「只升不降」。
  - 从 Profile、发件箱与一致性套件引用的应用，在 5.x 小版本可能需要按更新日志改代码。
- 以后新增的 `Stable` API 由 XH0006～XH0008 在编译期守住；`Preview` 类型升 `Stable` 前要先满足这三条。
