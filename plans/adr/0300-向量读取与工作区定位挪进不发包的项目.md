# ADR-0300 向量读取与工作区定位挪进不发包的项目

## 状态

已采纳（`Testing` 删除 `SpecVectors` 与 `FrameworkWorkspace`，两者挪进 `framework/test` 下不打包的类库 `XiHan.Framework.Testing.Workspace`，测试项目改引用它；规范不变）。

## 日期

2026-11-25

## 背景

### 两个只在框架仓库里有用的类型留在发布的包里

ADR-0289 把向量的定位与读取收成 `SpecVectors` 与 `FrameworkWorkspace`，放进了 `XiHan.Framework.Testing`（`Preview` 的公开类型），理由是「提供程序与 SDK 的仓库带着规范子模块时也能用」。仓库所有者已拍板：这两个类型挪出发布的包。

- `FrameworkWorkspace.Root` 从测试的输出目录向上找 `XiHan.Framework.slnx`，`SpecVectors` 在它下面读 `spec/conformance/vectors`。只有框架仓库有这个解决方案文件：别的仓库即使带着规范子模块，也没有 `XiHan.Framework.slnx`，`Root` 照样抛出。ADR-0289 说的那种用法实际上用不了。
- 应用的测试引用 `Testing` 是为了 `TestHost`、`LogCapture`、`SpanCapture` 这些；这两个类型在它们那里一调用就抛，却出现在包的公开面、README 与文档站上。
- 用到它们的是框架自己的 29 个测试项目，其中 8 个（`Configuration.Abstractions`、`Kernel.Analyzers`、`ObjectStorage.Abstractions`、`Plugins.InProcess`、`Primitives`、`Samples`、`Scheduling.Abstractions`、`Workflow.Abstractions` 的 `.Tests`）是 ADR-0289 为了它们才加上的 `Testing` 引用，别的类型一个也没用。

## 备选

1. **留在 `Testing`，标 `Internal` 或 `EditorBrowsable(Never)`**：否决。标记不改变包的内容，应用照样装上两个用不了的类型；`Internal` 的语义是「只供声明它的包自己使用」（ADR-0131），这里的使用者是别的项目。
2. **放进各测试项目的共享源文件**（`<Compile Include="../Shared/…" />` 链接进每个项目）：否决。同一份代码编进 30 个程序集，`internal` 的入口各有一份，`Lazy` 缓存也各算各的；ADR-0289 收拢副本要去掉的正是这种形状。
3. **在 `framework/test` 下新建一个不打包的类库**：采纳。
4. **新项目名**：
   - `XiHan.Framework.Testing.Workspace`：采纳。它不是包，包 ID 文法（`conventions/package-ids.md`，`Testing` 是没有角色段的结构词）与 `PackageIds_FollowGrammar` 都不管它；前缀用术语表的领域词 `Testing`（测试基座）表明它是测试工具，后段 `Workspace` 说它依赖什么：框架仓库的工作区，与 `FrameworkWorkspace`、架构测试的 `Workspace` 同一个词。命名空间等于项目名，测试项目照例是 `XiHan.Framework.Testing.Workspace.Tests`。
   - `XiHan.Framework.Testing.Spec` / `XiHan.Framework.Conformance.Vectors`：否决。它不只读规范，示例、构建产物与 `src/` 也由 `FrameworkWorkspace` 定位；`Conformance` 在文法里是 `<领域>.Conformance` 的角色段，指发布给 Provider 跑的套件。
   - 带 `Shared`、`Common`、`Helper` 的名字：文法的角色段禁用词，否决。
5. **新项目引用原语层以保留 `[ApiLevel]`**：否决。稳定性级别是包的公开面承诺，不发包的项目没有公开面要承诺；去掉之后它不引用任何项目，引用它的测试项目不因此多出依赖。

## 决策

### 不发包的测试类库

1. 新增 `framework/test/XiHan.Framework.Testing.Workspace`（命名空间同名），加进 `XiHan.Framework.slnx` 的测试分组：
   - 类库，`IsPackable` 为假（仓库根的缺省），不在 `src/` 下，因此没有包验证、PublicAPI 文件与框架包分析器；不引用任何项目。
   - `IsAotCompatible` 照旧打开：按反射读取的重载标了 `RequiresUnreferencedCode` / `RequiresDynamicCode`，分析器仍核对这些标注。
   - 对自己的测试项目开放内部成员（`InternalsVisibleTo`）。
2. `SpecVectors` 与 `FrameworkWorkspace` 原样挪过去：成员、读法、报错与消息都不变，只去掉 `[ApiLevel]`；`FrameworkWorkspace` 的解决方案文件名由私有常量改成内部常量 `SolutionFile`，测试用它而不再另写一遍文件名。
3. `test/Directory.Build.props` 只对名字以 `.Tests` 结尾的项目设测试项目的属性、包引用（`xunit.v3`、`Microsoft.NET.Test.Sdk` 等）与 `using Xunit`；别的项目（现在只有这一个）是普通类库，不当测试运行。
4. `Testing.Tests` 里两个类型的测试（`SpecVectorsTests`、`FrameworkWorkspaceTests` 与 5 个夹具）挪进新增的 `XiHan.Framework.Testing.Workspace.Tests`；原先借用 `LogCaptureEntry` 作「源生成上下文不认得的类型」的用例，改用新夹具 `UnlistedVector`。
5. `XiHan.Framework.Testing` 删除这两个类型：`PublicAPI.Unshipped.txt` 删 7 行，README 删去相应的特性、示例与类型条目。包的依赖不变。
6. 用到它们的 29 个测试项目加上对新项目的引用、`using XiHan.Framework.Testing.Workspace;`；只为它们才引用 `Testing` 的 8 个项目（见背景）去掉 `Testing` 的引用，其余 21 个仍用 `Testing` 的别的类型，保留。
7. CLI 的 `Knowledge/catalog.json` 只收录包、包的引用与依赖，`Testing` 的这些都没变，不用重新生成。

## 影响

- **升级须知**（`Testing` 的 `Preview` 类型移除）：`XiHan.Framework.Testing.SpecVectors` 与 `FrameworkWorkspace` 不再随包发布。在框架仓库里的测试改引用 `framework/test/XiHan.Framework.Testing.Workspace` 并改 `using`；仓库之外本来用不了它们（见背景），没有迁移对象。5.0.0 还没有发布基线，不需要登记豁免（ADR-0131）。
- 8 个测试项目的构建闭包少了 `Testing` 带进的内核、缓存与持久化的抽象、`Security.WebAuthn`：`Primitives.Tests` 回到只引用原语层（ADR-0289 记过它因此间接引用内核）。
- `framework/scripts/New-TestShard.ps1` 与架构测试把 `test` 下有同名项目文件的目录都算作测试项目，新类库因此在 `core` 分片的筛选器里、在架构测试的命名空间门禁里；它不是测试项目，`dotnet test` 跳过它（与 `src` 下的包一样），命名空间等于项目名，两处都不用改。
- 用例数：`Testing.Tests` 少 28 条（62 → 34），`Testing.Workspace.Tests` 多 28 条，别的测试项目不变。
