# ADR-0215 锁可原子续约，雪花机器位不再释放再获取

## 状态

已采纳（RFC-0006「存储契约」「分布式锁」、RFC-0005「雪花标识」、RFC-0019 与 `provider/caching-distributed.md` 的操作集各一条修订，一致性向量增补 `cache-entries.try-refresh`）。

## 日期

2026-11-13

## 背景

5.0 安全审查 S-42（`plans/5.0-安全审查.md`），低危，可靠性（即审查清单的「锁续约」一项）。

- `IDistributedLock` 不续约。`LeasedWorkerIdSource` 每三分之一存活时间「续约」一次，做法是释放锁再获取同一机器位。
- 释放的那一刻锁条目不在了，正在启动的实例从 0 起逐个抢机器位，可能正好抢到它。本实例要等重新获取失败才发现，在这之前一直用这个机器位生成 ID，两边会在同一毫秒发出相同的雪花 ID。

复现：`LeasedWorkerIdSourceTests.RenewAsync_NeverFreesTheSlot_SoAnotherInstanceCannotTakeItWhileItIsInUse`。修正前，竞争者在锁条目被删的那一刻取得了机器位 0。

## 备选

1. **续约期间停用机器位**（先让 `Current` 无值，再释放再获取）：否决。每个周期都有一段不能生成 ID；新持有者仍可能在同一毫秒拿到机器位，重复的风险只是变小。
2. **两个锁资源交替持有**：否决。新旧版本混跑时旧实例只认原来的锁资源，新实例交替持有的那一刻旧实例能抢到，滚动升级期间反而更危险。
3. **先读令牌、相同再写回**：否决。读与写之间锁到期并被他人取得时，会把别人的锁覆盖成自己的。
4. **存储加原子的比较后重设到期，锁据此续约**：采纳。与已有的比较删对称，各后端都能原子实现（内存实现在锁内，Redis 用 Lua，远程插件在自身的串行化范围内）。

## 决策

1. **存储原语**：`ICacheStore.TryRefreshAsync(key, expectedValue, timeToLive)`。
   - 当前值等于期望值时把到期时刻重设为现在加 `timeToLive`，返回 `true`；不存在、已过期或值不同返回 `false`。
   - 原子，不改值；滑动过期的条目只重设这一次的到期时刻，滑动窗口不变。单键，不提供批量。
2. **锁续约**：`LockHandle.TryExtendAsync(timeToLive)`，派生类实现 `ExtendCoreAsync`。
   - `StoreDistributedLock` 的句柄即 `TryRefreshAsync(lock:<resource>, 令牌, timeToLive)`。
   - 句柄已释放时直接返回 `false`，即使存储里的条目还在（释放失败）也不续回来。
3. **机器位租约**：续约改为 `TryExtendAsync`，锁条目一直在。续约时刻取在请求发出之前，本地到期不晚于存储侧到期。续约返回 `false` 或存储不可达都按丢失处理并重新分配，与原来一致。
4. **远程插件**：操作集新增 `cache-entries.try-refresh`（`key`、`expected`、`ttlMs` → `refreshed`）。
   - cache-go 插件的操作集来自 `framework-sdk-go` 的 `examples/cache`，那边还没有实现。远程适配器的一致性测试暂时以 `SupportsRefresh = false` 跳过新增的两个用例，SDK 发布后升级 `samples/CacheGoPlugin/go.mod` 并去掉覆写。

## 影响

- 破坏性变更（5.0 尚未发布，契约仍在 Unshipped）：
  - 自己实现 `ICacheStore` 的要补上 `TryRefreshAsync`。
  - 派生 `LockHandle` 的要补上 `ExtendCoreAsync`。
  - 远程缓存插件要实现 `cache-entries.try-refresh`。没有实现的插件上，锁续约失败；雪花机器位每个周期都按丢失处理重新分配。
- 滚动升级：新实例原子续约同一个锁资源，旧实例仍按旧方式续约；新旧混跑不比以前更差，旧实例全部升级后风险消除。
- 一致性套件 `CacheStoreConformance` 新增用例 15（比较后重设到期）与 16（锁续约）。
- 公开 API：`ICacheStore.TryRefreshAsync`；`LockHandle.TryExtendAsync`、`ExtendCoreAsync`；`RemoteCacheOperations.TryRefresh`、`TryRefreshRequest`、`RefreshedResponse`；`CacheStoreConformance.SupportsRefresh`。
