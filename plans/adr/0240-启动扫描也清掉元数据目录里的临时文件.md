# ADR-0240 启动扫描也清掉元数据目录里的临时文件

## 状态

已采纳（补全 ADR-0212 的清理范围；RFC-0012「Provider」的条文与公开 API 不变）。

## 日期

2026-11-18

## 背景

- `CommitAsync` 先把元数据写成同目录的临时文件 `<容器>/meta/<键的编码>.json~xihan-tmp-<32 位十六进制>`，再进配额锁换上去（ADR-0239）。进程在写好它之后、换上之前崩溃，这个文件就留在 `meta` 目录里。
- `InitializeAsync` 只遍历 `data` 目录与上传目录，清掉那里的临时文件，从不遍历 `meta` 目录。
- 留在 `meta` 目录里的临时文件不计用量、不被列举，也没有别的路径会删它。每崩溃一次多一个，无界累积。
- ADR-0212 之前的写法 `<键的编码>.json.xihan-tmp-<32 位十六进制>` 同样留着，升级之后也没人清。
- 泄漏从元数据先写临时文件起就有。ADR-0239 让元数据的临时文件等到进锁才换上，它留在盘上的时间比以前长一点，崩溃时碰上的机会也大一点；ADR-0239「影响」把它列为不在范围的限制。

复现：新增用例 `FileSystemTemporaryFileTests.Initialize_CleansCurrentAndLegacyTemporaryMetadataFiles_ButKeepsTheMetadataOfObjects`，在 `meta` 目录里放两种写法的临时文件后重建存储。修之前确定失败，两个文件都还在。

## 备选

1. **元数据的临时文件放到单独的目录**：否决。与 ADR-0212 备选 2 同理，临时文件要与目标同目录，改名才是同一卷上的原子替换。
2. **照内容目录的判定，旧版写法还要看有没有对应的元数据文件**：否决，没有必要。内容目录里键的编码能写成旧版临时文件的样子，所以要看元数据；元数据目录里的文件名不会。
3. **启动扫描也遍历元数据目录，两种临时文件都直接删**：采纳。

## 决策

1. `InitializeAsync` 对每个容器遍历 `meta` 目录（含子目录），删掉文件名含 `~xihan-tmp-` 或以 `.xihan-tmp-` 加 32 位小写十六进制结尾的文件。判定只看文件名，与 ADR-0212 一致。
2. 遍历不取决于 `data` 目录在不在。
3. 其他文件不动，元数据文件照旧不计用量。

## 理由

元数据文件的名字都由本实现起：键的编码只产出小写字母、数字、`._-` 与 `%XX`，后面再加 `.json`。

- 它不含 `~`，新版判定不会误删。
- 它以 `json` 结尾，这几个字母不是十六进制数字，旧版判定也不会误删。键的最后一段恰好是旧版临时文件的样子时，元数据文件名是那段再加 `.json`，照样保留。
- 键的前缀段能写成临时文件的样子，但在 `meta` 目录里那是目录名，判定不看目录。

所以元数据目录不需要内容目录那样的元数据核对，与上传目录一样两种临时文件都直接删。

## 影响

- 升级不需要迁移：以前崩溃留在 `meta` 目录里的两种临时文件，在下次启动时清掉。
- 启动扫描多遍历一个目录，文件数与对象数同一量级。
- 下列限制不在本次范围：
  - 与内容目录、上传目录的清理一样，假定扫描时没有进行中的写入。特性在启动时、Provider 在建出命名实例时、`CreateAsync` 在交出存储之前扫描，都满足这一点。对正在使用的存储再次调用 `InitializeAsync`，可能删掉某个写入方已写好、还没换上的元数据临时文件，那次写入在换上内容之后以 `OBJECTSTORAGE_UNAVAILABLE_001` 失败。
  - 删除时内容已删、元数据还没删就崩溃，留下没有内容文件的元数据文件，启动扫描不清。它读不到（读元数据先看内容文件），同一个键再写入时被替换，个数不超过键的数目，不会无界累积。
- 公开 API 不变。
- 测试：新增用例修之后通过，并核对键恰好是旧版临时文件样子的对象，其内容与元数据文件都保留，内容类型仍是写入时给的。
