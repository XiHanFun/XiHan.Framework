# ADR-0169 审计查询的租户与主体显式过滤

## 状态

已采纳（RFC-0015「查询」修订过滤项一条）。

## 日期

2026-11-11

## 背景

API 审查第 6 批留作后续的一项：`AuditQuery` 的 `PrincipalId` 与 `TenantId` 为 `null` 时表示「不过滤」。

- 事件上 `null` 主体就是匿名调用，`null` 租户就是不属于任何租户的平台级事件（RFC-0001「缺失用 null」）。
- 所以查询分不清「不过滤」与「只要匿名 / 只要全局」，运维要单独看平台级事件或匿名调用时无从表达。
- 授予管理的同一个问题已在 ADR-0158 用显式的 `GrantTenantFilter` 解决。
- 第 7 批把 `Auditing.Abstractions` 升为 `Stable`（ADR-0167），GA 后就不能再改，所以在 GA 前处理。

## 备选

1. **保持现状，在文档里写明查不到全局与匿名**：否决。这是查询语言缺一种表达，不是文档问题。
2. **内核里放一个通用的租户过滤，授予与审计共用**：否决。
   - 内核不承载查询语言。
   - 授予与审计的过滤各属各的子系统契约，形状相同不等于语义必须绑定；主体过滤也只有审计需要。
3. **审计子系统自己的两个显式过滤**：采纳，与 `GrantTenantFilter` 同形。

## 决策

1. **新增两个 `Stable` 的过滤类型**（`Auditing.Abstractions/Trail`）：
   - `AuditTenantFilter`：`Any`（不过滤）、`Global`（只要租户为 `null` 的事件）、`Of(tenantId)`。
   - `AuditPrincipalFilter`：`Any`（不过滤）、`Anonymous`（只要主体为 `null` 的事件）、`Of(principalId)`。
   - `Of` 拒绝空白；`Matches(value)` 给内存实现与 `AuditQuery.Matches` 用。
2. **`AuditQuery` 的 `PrincipalId` / `TenantId` 改为 `Principal` / `Tenant`**：缺省 `Any`，`init` 拒绝 `null`。
   - 其余可空的过滤项（`Action`、`TraceId`、`Resource`、时间、`Succeeded`）为 `null` 时不按它过滤：那些字段上「没有值」不是要单独查的一类事件。
3. **数据库实现**：「只要匿名 / 全局」写成与字面 `null` 的比较，各 Provider 都生成 `IS NULL`；与捕获的 `null` 变量比较时，有的 Provider 会生成 `= NULL`。
   - `(TenantId, Sequence)` 索引同样覆盖 `IS NULL`。
4. **一致性套件**新增一个用例：四个事件覆盖有无租户、有无主体，分别以 `Any`、`Global`、`Of`、`Anonymous` 及其组合查询。

## 影响

- 源码迁移：
  - `new AuditQuery { TenantId = id }` → `new AuditQuery { Tenant = AuditTenantFilter.Of(id) }`
  - `new AuditQuery { PrincipalId = id }` → `new AuditQuery { Principal = AuditPrincipalFilter.Of(id) }`
  - 以前传 `null` 的写法不用改：缺省就是 `Any`。
- 自写的 `IAuditTrail` 实现要按两个过滤的 `IsAny` 与值翻译查询，并过新的一致性用例。
- GA 前修改，不需要登记豁免（ADR-0131）。
