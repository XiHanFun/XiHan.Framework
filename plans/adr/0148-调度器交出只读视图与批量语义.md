# ADR-0148 调度器交出只读视图、状态分页与批量语义

## 状态

已采纳（规范 `rfcs/0013-scheduling.md` 修订；错误码登记进 `conventions/error-codes.md`）。

## 日期

2026-11-11

## 背景

API 审查对 `IJobScheduler`（`Preview`，计划 GA 时升 `Stable`）提了四件事：

1. **应用面拿到存储记录**：
   - `RunsAsync` 返回 `JobRunRecord`，它带 14 个公开 setter。
   - `JobStatus.Job` 是 `JobRecord`，带引擎的簿记字段（进行中的运行 ID、代码指纹）。
   - 应用改了这些对象，看起来像改了调度器的状态。
2. **状态读取没有上限**：`StatusesAsync()` 一次读出全部作业，没有分页，也没有按名批量取。
3. **批量语义没写**：引擎在批量循环中途 `ThrowIfCancellationRequested`，已经生效的项连同结果一起丢掉，违背批量优先第 7 条「不在中途取消而留下半批」。
4. **会演进的位置记录**：`JobTriggerStatus`（7 参）、`JobTriggerRequest`、`JobRun`、`JobOutcome`、`JobStatus`。

## 决策

- **只读视图**：
  - 新增 `JobView` 与 `JobRunView`，都是只读的初始化器记录，数据字段是副本。
  - `JobStatus.Job` 改为 `JobView`。
  - `RunsAsync` 返回 `JobRunView`，失败结果在 `Outcome` 里。
  - `JobRecord`、`JobRunRecord` 只留给 `IJobStore`。
- **状态读取**：
  - `StatusesAsync(names)` 按名批量：与入参等长、同序，未登记的为无值，重复的名字各得一份，空集合不访问存储，存储读不到时整批失败。
  - 单个作业的 `StatusAsync(name)` 改为扩展方法。
  - 原来的 `StatusesAsync()` 改为 `ListStatusesAsync(JobStatusQuery)`，按作业名的序数升序做键集分页：`PageSize` 1～1000、缺省 100，令牌是上一页最后一个作业名，对调用方不透明。
  - 每页条数越界或令牌不合法时返回新错误码 `SCHEDULING_VALIDATION_003`，消息键 `scheduling.status.query_page_invalid` / `query_token_invalid`，10 种区域齐全。
- **批量语义写进接口文档与 RFC**：
  - 逐项结果与入参等长、同序；空集合返回空结果；重复项按顺序施加。
  - 取消在开始前检查，已取消时抛出。
  - 开始之后取消，已开始的项照常给出结果，尚未开始的项以 `KERNEL_CANCELLED_001` 结束，方法不抛出。
  - 引擎实现：
    - 写入类方法逐项传 `CancellationToken.None`，保证一项要么做完要么没开始。
    - `TriggerAsync` 等的是运行本身，令牌照常传进运行。
- **位置记录改初始化器**（ADR-0142）：
  - `JobTriggerStatus`、`JobRun`、`JobOutcome`、`JobStatus` 全部走初始化器。
  - `JobTriggerRequest` 只保留作业名构造，`Data` 走初始化器。
  - `JobTriggerResult(Name, Outcome)` 是 `(Key, Outcome)` 形的逐项结果，保留位置形式。
- **不加 `MaxBatchSize`**：批量优先第 8 条规定抽象不强加批次上限，审查里这条建议不采纳。
- **一致性套件**新增两个用例：
  - 按名批量取状态与分页读完。
  - 开始前已取消时抛出，作业不变。

存储接口 `IJobStore`（`Preview`）的 `ListJobsAsync` 仍一次读全部；调度器先在内存里分页。存储侧分页可以以后加，不影响调度器的公开形状。

## 影响

- 源码迁移：
  - `StatusesAsync(ct)` → `ListStatusesAsync(new JobStatusQuery(), ct)`，逐页读到 `ContinuationToken` 为空。
  - `StatusAsync(name)` 照常可用（扩展方法）。
  - `RunsAsync` 的结果从 `JobRunRecord` 换成 `JobRunView`：`ErrorCode` / `ErrorMessage` → `Outcome?.Error?.Code` / `Message`。
  - `status.Job` 的类型从 `JobRecord` 换成 `JobView`，字段名不变，簿记字段不再可见。
  - `new JobTriggerRequest(name, data)` → `new JobTriggerRequest(name) { Data = data }`。
  - `JobRun`、`JobOutcome`、`JobTriggerStatus`、`JobStatus` 改为按属性名写初始化器，不再能解构。
- 批量中途取消不再抛出，调用方按逐项结果判断哪些项被取消。
- 这些类型都是 `Preview`，GA 前修改，不需要登记豁免（ADR-0131）。
