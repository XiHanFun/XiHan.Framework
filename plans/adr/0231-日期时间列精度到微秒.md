# ADR-0231 日期时间列在各数据库上精度到微秒

## 状态

已采纳（`spec/rfcs/0005-persistence.md` 随之修订）。

## 日期

2026-11-16

## 背景

BasicApp 在 MySQL 上跑集成测试，按时间排序的列表与审计记录顺序不稳定。核对 SqlSugar 的类型映射：

- MySQL：`DateTimeOffset` 与 `DateTime` 都建成 `datetime`，没有小数秒，写进去的时刻截到秒。
- Oracle：两者都建成 `DATE`，同样只到秒。
- SQL Server：`DateTimeOffset` 建成 `datetimeoffset(7)`，列本身够精确；但 `DateTimeOffsetConverter` 的写入参数是 `DbType.DateTime`，SqlClient 把它当 `datetime` 传，写进列之前就只剩 1/300 秒。`DateTime` 列建成 `datetime`，也只到 1/300 秒。
- PostgreSQL 的 `timestamptz` / `timestamp` 到微秒；SQLite 存文本，完整保留。

同一秒内写入的行按时间排序时顺序不确定，时刻比较（租约到期、保留期、按时间分页）也只到秒。框架 CI 在 MySQL 与 Oracle 上只跑库结构读取与字面匹配的一致性用例，没有往返时刻的用例，所以没发现。

## 备选

1. 约定按数据库类型给日期时间列定精度，SQL Server 的写入参数按 `datetime2` 传。
2. 让应用在实体上逐列写 `[SugarColumn(ColumnDataType = "datetime(6)")]`：每个实体、每种数据库都要写，框架自己的记录也要改，且列类型就绑死在一种数据库上。
3. 时间列一律存 UTC ticks 整数（EF Core 在 SQLite 上的做法，ADR-0091）：各库一致，但库里的值人读不懂、数据库的日期函数都用不了，已有的库要整体换算。

## 决策

采用备选 1，`SqlSugarConventions.Apply` 在实体回调里施加：

- MySQL：`DateTimeOffset` 与 `DateTime` 建成 `datetime(6)`。
- Oracle：两者建成 `timestamp(6)`。
- SQL Server：`DateTime` 建成 `datetime2(6)`；`DateTimeOffset` 仍是 `datetimeoffset(7)`。两者的写入参数都按 `DbType.DateTime2` 传：`DateTimeOffset` 列换用 `SqlServerDateTimeOffsetConverter`（`DateTimeOffsetConverter` 的子类，只改参数类型），`DateTime` 列的 `SqlParameterDbType` 设为 `DateTime2`。
- 精度 6 位，与 PostgreSQL 一致；实体自己已给列类型（`ColumnDataType`）的列不改，自己给了参数类型或转换器的列不改。
- 列类型与精度分开给（`DataType = "datetime"`、`Length = 6`），不写成 `"datetime(6)"`：写在一起时 SqlSugar 的 `InitTables` 每次都判为类型不同、重发一次改列。

新增 `TimestampPrecisionTests`：在 SQLite、PostgreSQL、MySQL、SQL Server、Oracle 上按约定建表，写入带微秒的时刻再读回，核对值不变、同一秒里先后写入的两行按时间排序不乱；外部数据库沿用各自的环境变量，没设即跳过。

## 理由

- 精度问题出在框架的约定上，应该由约定解决，使用方不需要知道每种数据库的缺省类型。
- 微秒是五种数据库都能表示的最高公共精度；.NET 的 100 纳秒只有 SQL Server 存得下，统一到微秒，同一个值在哪个库上读回来都一样。
- 备选 3 的代价是库里的数据不可读，为解决精度不值得。

## 影响

- 建表变化：MySQL、Oracle 的日期时间列与 SQL Server 的 `DateTime` 列按上面的类型新建或加列。已经建成 `datetime` / `DATE` 的列不随之改变（实测 MySQL 上 `InitTables` 不把已有的 `datetime` 改成 `datetime(6)`），要精度的库自己改列（`ALTER TABLE … MODIFY … datetime(6)` / `timestamp(6)`）。
- 写入变化：SQL Server 上写入的时刻不再被截到 1/300 秒。
- 公开 API、错误码、消息键、配置键不变。
