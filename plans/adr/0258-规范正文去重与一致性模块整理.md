# ADR-0258 规范正文去重与一致性模块整理

## 状态

已采纳（只动 framework-spec：规范性内容不变，按 RFC-0024 属 PATCH；各实现的可观察行为不变）。

## 日期

2026-11-24

## 背景

对规范仓库做了一轮审计，问题分三类：

- **同一条规则写在几处，已经出现出入**。「薄 RFC + 规范性文本」这一类最重：RFC-0018「设计」§1–§6 与 `plugin/wasm.md` §1–§6 近乎逐字重复，RFC 一侧已经落后（中间件不能改写的 Baggage 键只写了 `xihan.principal`，规范性文本与实现都含 `xihan.tenant`）；RFC-0019 重抄 `provider/README.md` 的规则与操作集表；RFC-0016 重抄应用清单的字段。RFC-0017、RFC-0018 各有一张错误码表，是登记表的不完整副本，而登记表里几个码的「含义」又落后于正文。
- **过时或不准确的段落**：RFC-0010 的格式说明符示例与同一文件后面的规则矛盾；RFC-0015 的正则漏了转义；RFC-0002 有两个「4.」；`caching.distributed@1` 写着「五个操作」而表里是九个；正文里留着里程碑代号与依赖的版本号。
- **一致性模块里手写了几份的表**：向量文件表三份（类型化入口、`vectors` 子命令、非空核对），其中非空核对只覆盖 17 个文件；用例表三份；运行器上报的版本是写死的 `0.1.0`，与标签脱节。CI 里 `conformance/plugin` 一个包占 30 秒，两个各串行跑 14 个用例的测试互不相干却没有并行；只在 Windows 上编译的文件在 CI 里连编译都没有。

审计同时列出了一批**规范性**的问题（没有向量盯住的地方实现已经分歧、Schema 比正文宽、档的划分等）。那些要改变实现的行为，不在本 ADR，另行决定。

## 备选

1. **把 RFC-0018 独有的规则并进 `plugin/wasm.md`**：这次不做。并入是改规范性文本；RFC 概览里保留这些细节，并写明同一条规则两处都有时以 `wasm.md` 为准。
2. **删掉已被取代的导出函数 `rules.HasNoDuplicateMembers`**：否决。Go SDK 的测试还在用，标 `Deprecated`。
3. **speccheck 直接引用一致性模块的档表类型**：否决。`tools/speccheck` 是独立模块，引用会新增依赖方向（ADR-0242 把它单独建模块正是为了不进 SDK 用户的模块图）。

## 决策

1. **确立唯一出处，其余改引用**（只在出处、实现与向量三者一致时动手）：
   - RFC-0018「设计」缩成概览，规则以 `plugin/wasm.md` 为准，节号不变；RFC 独有的理由、参考实现的选项名与默认值留在概览里。
   - RFC-0019 的通用模式与操作集表、RFC-0016 的清单字段，分别以 `provider/README.md`、`provider/caching-distributed.md`、`packaging/app-manifest.md` 为准。
   - RFC-0017、RFC-0018 的错误码表改为引用登记表；登记表补全 `KERNEL_NOTFOUND_001`、`PLUGINS_UNEXPECTED_001`、`PLUGINS_VALIDATION_004`、`PLUGINS_DENIED_002`、`PLUGINS_UNAVAILABLE_001` 的含义，只写正文已有的用法。
   - 25 个空白码位以 RFC-0001「空白字符」为出处，`plugin/handshake.md` 改为引用。
2. **修正过时与不准确的段落**：背景第二条列出的各处，按实现与向量改准；正文不再出现里程碑代号与依赖版本号。
3. **一致性模块**：
   - 向量文件表收成 `typedVectors` 一张，导出 `TypedVector` / `TypedVectors()`；测试要求它覆盖 `Names()` 的全部文件。
   - 运行器的用例收成 `caseTable` 一张，`AllCases` 由它导出；测试要求常量、表与实现一一对上。
   - `plugin.Version` 改为取构建信息里一致性模块的版本，取不到是 `devel`。它由常量变成变量。
   - `rules.HasNoDuplicateMembers` 标 `Deprecated`。
4. **CI**：`conformance/plugin` 两个假插件测试并行；加 `GOOS=windows go vet ./...`；构建运行器之后执行 `xihan-conformance vectors`。

## 影响

- 规范的 `go test -race ./...` 由约 31 秒降到约 17 秒。
- `const x = plugin.Version` 这样的写法编译不过（七个仓库里没有）；握手上报的 `sdk_version` 与 `xihan-conformance version` 的输出由 `0.1.0` 变为模块版本或 `devel`。
- 各实现不用跟着改。SDK 的规范指针在下一次规范打标签时照常升。
