# ADR-0196 租户 ID 只用小写

## 状态

已采纳（RFC-0007「租户 ID」与数据库 Provider 各一条修订，RFC-0008「资源名」一条修订）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-11（`plans/5.0-安全审查.md`），中危；审查时数据库行为未实测，这里按各数据库的缺省排序规则判定。

- RFC-0007 规定租户 ID 区分大小写：`Acme` 与 `acme` 是两个租户。
- 租户 ID 的比较却常常不由框架做：
  - 持久化的租户过滤是 `WHERE TenantId = @tenant`，按数据库的排序规则比较。SQL Server 与 MySQL 的缺省排序规则不区分大小写，`ACME` 的调用能读写 `acme` 的行，按 ID 的更新与删除也会落到 `acme` 的行上。
  - 授予表、租户目录、唯一索引同样按排序规则比较。
  - 文件系统（Windows、macOS 的缺省卷）、主机名（子域名解析租户）不区分大小写，按租户分的目录与按租户分的主机名会撞在一起。
- 关闭存储校验（`ValidateAgainstStore: false`）或租户来自身份提供方的声明时，`ACME` 不必在租户目录里存在，任何人都能拿它去碰 `acme` 的数据。
- 另一个缺陷：文法的正则以 `$` 结尾，.NET 的 `$` 放过结尾的换行，`acme\n` 是合法的租户 ID，资源名却拒绝它，两处文法不一致。

复现：`TenantContractTests`、`TenantResolutionMiddlewareTests`、`SecurityTests`。修正前 `Acme-01`、`ACME`、`acme\n` 都是合法的租户 ID，Tenant 阶段把 `ACME` 当作另一个租户去查存储。

## 备选

1. **保持区分大小写，读回后按序数再筛一遍，文档要求区分大小写的排序规则**：否决。
   - 读回再筛只管读：按 ID 的更新与删除、批量删除、唯一索引都在数据库里比较，筛不到。
   - 每个 Provider、每条查询都要记得筛，漏一处就是跨租户。
   - 排序规则是部署配置，框架核对不了，文件系统与主机名更改不了。
2. **不区分大小写，入口处统一改成小写**：否决。静默改写调用方给的值，两个 ID 合成一个；RFC-0007 规定不改写。
3. **文法只收小写**：采纳。只用小写时，按序数比较与不区分大小写的比较结论相同，排序规则、文件系统与主机名都不再影响租户隔离。

## 决策

1. **文法**：`^[a-z0-9][a-z0-9._-]{0,63}$`，整串匹配。
   - 小写字母或数字开头，之后是小写字母、数字、`.`、`_`、`-`，最长 64 个字符。
   - .NET 实现以 `\z` 结尾，结尾的换行不合文法。
2. **同一文法的三处**：Baggage `xihan.tenant`、资源名的租户段、持久化实体的 `TenantId`。资源名的其余段同样改为 `\z` 整串匹配。
3. **不改写**：含大写的 ID 不合文法。
   - Tenant 阶段解析出来的为 `MULTITENANCY_VALIDATION_001`。
   - `TenantInfo`、`ResourceName` 构造时抛出 `ArgumentException`。
   - 框架不把大写改成小写。
4. **数据库租户目录**：读回的行按序数核对 ID，与请求的 ID 不同即视为不存在。排序规则不区分大小写时，迁移之前留下的大写 ID 不被当作它的小写形式。

## 影响

- 破坏性变更：含大写字母的租户 ID 不再合法。
- 迁移：
  - 升级之前，把租户目录、所有 `TenantId` 列、授予表的租户列与资源名里的大写租户 ID 改成小写。
  - 只有大小写不同的两个租户，在不区分大小写的排序规则下早已共用数据，要先人工拆开，再改名。
  - 身份提供方签发的租户声明、子域名与配置里的租户 ID 一并改成小写。
- 一致性套件 `TenantStoreConformance` 的种子租户 `Dormant` 的 ID 改为 `dormant-01`；「ID 区分大小写」用例改为「大写的 ID 找不到小写的租户」。
- 公开 API 的签名不变，`TenantIdentifier` 与 `ResourceName` 的文法与异常消息变了。
