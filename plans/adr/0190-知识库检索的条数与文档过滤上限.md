# ADR-0190 知识库检索的条数与文档过滤上限

## 状态

已采纳（RFC-0022「知识库」模型一条修订）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-29（`plans/5.0-安全审查.md`），低危，审查时为推断，这里复核确认。

- `KnowledgeQuery.Top`、`KnowledgeSearch` 的条数与 `KnowledgeOptions.Top` 只要求至少 1，没有上限。
  - 应用常把调用方的输入（检索界面上的条数、Agent 工具的参数）原样交给检索器。
  - `VectorDataKnowledgeStore` 带元数据过滤时按 `top * MetadataOverfetch` 向后端取数，条数大到一定程度就溢出成负数。
- `RetrievalFilter.DocumentIds` 没有上限，而且只保存调用方给的列表引用。
  - `VectorDataKnowledgeStore` 把每个文档 ID 逐个左接成一条 `OrElse` 链，有多少个 ID 就有多深。
  - 连接器翻译表达式是递归的：几万个 ID 就是几万层，可能栈溢出，进程直接退出。
- 框架自己没有暴露检索操作，入口在应用手里；但上限属于契约，不该要每个应用自己记得。

复现：`KnowledgeLimitTests`。修正前，条数 1001 与 1001 个文档 ID 都照常构造，构造之后改原来的列表，过滤也跟着变。

## 决策

1. **条数**：`KnowledgeSearch.MaxTop = 1000`。以下三处在 1 到 1000 之外即抛出 `ArgumentOutOfRangeException`，与它们已有的「至少 1」同一种做法：
   - `KnowledgeQuery.Top` 的 `init`。
   - `KnowledgeSearch` 的构造。
   - `KnowledgeOptions.Top` 的 `init`。
2. **文档过滤**：`RetrievalFilter.MaxDocumentIds = 1000`。`DocumentIds` 超过即抛出 `ArgumentOutOfRangeException`，保存的是副本，构造之后改传入的列表不影响过滤，上限也就不能被绕开。
3. **向量存储**：文档过滤拼成平衡的或树，深度是文档数的对数。

## 影响

- 行为：条数超过 1000、过滤超过 1000 个文档的检索在构造时抛出。应用拿调用方的输入构造时先核对，或捕获后返回校验错误。
- 公开 API：`KnowledgeSearch.MaxTop`、`RetrievalFilter.MaxDocumentIds`。`AI.Abstractions` 是 `Preview`。
