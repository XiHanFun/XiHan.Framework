# ADR-0226 插件投递带订阅方式

## 状态

已采纳（`spec/plugin/plugin.proto` 的 `HandleEventRequest` 新增 `mode`，`spec/plugin/invocation.md` §4、`spec/rfcs/0009-messaging.md`「订阅方式」第 1 条与 `spec/rfcs/0017-plugin-protocol.md` 随之修订）。

## 日期

2026-11-13

## 背景

- ADR-0079 给订阅加了方式（竞争、广播），插件在握手的 `Subscription.mode` 里声明。握手第 5 条只禁止同一（主题，类型）对重复，同一主题的不同类型可以各用一种方式。
- 宿主按（主题，方式）各订阅一份，投递时只投给以这种方式订阅了该主题的插件，但 `HandleEventRequest` 不带方式。
- 插件声明（`t`，不限类型）竞争、（`t`，`x`）广播时，类型 `x` 的消息以两种方式各到一次。插件只能按主题与类型找处理器，两次都交给第一个匹配的：广播处理器收不到，竞争处理器收到两次。
- Go SDK 补上订阅方式（framework-sdk-go `f5dba1d`）时发现。

## 备选

1. **禁止同一主题用两种方式**：否决。RFC-0009 允许同一主题同时有两种方式的处理器，应用内的派发器按方式区分，插件不该少这一种能力。
2. **宿主把两种方式的投递合成一次**：否决。两种方式的语义不同（竞争进死信、可重放，广播尽力而为），尝试次数也各自计，合不成一次。
3. **投递带方式**：采纳。

## 决策

1. `HandleEventRequest` 新增 `string mode = 4`：这次投递的订阅方式，`competing` 或 `broadcast`。宿主总是填写，空同 `competing`。
2. 插件按（主题，方式）找处理器，再看类型。没有以这种方式声明的订阅时返回失败，不改交给另一种方式的处理器。
3. 进程外与 Wasm 宿主按 `MessageDelivery.Mode` 填写；`Plugins.Conformance` 与规范的黑盒运行器按订阅声明的方式投递。
4. Go SDK 按投递的方式找处理器（framework-sdk-go `782782a`）；`samples/EchoPlugin` 在 `events.list` 里报出每次投递的方式，端到端测试据此核对。

## 影响

- 线上兼容：新增字段，协议版本仍为 1。不认识这个字段的插件忽略它，行为不变；新插件遇到不填它的宿主按 `competing` 处理，这样的宿主上以广播声明的处理器收不到投递。
- 自己从 `plugin.proto` 生成桩的插件要重新生成，并在 `HandleEvent` 里按 `mode` 分派。
- 框架的公开 API 不变：协议桩是 internal。
