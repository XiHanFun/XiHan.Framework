# ADR-0205 幂等作用域键无歧义与内层调用的幂等键

## 状态

已采纳（RFC-0006「幂等」修订）。

## 日期

2026-11-12

## 背景

5.0 安全审查 S-24（`plans/5.0-安全审查.md`），低危，这里复现确认。

- **作用域键有歧义**：`idem:<租户>:<主体>:<键>` 直接拼接。主体 ID 能含冒号：主体 `a:b` 配键 `c`，与主体 `a` 配键 `b:c` 是同一个存储键，后者回放前者的结果。
- **匿名共用命名空间**：匿名调用的主体段都是 `-`，知道别人键的匿名调用方能拿到别人的结果。
- **MCP 的外层请求挡住内层**（功能缺陷）：`/mcp` 是经 `UseXiHan()` 的普通端点。带幂等键的请求先在外层写下「处理中」，同一个键的内层 `tools/call` 随即撞上它，得到 `CACHING_CONFLICT_002`，工具一次也执行不了。即使让内层不带键，外层的回放也只能还原结果、还原不了 JSON-RPC 答复。

复现：
- `IdempotencyMiddlewareTests.PrincipalsWithColons_DoNotShareRecords`：修正前第二个调用回放了第一个的结果。
- `McpIdempotencyTests.ToolCall_WithAnIdempotencyKey_RunsOnce_AndIsReplayed`：修正前第一个 `tools/call` 就是 `isError`。

## 备选

1. **转义主体 ID**：否决。匿名标记 `-` 本身是合法的主体 ID，转义还要为它另定规则；长度前缀更简单，也是单射。
2. **拒绝匿名调用带幂等键**：否决。没有能区分匿名调用方的身份，拒绝会让公开的幂等端点（匿名下单、报名）不能用；幂等键是调用方生成的随机串，本身就是秘密。
3. **把操作 ID 并进作用域键，让外层与内层分开**：否决。RFC-0006 规定同一个键在操作之间复用是 `CACHING_CONFLICT_003`，并进作用域会改掉这条语义；外层的回放仍然还原不了答复。
4. **外层请求把幂等键交给端点另起的内层调用**：采纳。

## 决策

1. **作用域键**：`idem:<租户或 ->:<主体>:<键>`，主体写成 `<长度>.<主体 ID>`，匿名为 `-`。租户 ID 不含冒号；长度前缀以数字开头，不会与 `-` 混淆。
2. **匿名**：已知并接受，写进 RFC-0006。键是唯一的保护，调用方要用猜不到的随机键（至少 128 位）。
3. **内层调用**：
   - 新的端点元数据 `InnerInvocationsMetadata`：端点为请求里的消息另起内层调用。
   - `HttpInvocation.CreateContext(httpContext)` 在端点带它时不把幂等键放进外层上下文。端点另起内层调用时用的 `CreateContext(httpContext, services)` 照常带上。
   - `MapXiHanMcp` 带这个元数据：幂等键交给每个 `tools/call`，按操作调用去重与回放。

## 影响

- 升级前写下的、主体非匿名的幂等记录不再命中：保留期（缺省 24 小时）内的重试会再执行一次。
- MCP 客户端带幂等键重试 `tools/call` 得到首次的结果。
- 公开 API：`InnerInvocationsMetadata`。
