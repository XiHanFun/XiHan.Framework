# ADR-0166 护栏方向与知识库检索请求

## 状态

已采纳（RFC-0022「聊天入口」「知识库」）。

## 日期

2026-11-11

## 背景

API 审查第三节「AI」一组：

- `IAIGuardrail.InspectAsync(messages)` 只收一组消息。它只能检查输入，模型的回答没有审查的位置；以后要给护栏更多上下文（提供方、提示词名、调用方），只能再改签名。
- `IKnowledgeStore.SearchAsync(collection, vector, top, filter)` 用位置参数，检索参数一多签名就要变。`KnowledgeQuery.MinScore` 由检索器在存储返回之后过滤，原生支持得分阈值的后端（如 Qdrant）用不上，不合格的块也要全部传回来。
- `TrimAsync(collection, documentId, chunkCount)` 一次只裁一篇，不合「批量优先」（batch-first.md）。

`IngestAsync` 逐项结果不带 `DocumentId` 的问题已由 ADR-0154 解决：结果与请求同序对齐。

## 决策

1. **护栏收检查上下文**：
   - `InspectAsync(GuardrailInspection inspection, ct)`。`GuardrailInspection` 是初始化器记录，含 `required Direction` 与 `required Messages`，以后加上下文只加属性。
   - `GuardrailDirection` 有 `Input = 0` 与 `Output = 1`，整数值以后只追加。
2. **非流式调用多一道输出检查**：
   - `CompleteAsync` 拿到响应、没有超时，再以输出方向检查模型返回的消息。
   - 拦截与出错的错误码与输入方向相同：拦截是 `AI_DENIED_001`，出错是 `AI_UNEXPECTED_001`。被拦下时不交出响应。
   - 流式调用只有输入方向：已经推给调用方的内容收不回来，要审查回答就用 `CompleteAsync`。
   - `SkipGuardrails` 两个方向都跳过。内置的 `KeywordBlocklistGuardrail` 只看输入方向，对输出方向放行。
3. **检索收请求对象**：
   - `SearchAsync(collection, KnowledgeSearch search, ct)`。`KnowledgeSearch` 的 `Vector` 与 `Top`（至少 1）经构造给出，`Filter` 与 `MinScore` 经初始化器给出。
   - 过滤与最低得分都由存储施加，低于 `MinScore` 的块不返回。
   - 检索器把 `KnowledgeQuery.MinScore` 原样交给存储，不再自己过滤。
   - `VectorDataKnowledgeStore` 在进程内逐条判断最低得分（连接器抽象没有统一的阈值参数），以后连接器支持时下推到服务端。
4. **裁剪按批**：
   - `TrimAsync(collection, IReadOnlyList<KnowledgeTrim> trims, ct)`，每项 `KnowledgeTrim(DocumentId, ChunkCount)`。构造时校验：ID 不能为空白，块数不能为负。
   - 空集合不访问后端，整批成功或失败。
   - 摄入器重新摄入时传一项。
5. **一致性套件**加两个用例：一次裁剪多篇（含空集合与不存在的文档），最低得分由存储施加。

## 影响

- 自写护栏改为接收 `GuardrailInspection`。只关心输入的护栏在 `Direction` 不是 `Input` 时放行，否则会在模型回答上误拦。
- 自写知识库存储按新签名实现 `SearchAsync` 与 `TrimAsync`，并在检索里施加 `MinScore`。
- 经 `IAIChat`、`IKnowledgeRetriever`、`IKnowledgeIngestor` 使用的调用方不用改。
- 这些类型都是 `Preview`，GA 前修改，不需要登记豁免（ADR-0131）。
