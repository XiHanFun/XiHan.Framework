# ADR-0070 同名消息目录合并；区域名不合法不占用错误码

## 状态

已采纳（`spec/rfcs/0010-localization.md` 与 `spec/conventions/error-codes.md` 随之修订）。

## 日期

2026-11-01

## 背景

写 5.0 文档站的国际化一章时发现，登记的两个本地化错误码没有任何代码会产生：

- `LOCALIZATION_CONFLICT_001`（同名消息目录重复注册）：`AddMessageCatalog` 遇到同名目录直接返回，后注册的那份被静默丢弃，不论内容是否相同。RFC-0010 写的是「同名目录只注册一次」，与错误码表自相矛盾。
- `LOCALIZATION_VALIDATION_001`（区域名不合法）：`LocaleName.Validate`、各构造函数与 `LocalizationOptions.FromConfiguration` 遇到不合法的区域名抛 `ArgumentException`；目录里的区域名不合法归 `LOCALIZATION_VALIDATION_002`；Baggage 与 `Accept-Language` 里的在协商中忽略。

改成「同名不同内容即冲突」之后，全量测试暴露出一处真实的静默丢弃：`Caching.Remote` 的宿主包嵌入了插件侧错误 `caching.remote.*` 的十种语言译文，目录名 `caching.remote`；Go 插件（framework-sdk-go 的 `examples/cache`）握手时也带一份同名目录，只有 en-US 与 zh-CN，模板与宿主包逐字相同。插件宿主先注册插件的目录，于是宿主包的另外八种语言一直被丢弃，日语等调用方拿到的是英文回退。包 README 写的「宿主不依赖插件自带的目录」并不成立。

## 备选

### 同名目录

1. 保持「只注册一次」，从错误码表删掉 `LOCALIZATION_CONFLICT_001`。
2. 同名即冲突，内容相同的重复注册除外。`Caching.Remote` 与 Go 插件就此启动失败，只能改其中一方的目录名，而插件的目录名在外部 SDK 里。
3. 同名目录合并为一份：区域与键取并集，同一键同一区域的模板不同才是冲突。
4. 同名后者覆盖前者。

### 区域名不合法

1. 让 `LocalizationOptions.FromConfiguration` 等改抛携带 `LOCALIZATION_VALIDATION_001` 的 `FrameworkException`。
2. 撤销 `LOCALIZATION_VALIDATION_001` 的登记，在 RFC-0010 写明各种来源的处理。

## 决策

### 同名目录合并

取 3。

- `AddMessageCatalog` 把同名目录合并为一份，留在先注册的位置。内容相同时什么都不变；互为补充时区域与键取并集，先有的在前。
- 同一键同一区域的模板必须逐字相同，否则抛出携带 `LOCALIZATION_CONFLICT_001` 的 `FrameworkException`，应用启动失败，已注册的目录不变。
- 合并在 `MessageCatalog` 的内部方法 `MergeWith` 里完成，公开 API 不变。

### 区域名不合法不占用错误码

取 2。传给 API 或写在选项里的不合法区域名是编程或配置错误，在调用处抛 `ArgumentException`；目录里的归 `LOCALIZATION_VALIDATION_002`；外部输入里的在协商中忽略。`LOCALIZATION_VALIDATION_001` 撤销登记，序号不复用；常量 `LocalizationErrors.InvalidLocale` 删除（尚未发布，PublicAPI 在 Unshipped）。

## 理由

### 同名目录合并

- 同名目录有正当的来源：多个 Provider 带同一个抽象包的目录，插件与宿主包各带一部分语言。备选 2 把后一种当作错误，又改不了外部 SDK 里的名字；备选 4 与原来一样会丢掉先注册的那份里独有的语言。
- 真正的冲突只有一种：同一键同一区域给出了两个不同的模板。这时任何取舍都会让某个调用方看到意料之外的文案，所以报错。
- 合并之后不再有被丢弃的内容，「只注册一次」的本意（同一份目录不重复）也保留下来。

### 区域名不合法不占用错误码

- 框架里所有 `FromConfiguration` 对不合法的值都抛 `ArgumentException`，`LocaleName` 是稳定 API，单为区域名改成 `FrameworkException` 会与其余选项不一致，也是破坏性变更。
- 外部输入的区域名本来就按协商规则容错，没有需要报给调用方的失败。
- 一个从不出现的错误码会让客户端写出永远走不到的分支。

## 影响

- 行为：同名目录不再静默丢弃后注册的那份。`Caching.Remote` 配合 Go 插件时，宿主包的十种语言生效；同一键同一区域的模板不同的应用会在启动时失败。
- 公开 API：`Localization.Abstractions` 删除 `LocalizationErrors.InvalidLocale`（PublicAPI −1），其余不变。
- 测试：
  - `MessageCatalogTests`：内容相同与子集不变、仍是先注册的实例；互为补充时合并并留在原位；同一键同一区域的模板不同抛出冲突，消息带键与区域，已注册的目录不变。
  - `RemoteCachingTests`：Go 插件与宿主包的 `caching.remote` 合并为一份，有十种语言，日语模板来自宿主包。修正前只有两种语言（Expected 10 / Actual 2）。
