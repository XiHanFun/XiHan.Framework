# ADR-0018 P5-09 能力补齐：租户分库进契约层、`IDistributedCache` 架在 `ICacheStore` 上、S3 走 AWS SDK、不补 Kafka

## 状态

已采纳（RFC-0007 / RFC-0006 / RFC-0012 修订）。

## 日期

2026-10-26

## 背景

[06-BasicApp迁移清查](../architecture/06-BasicApp迁移清查.md) 列出 BasicApp 跑在 5.0 之前要补的四项能力：租户分库（4.x `SysTenant.ConnectionString` + `SaasTenantConnectionProvider` 按租户缓存连接并可失效，隔离模式 Field / Schema / Database）、94 处 `IDistributedCache` 调用点、云对象存储（BasicApp 用 MinIO，30 处）、Production 配置里出现的 Kafka / Redis 事件总线。`multitenancy.sharding@1` 在 RFC-0007 里只是预留的能力 ID。

## 备选

1. 分片作为独立包 `MultiTenancy.Database`：租户目录与分片都进数据库，持久化 Provider 依赖它。
2. 分片契约进 `MultiTenancy.Abstractions`：`ITenantShardResolver` 由 Provider 实现，默认解析器从 `ITenantStore` 的租户属性推出，Tenant 阶段解析一次写进调用上下文，持久化 Provider 在作用域内按分片选连接。
3. 不进框架：应用在自己的 `ISqlSugarClient` 工厂里按租户换连接。
4. `IDistributedCache` 的 94 处调用点改成 `ISharedCache`。
5. 适配器 `CacheStoreDistributedCache` 架在 `ICacheStore` 上，调用点不改。
6. 对象存储每家云一个包（`ObjectStorage.AliyunOss`、`ObjectStorage.Minio`…），各用各的 SDK。
7. 一个 `ObjectStorage.S3` 用 AWS SDK，覆盖 Amazon S3 与全部兼容服务。
8. 补 `Messaging.Kafka`。
9. 不补，`messaging.stream` 保持无实现。

## 决策

- **取 2**。分片是租户信息的一部分（RFC-0007 的 `ITenantStore` 属性本来就允许"租户专属连接"），不该要求数据库。`TenantShard`（租户 ID、连接串、小写提供者名、透传属性）、`ITenantShardResolver`（`ResolveAsync` → `Result<Maybe<TenantShard>>`，`Invalidate`）与默认 `TenantStoreShardResolver`（属性键 `ConnectionString`、`DatabaseProvider`、`Shard.*`，按租户有界缓存）进 `MultiTenancy.Abstractions/Sharding`；`TenantResolutionMiddleware` 在租户写入安全上下文后解析分片写进调用上下文，解析失败即调用失败（`MULTITENANCY_UNAVAILABLE_002`），不降级为共库；`MultiTenancy.InMemory` 同时提供 `multitenancy.sharding@1`。`Persistence.SqlSugar` / `EntityFrameworkCore` 以可选依赖声明分片能力，作用域内创建客户端时经 `TenantShardBinding.Resolve` 读上下文（不触存储、不阻塞）：有分片按分片绑定另建连接，否则共用应用默认连接。只做 Database 隔离（分库）；Field 隔离是仓储的租户过滤，Schema 隔离由应用通过透传属性自行处理。`MultiTenancy.Database`（租户目录进数据库）另行按需做，分片不依赖它。
- **取 5**。适配器进 `Caching.Abstractions/Distributed`（`Microsoft.Extensions.Caching.Abstractions` 是 Ring 2 允许的抽象包）：键须满足 `CacheKey` 文法，绝对过期换算成 TTL、与滑动同时给时绝对优先，`Refresh` 是一次读取，同步成员在边界阻塞；三个 `caching.distributed` Provider 被选中时 `AddXiHanDistributedCache`（`TryAdd`），应用自己的登记优先。
- **取 7**。S3 协议是事实标准，MinIO、OSS、COS、R2 都提供兼容端点；AWS SDK 支持 `ServiceURL` + 路径式 + `WHEN_REQUIRED` 校验和，一个包覆盖全部。`ObjectStorage.AliyunOss` 从计划里删除。不覆盖用条件写入（`If-None-Match: *`），批量删除先逐键 HEAD 再一次 `DeleteObjects`，列举条目不带内容类型与自定义元数据（RFC-0012 注明"可能不完整"）。
- **取 9**。BasicApp 的 appsettings 没有事件总线节，代码里 Kafka 只出现在一个日志写入器，生产用 RabbitMQ；不补 Kafka，Redis 也不作消息 Provider（见 04 的废弃表）。

## 理由

- 分片在 Tenant 阶段解析一次、持久化 Provider 只读上下文，与 RFC-0007 "租户是调用上下文的一部分，没有环境态访问器"一致；缓存与失效语义对齐 4.x 的 `SaasTenantConnectionProvider`，迁移只是把 `SysTenant.ConnectionString` 放进租户属性。
- 适配器让 BasicApp 的 94 处调用点与依赖 `IDistributedCache` 的第三方库零改动，且过期语义有明确换算规则，不是"大致相同"。
- 一个 S3 包的维护成本远低于每家云一个包；兼容性差异（条件写入、校验和）在 README 与 RFC 里写明。

## 影响

- 新增错误码 `MULTITENANCY_UNAVAILABLE_002` 与消息键 `multitenancy.shard.unavailable`（10 种区域）；`MultiTenancyOptions.ShardCacheSize`（默认 10000）；`MultiTenancy.Conformance` 新增 `TenantShardResolverConformance`。
- `Persistence.SqlSugar` / `Persistence.EntityFrameworkCore` 新增对 `MultiTenancy.Abstractions` 的引用与 `multitenancy.sharding@1?` 可选依赖；分片库的表结构由应用管理，`InitTables` / `EnsureCreated` 只作用于默认连接。
- `Caching.Abstractions` 新增包引用 `Microsoft.Extensions.Caching.Abstractions`。
- 新包 `ObjectStorage.S3`（依赖 `AWSSDK.S3`，不满足 AOT 分析器）；其测试在设置 `XIHAN_TEST_S3` 时对真实服务跑一致性套件。MinIO 官方镜像已从 Docker Hub 与 quay.io 下架，本地验证用 `bitnamilegacy/minio`（MinIO DEVELOPMENT.2025-05-24）。
- `04-功能扁平化定义` 的 `ObjectStorage.AliyunOss` 删除、`Messaging.Kafka` 改按需、`MultiTenancy.Database` 改后续。
