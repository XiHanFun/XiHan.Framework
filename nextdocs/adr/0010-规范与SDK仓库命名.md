# ADR-0010 规范与各语言 SDK 分仓库，按 `framework-*` 命名

## 状态

已采纳（修订 ADR-0004 的 Go 包路径与 ADR-0007 的规范仓库名）

## 日期

2026-10-23

## 背景

P4 公开规范并开始第二语言。ADR-0007 决定规范在 P4 拆为独立仓库，ADR-0004 把 Go 包路径定为 `github.com/xihanfun/xihan-go`、规范仓库定为 `XiHanFun/xihan-spec`。拆出时要定下仓库布局（单仓库还是分仓库）与命名，组织里现有仓库是 `XiHan.Xxx` 风格，Go 模块路径又必须小写。

## 备选

1. 一个新仓库同时放规范、Go SDK 与运行器（monorepo，Go 模块在子目录）。
2. 规范一个仓库，每种语言 SDK 各一个仓库，沿用 ADR 里的 `xihan-spec` / `xihan-go`。
3. 同备选 2 的布局，仓库按 `framework-<角色>` 命名：`framework-spec`、`framework-sdk-go`、`framework-sdk-rust`（以后）。

## 决策

采用备选 3。

- `XiHanFun/framework-spec`：规范、一致性向量、规范文法与语言中立的黑盒运行器（Go 模块 `github.com/xihanfun/framework-spec/conformance`），公开，MIT。历史用逐提交重建的方式从 `next/spec` 拆出（38 个提交，作者与时间保留）。
- `XiHanFun/framework-sdk-go`：Go SDK，模块路径 `github.com/xihanfun/framework-sdk-go`，公开，MIT；`plugin.proto` 的 `go_package` 改为 `github.com/xihanfun/framework-sdk-go/plugin/v1`。
- `XiHanFun/framework-sdk-rust`：等 Wasm ABI 的 Rust 样板抽成 crate 时再建。
- XiHan.Framework 以 git submodule 在 `next/spec` 引用 `framework-spec`，路径不变，.NET 侧的 csproj 与测试按相对路径读规范文件的方式不变；规范改动先在 `framework-spec` 提交，再更新指针。

## 理由

- 规范与 SDK 的发布节奏不同：规范改一次所有语言都要跟，SDK 修一个 bug 不该动规范版本；分仓库天然各自打标签。OpenTelemetry、MCP、CloudEvents 都是"规范仓库 + 各语言 SDK 仓库"。
- Go 生态偏好模块在仓库根：`go get github.com/xihanfun/framework-sdk-go`、标签 `v0.1.0`；子目录模块要带 `go/v0.1.0` 前缀标签，Go 代理还得拉整个仓库，这个代价是永久的，而单仓库的好处只在 P4 这几周明显。
- 组织名已经是 XiHanFun，仓库名不必重复 "xihan"；`framework-` 前缀把它们和 `XiHan.Framework` 归到同一产品下，`sdk-<语言>` 是 CloudEvents（`sdk-go`、`sdk-csharp`）那种通行写法。
- submodule 精确锁定规范版本、不复制文件；新建 worktree 后要 `git submodule update --init`，CI 检出要带 `submodules: true`。

## 影响

- ADR-0004 的 Go 包路径与 ADR-0007 的仓库名以本文为准；`nextdocs/下一代框架总体方案.md` 的仓库表同步修改。
- XiHan.Framework 根目录新增 `.gitmodules`；`next-ci.yml` 检出带 submodule；AGENTS.md 的 worktree 步骤加 submodule 初始化。
- P4-08"Spec 拆为独立仓库并公开，含向量与运行器"由此完成；P4-05～07 在 `framework-sdk-go` 与 XiHan.Framework 的 `next/samples/EchoGoPlugin` 推进。
