# ADR-0105 工作流故障原因用消息键与参数，按调用方区域本地化

## 状态

已采纳（`spec/rfcs/0021-workflow.md`「故障与重试」后新增「故障原因的本地化」、「HTTP 活动的超时与取消」第 1 条、「子流程」随之修订）。修订 ADR-0097：HTTP 活动超时的节点故障改报消息键 `workflow.http.timed_out`，不再是 `workflow.http.failed` 带 `status` 0、`reason` `timeout`。

## 日期

2026-11-03

本 ADR 记录第十四批回灌（`r-batch-backlog.md`，BasicApp 报回的框架缺陷）的一项决定：工作流引擎给出的失败原因按调用方的区域本地化，同框架其余错误（RFC-0010）。

## 背景

BasicApp 发起授权申请时流程立即故障（没有解析出审批人），把 `instance.Fault.Message` 原样展示给用户，中文界面下也是英文。原因有两层：

1. 存储的形状：`WorkflowFault(Code, Message)` 只存写入时按进程默认区域渲染好的文本（`Error.Message`），消息键与参数在写入时丢掉了，读出来之后已经没法按调用方的区域重新渲染。
2. 失败原因本身：引擎与内置活动在很多地方把英文句子放进参数，即使外层是消息键，`reason` 仍是英文。

盘点（Workflow.Abstractions，按来源分两类）：

| 类 | 来源 | 原来 | 现在 |
| --- | --- | --- | --- |
| 存进实例 / 节点实例的故障 | 节点超时（执行器、`Delay`、`EventGateway`、`ExternalTask`、`ForEach`、`SubWorkflow`） | `workflow.activity.failed`，`reason` "The node timed out." | `workflow.node.timed_out`（`node`） |
| 同上 | 执行器没有调用 | `reason` "The activity has no invocation to run in." | `workflow.activity.no_invocation`（`type`） |
| 同上 | 活动属性不合法（`Delay`、`EventGateway`、`ExternalTask`、`ForEach`、`Http`、`PublishEvent`、`SetVariable`、`SubWorkflow`、`UserTask`、`WaitSignal`，引擎的 `Join` 模式） | `workflow.activity.property_invalid`，`reason` 英文短语 | 按种类 18 个键 `workflow.activity.property_*`（`name`，有原值的另带 `value`） |
| 同上 | 指派规则（`AssigneeRule.Parse`、`User`、`Expression` 规则） | `workflow.assignee.rule_invalid`，`reason` 英文 | `workflow.assignee.rules_not_array`、`rule_type_missing`、`expression_count`、`users_missing` |
| 同上 | 表达式结果不是布尔、模板占位符没闭合 | `workflow.expression.invalid`，`reason` 英文 | `workflow.expression.not_boolean`、`unterminated_placeholder` |
| 同上 | HTTP 超时 | `workflow.http.failed`，`status` 0、`reason` "timeout" | `workflow.http.timed_out` |
| 同上 | `Fault` 节点 | `workflow.activity.failed`，`reason` 作者的消息 | `workflow.activity.fault_raised`（`message` 原样） |
| 同上 | 没有开始节点 | `workflow.definition.invalid`，`errors` "no start node" | `workflow.definition.start_missing` |
| 同上 | 子流程没有正常完成（`SubWorkflow`、`ForEach`） | `workflow.child.failed`（`id`、`reason` = 子实例 `Code + ": " + Message`） | `workflow.child.failed`（`id`、`status`），子实例的故障是内层原因 |
| 返回给调用方的错误 | 外部任务的锁定时长、拉取条数、重试延迟 | `workflow.task.query_invalid`，`reason` 英文 | `workflow.external.lock_duration_invalid`、`max_tasks_invalid`（`count`、`max`）、`retry_after_negative` |
| 同上 | 待办查询既没给指派人也没给实例 | `workflow.task.query_invalid`，`reason` 英文 | `workflow.task.query_target_missing` |
| 同上 | 引擎自己开的调用没有工作单元（装配错误） | `workflow.store.unavailable`，`reason` 英文 | `workflow.store.unit_of_work_missing` |

其余已是消息键、参数也没有英文的（实例 / 书签 / 定义不存在、状态不允许、缺必填变量、没有指派人、汇合已死、波次上限、实例超时、任务结果不允许等）不动。发起、恢复、信号、完成、认领、退回、跳转、迁移返回的错误都是这些键之一；事件载荷里的 `fault` 就是实例的 `WorkflowFault`。

应用或第三方给的文本原本就不是框架能翻译的：活动抛出的异常消息（`workflow.activity.failed` 的 `reason`）、HTTP 应答的原因短语与连接异常（`workflow.http.failed` 的 `reason`）、外部任务工作者报的错误（`workflow.external.failed` 的 `reason`）、`Fault` 节点作者写的消息、存储与驱动的异常（`workflow.store.unavailable` 的 `reason`）、自定义活动经 `ActivityContext.PropertyInvalid(name, reason)` 给的原因。

## 备选

存储的形状：

1. 写入时按进程默认区域渲染、只存文本（原状）：按调用方区域展示无从做起。
2. 写入时按发起调用的区域渲染：文案只对发起人对，审批人、管理员、通知收件人的区域各不相同；同一条故障被不同的人看，只能有一种语言。
3. 存消息键与参数，展示时按读取方的区域渲染（采纳）：同幂等记录（`IdempotencyRecord`）的做法，参数值按不变文化转成字符串。

异常消息：

1. 丢掉原文、只给本地化的概括：排障时看不到真正的原因。
2. 原文进参数、外层是本地化的概括键（采纳）：`workflow.activity.failed` 本来就是这个形状，用户看到「活动 'Http' 失败：…」，冒号后面是原文。

子流程的故障：

1. 父节点的 `reason` 放子实例故障的文本：又回到存渲染好的文本。
2. 子实例的故障作为父节点故障的内层原因（采纳）：`Error.Inner` 本来就能携带，`WorkflowFault.Inner` 随之递归，展示时以 `workflow.fault.caused_by` 把两段接起来，两段同一种语言。子流程回调输入 `childFault` 随之从字符串改为 `WorkflowFault` 的 JSON。

## 决策

- `WorkflowFault` 新增 `MessageKey`、`Arguments`（`IReadOnlyDictionary<string, string>`，值按不变文化转成字符串）、`Inner`；`Code`、`Message` 不变，`Message` 仍是写入时按进程默认区域渲染的文本，只供日志。`WorkflowFault.From(error)` 连同内层一起存；`Localize()` 按当前消息作用域渲染（调用链里是调用方的区域，`App.InvokeAsync` 按 Baggage 的区域协商后安装，RFC-0010），有内层时以 `workflow.fault.caused_by`（参数 `message`、`cause`）接上；`ToError()` 返回带键、参数与内层的错误，宿主在 Egress 翻译；没有消息键的故障（自由文本，或升级前写入的）`Localize()` 是 `Message` 原文、`ToError()` 是自由文本的错误。
- 引擎与内置活动的失败原因全部改成上表的消息键，参数里只放属性名、原值、节点 ID 等标识，不放英文句子；10 种语言补齐。
- `workflow.child.failed` 的参数由 `id`、`reason` 改为 `id`、`status`，子实例的故障作为内层原因；`childFault` 是 `WorkflowFault` 的 JSON（`code`、`message`、`messageKey`、`arguments`、`inner`），没有故障为空，不是 JSON 对象时当作没有故障。
- 只承载英文原因、已没有调用点的 `WorkflowMessages.TaskQueryInvalid`（`workflow.task.query_invalid`）与 `AssigneeRuleInvalid`（`workflow.assignee.rule_invalid`）删除；自定义指派规则用应用自己的消息键。`ActivityPropertyInvalid` 与 `ActivityContext.PropertyInvalid(name, reason)` 留给自定义活动。
- 不动的：定义校验（创建、修改、发布时 `workflow.definition.invalid` 的 `errors`，以及 `AssigneeResolver.Validate` 返回的说明）的逐条明细、表达式解析器的语法诊断（`workflow.expression.invalid` 的 `reason`）仍是英文——设计期给流程作者看的诊断，不是运行期的失败原因，列为待定；变量 `lastError` 仍是错误码与按进程默认区域渲染的消息，供表达式判断，不用于展示。

## 理由

- 同一条故障会被不同区域的人看到（发起人、审批人、管理员、通知收件人），只有存键与参数、读取时渲染才能各自是自己的语言。
- 不改表：`WorkflowFault` 在实例与节点实例的 JSON 文档里（数据库实现的 `Document` 列），新属性随文档读写；故障事件同样是 JSON。没有列、索引、回填，`InitTables` 无变化。
- 升级前写入的故障没有键，原文展示，不猜测、不重写旧数据。

## 影响

- 公开 API（Workflow.Abstractions，Unshipped）：`WorkflowFault` 新增 `MessageKey`、`Arguments`、`Inner`、`Localize()`；`WorkflowMessages` 新增 36 个常量（`FaultCausedBy`、`NodeTimedOut`、`ActivityNoInvocation`、`ActivityFaultRaised`、`HttpTimedOut`、`Property*` 18 个、`Assignee*` 4 个、`ExpressionNotBoolean`、`ExpressionUnterminatedPlaceholder`、`DefinitionStartMissing`、`StoreUnitOfWorkMissing`、`TaskQueryTargetMissing`、`ExternalTask*` 3 个），删除 `TaskQueryInvalid`、`AssigneeRuleInvalid`；`ChildFailed` 的参数改为 `id`、`status`。Workflow.Conformance 新增用例方法两个。错误码不变。
- 行为：同一错误码下消息键变了的有上表各项；HTTP 超时的节点故障不再带 `status` / `reason`；`childFault` 输入由字符串变为对象。没有表结构、配置键、启动失败条件的变化。
- 测试：引擎用例 38（发起即故障、完成任务之后活动失败、子流程故障三条路径，实例、节点实例与故障事件上的故障经存储与事件往返仍带键与参数，zh-CN 与 en-US 分别渲染，`ToError()` 带键与内层）、39（外部任务的锁定时长与拉取条数、待办查询的目标，错误只带键与参数，按两种区域解析）；Abstractions 的 `WorkflowFaultTests`（内层与 `caused_by`、参数按不变文化、自由文本与升级前的故障、JSON 往返与旧文档）；HTTP 超时用例改断言消息键。修改验证：子流程失败不带内层时用例 38 失败；`From` 不存消息键时用例 38 失败。
- 升级（BasicApp）：展示故障原因处把 `Fault?.Message` 换成 `Fault?.Localize()`（在调用里即调用方的区域）；把故障作为错误返回的，用 `Fault.ToError()` 作内层或直接返回；通知按收件人区域渲染的，在 `MessageScope.Use(null, locale)` 里调 `Localize()`。

## 4.x 对照

4.x 的实例与节点实例存一段文本 `FaultMessage`（只读查看 `framework/src/XiHan.Framework.Workflow.Abstractions/Runtime/WorkflowInstance.cs`、`WorkflowNodeInstance.cs`），不随调用方的区域变化；5.0 这里不对齐 4.x，按 RFC-0010 与框架其余错误统一。
