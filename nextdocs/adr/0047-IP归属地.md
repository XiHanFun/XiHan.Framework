# ADR-0047 IP 归属地：契约进 Security.Abstractions，离线库实现单独成包

## 状态

已采纳（`spec/rfcs/0008-security.md` 增「IP 归属地」节，`spec/conventions/capability-ids.md` 登记 `security.ip-region`）。

## 日期

2026-10-29

## 背景

BasicApp 6.0 Access 深化报告：条件属性 `environment.geo.country / province / city / isp`（预置模板"境外访问"）、命中记录与登录日志的归属地列都要 IP 归属地。4.x 在 `XiHan.Framework.Web.Core/Clients`：`IIpRegionResolver` 加 `Ip2RegionResolver`（ip2region 离线库），5.0 没有。要求做成抽象加离线库实现，宿主可以不装，不装时归属地属性按缺失处理。

## 备选

1. 放进 `Hosting.AspNetCore`：归属地与 HTTP 无关，消息派发、命令行也可能有对端地址；条件引擎在 `Security.Abstractions`，不该依赖宿主包。
2. 新开领域词（如 `Geo`）：要改术语表、新开抽象包，只为一个接口不值得。
3. 契约进 `Security.Abstractions` 的子命名空间 `Network`，实现单独成 Ring 3 包 `Security.Ip2Region`：归属地在这里服务访问控制与安全审计，契约包零第三方依赖，`IP2Region.Net` 只进实现包。

## 决策

采用 3。

- `IIpRegionResolver.Resolve(IPAddress)` 返回 `Maybe<IpRegion>`（5.0 用 `Maybe` 表达可能没有的结果）。`IpRegion` 是（国家，省份，城市，运营商，国家代码），`Location` 是展示文本。能力 `security.ip-region@1`（`SecurityCapabilities.IpRegion`）。
- `Security.Ip2Region`（`Ip2RegionSecurityFeature`）：
  - xdb 文件由宿主提供，框架包不带数据。配置节 `XiHan:Security:Ip2Region:V4Database` / `V6Database`，缺省 `IpDatabases/ip2region_v4.xdb` 与 `IpDatabases/ip2region_v6.xdb`，相对路径按 `AppContext.BaseDirectory` 解析。
  - 首次用到某个地址族时整库读进内存（`CachePolicy.Content`）。文件缺失或加载失败记一条警告，该族之后一律无值。
  - 回环与私有网段不查，IPv4 映射地址按 IPv4 查。单次查询失败按无值处理，地址不进日志。
  - 记录文本两种格式照 4.x 解析：新版"国家|省份|城市|运营商|国家代码"，旧版"国家|区域|省份|城市|运营商"。`0` 与空段为未知，`Reserved` 与全未知为无值。
- 与 4.x 的差异：
  - 4.x 的启用开关 `EnableIpRegion` 不再需要：装不装特性就是开关。
  - 4.x 按内容根找文件并逐个试多个候选路径；5.0 只认配置的两个路径。
  - 日志工厂取内核登记的 `ILoggerFactory`，没有日志时是空实现。

## 理由

- 契约与实现分开：只要归属地字段而不想带离线库的应用（或换成在线服务、MaxMind 等）只依赖契约。
- 宿主可以不装，调用方经容器判断有没有本服务，归属地属性按缺失处理，条件引擎的无法判定语义已经覆盖。
- 不访问网络：访问控制的判定路径上不能有外部调用。

## 影响

- 公开 API：`Security.Abstractions.Network` 的 `IIpRegionResolver`、`IpRegion`；`SecurityCapabilities.IpRegion`；新包 `Security.Ip2Region`（`Ip2RegionSecurityFeature`、`Ip2RegionResolver`、`Ip2RegionOptions`）。中央包版本增加 `IP2Region.Net` 3.0.2。
- 测试：`Security.Ip2Region.Tests`（两种记录格式与未知 / 保留、回环与私有网段不查、映射地址、库不可用与查询失败、选项、特性装配），设 `XIHAN_TEST_IP2REGION_V4` 时用真实库查一次公网地址。
