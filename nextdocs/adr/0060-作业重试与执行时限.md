# ADR-0060 作业重试与执行时限

## 状态

已采纳（`spec/rfcs/0013-scheduling.md` 作业一节增加重试与执行时限；错误码 `SCHEDULING_TIMEOUT_001`）。

## 日期

2026-10-31

## 背景

BasicApp 6.0 N2 收尾时报告：4.x 的任务调度有最大重试次数与超时（`maxRetryCount`、`timeoutSeconds`），5.0 的 `JobDefinition` 没有。一次运行失败后不会自动再跑，也没办法限制单次执行时长。管理面要能展示和修改这两项。

## 决策

- 作业定义加两项，都随作业持久化，`JobStatus.Job` 带出：
  - `Retry`（`JobRetryPolicy`）：`MaxRetries` 1–100；`Delay` 是第一次重试前的等待；`Backoff` 为 `Fixed` 或 `Exponential`（第 n 次重试等 `Delay × 2^(n-1)`）；`MaxDelay` 是指数退避的上限。等待与上限最长 30 天。
  - `Timeout`：大于零、不超过 30 天。
- 重试：
  - 只有失败的运行重试：作业返回失败、抛出异常或超过执行时限。被取消（取消请求、宿主停止）与失联的运行不重试。
  - 重试是一次新运行：`JobTrigger.Retry`，`JobRun.Attempt` 加一（首次为 1），`RetryOf` 指向首次运行，`Data` 与失败的那次相同。运行记录、事件数据同样带上这两项。
  - 集群唯一的作业把重试写成存储里的一次性触发器（`retry-` 前缀），到期时刻是失败时刻加等待时间，任一节点抢占运行，进程重启不丢。
  - 不允许并发的作业照常独占：上一次未结束时，重试阻塞到它结束。
  - `RunOnEveryInstance` 的作业在失败的实例上进程内等待，不进存储，实例停止时未到期的重试丢弃。
  - 手动 `TriggerAsync` 失败也重试，调用方拿到第一次的结果。
- 执行时限：
  - 另挂一个按时钟到期的取消源，与取消请求合成作业拿到的令牌。
  - 作业返回之前时限已过，运行记为失败，错误码 `SCHEDULING_TIMEOUT_001`；作业不响应取消时，运行在它返回后才结束。
  - 取消请求在先时仍记为取消。
- 代码作业的指纹在设置了重试或时限时才计入它们，没设的作业指纹不变，升级后不会把已有的运行时修改当成代码变了。
- 顺带修正：`ScheduleAsync`、`RestoreAsync`、`UnscheduleAsync` 先把代码作业同步进存储，与 `TriggerAsync` 和暂停 / 恢复一致。原来宿主刚启动、首个轮询周期之前改代码作业，会被记成运行时作业，随后的同步又冲掉这次修改。同步之前读状态时按代码定义拼的作业记录也补上了这两项。

## 理由

- 重试复用一次性触发器：入队与失联恢复已经走这条路，抢占、独占、misfire 与跨节点都现成，不另建重试队列，也不需要新表。
- 新运行而不是原地重跑：每次尝试都有自己的开始、结束、结果与节点，历史里能按 `RetryOf` 串起来，界面不用拆一条记录。
- 每个实例的作业在本实例重试：放进存储会被别的实例抢到，违背「每个实例各自运行」；本地触发器本来也只在内存里推算。
- 超时用取消令牌而不是强行中止：.NET 不能安全地中止任务，作业需要配合取消，这与取消请求的语义一致。

## 影响

- 公开 API：
  - `Scheduling.Abstractions`：`JobRetryPolicy`、`JobRetryBackoff`；`JobDefinition.Retry` / `Timeout` / `TimeoutLimit`；`JobRecord.Retry` / `Timeout`；`JobRun.Attempt` / `RetryOf`；`JobRunRecord.Attempt` / `RetryOf`；`TriggerRecord.Attempt` / `RetryOf`；`JobTrigger.Retry`；`SchedulingEventData.Attempt` / `RetryOf`；`SchedulingErrors.RunTimedOut`、`SchedulingMessages.RunTimedOut`（十种区域）；`JobSchedulerEngine.RetryTriggerPrefix`。
  - `Scheduling.Database`：`JobEntity` 五个可空列；`TriggerEntity` 与 `JobRunEntity` 的 `Attempt`、`RetryOf`。都是可空列，已有的表加列即可。
- 行为：设置了策略的作业失败后会再跑；设置了时限的作业到时收到取消。
- 测试：
  - 一致性套件（内存与数据库实现都跑）：重试到成功、次数用尽、每实例作业在本实例重试；超时失败并重试、取消不重试；状态里的两项、运行时修改与恢复。
  - 存储套件：新字段往返。
  - 单测：等待时间的计算与取值范围。
