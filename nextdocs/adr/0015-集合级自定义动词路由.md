# ADR-0015 自定义动词按请求是否含 id 分实例级与集合级 HTTP 路由

## 状态

已采纳

## 日期

2026-10-25

## 背景

`spec/conventions/operation-ids.md` 原来把所有非标准动词统一推导为 `POST /{resource}/{id}:{verb}`。BasicApp 迁到 5.0 后共 522 个操作，其中 260 个是没有标识的集合级动词（`user-query.list-user`、`auth.login`、`access-log-query.list-access-log` 等），按原约定得到 `POST /user-query/{id}:list-user`，调用方只能填占位符 `_`，路由值还会被绑定进请求对象。前端改接 5.0 之前必须把这个形态定下来。

## 备选

1. 保持约定，调用方对没有标识的操作填 `_`。零改动，但 URL 带无意义段，占位值会进请求对象，OpenAPI 里每个集合级动词都多一个必填路径参数。
2. 应用用 `XiHan:Protocols:Http:Routes` 为每个集合级操作逐条覆盖。约定不变，但 BasicApp 要维护 260 条路由配置，任何新操作都要补一条。
3. 改约定：路由按请求对象是否声明 `id` 属性分实例级与集合级——有 `id` 的带 `/{id}` 段（`GET /orders/{id}`、`POST /orders/{id}:cancel`），没有的落在集合或单例资源上（`GET /profile`、`PUT /profile`、`POST /orders:export`，Google AIP 的两种形态）；`create` 与 `list` 恒为集合级。HTTP 适配器从操作描述的请求序列化元数据（`JsonTypeInfo.Properties`）判定，不用反射，AOT 友好。

## 决策

采用备选 3。`OperationDescriptor` 公开 `RequestInfo` / `ResponseInfo`（`JsonTypeInfo?`，载荷原样搬运的插件代理为 null），`HttpRouteConvention.Derive(contract, hasIdentifier)` 与 `HttpProtocolOptions.RouteFor(descriptor)` 据此推导；`HttpRouteConvention.HasIdentifier(descriptor)` 先看序列化元数据，没有再看请求 Schema 的 `properties`，按序列化名不分大小写找 `id`，都没有按集合级处理。显式覆盖表优先级不变。

## 理由

- 判定依据是请求形状而不是额外标注：源生成的 `JsonTypeInfo` 已经带着属性清单，内核、gRPC、MCP 都不需要知道这件事。
- 两种形态都是业界已有的形式，OpenAPI 文档里集合级动词不再出现虚假的必填路径参数。
- 标准动词同样按请求形状判定：BasicApp 的 `profile.get` / `profile.update`（当前用户的单例资源）、`user-setting-query.get`（按场景与键取值）本来就没有标识，强加 `/{id}` 只会得到占位符。无 `id` 的 `get` 与 `list` 会撞到同一条 `GET /{resource}`，`MapXiHanOperations` 对重复路由以 `PROTOCOLS_CONFLICT_002` 启动失败，由显式覆盖解决。

## 补充（同日）

BasicApp 的代码生成模块有 4 个 `list` 操作以分页请求（嵌套的 `page` 与 `conditions`）为输入，按原约定推导成 `GET /{resource}`，但 GET / DELETE 不读请求体、嵌套对象进不了查询串，这些路由实际调不通。于是 `get` / `list` / `delete` 只在请求只有标量（及标量集合）字段时用无请求体的方法，否则改用 POST 自定义动词：`POST /{resource}:list`、`POST /{resource}/{id}:get`、`POST /{resource}/{id}:delete`。判断同样来自请求的序列化元数据（属性类型的 `JsonTypeInfoKind` 为 `Object` / `Dictionary`，或集合元素不是标量），插件代理看 Schema。

## 影响

- `Protocols.Http` 的 `Derive(OperationContract)` 与 `RouteFor(OperationContract)` 被带描述的重载替代（预览期，未发布符号）。
- `Kernel.OperationDescriptor` 新增两个可空 virtual 属性，类型化描述返回源生成的元数据，插件代理保持 null。
- BasicApp 的 260 个集合级操作路由变为 `POST /<资源>:<动词>`，前端据此改接。
