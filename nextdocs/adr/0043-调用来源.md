# ADR-0043 调用来源：协议适配器写入协议、请求目标与客户端信息

## 状态

已采纳（`spec/rfcs/0003-invocation-context.md` 规则 6）。

## 日期

2026-10-29

## 背景

BasicApp 6.0 N2 第三批（Auditing）报告：`InvocationContext` 只有 Trace、Baggage、截止时间与凭据，`HttpInvocation.CreateContext` 不带远端地址、User-Agent、HTTP 方法与路径，gRPC、MCP 也一样。BasicApp 在 Observe 阶段写访问日志与异常日志、在 Identity 写登录日志与会话的 IpAddress / ClientInfo，都拿不到这些值；4.x 直接读 `HttpContext`，6.0 的操作与中间件不绑定 HTTP，拿不到 `HttpContext`，会话表这两列一直为空。

## 备选

1. 应用自己在 `UseXiHan()` 之前加 ASP.NET Core 中间件，把 `HttpContext` 的值塞进 Baggage：Baggage 会跨进程传播且只收已登记的键，客户端信息不该随下游调用外传；gRPC、MCP、命令行各自另写。
2. 在 `InvocationContext`（原语层）加属性：原语层零行为、跨语言，字段表即 RFC-0003 的传播契约，传输层事实不属于它。
3. Kernel 增加一个与协议无关的只读项 `InvocationOrigin`，放在 `Items`（与安全上下文、调用结果同一机制），由每个协议适配器与派发器在建上下文时写入。

## 决策

采用 3。

- `InvocationOrigin`（record，`required` 的 `Protocol` / `Target`，可空的 `RemoteAddress` / `UserAgent` / `Referer`）、`InvocationProtocols`（`http`、`grpc`、`mcp`、`cli`、`messaging`、`job`、`workflow`）与 `GetOrigin()` / `SetOrigin()`，都在 `Kernel.Pipeline`。没有来源时 `GetOrigin()` 为无值。
- HTTP（`HttpInvocation.CreateContext`）：目标为方法与路径（含 PathBase，不含查询串，查询串可能带令牌）；远端地址取 `Connection.RemoteIpAddress`，IPv4 映射的 IPv6 还原为 IPv4。宿主在 `UseXiHan()` 之前 `UseForwardedHeaders()` 时就是转发头改写后的客户端地址；框架不自己解析 `X-Forwarded-For`，信任哪些代理由宿主配置决定。空头记 `null`。
- gRPC：同一请求先按 HTTP 建上下文，再把协议与目标改成 `grpc` 与方法全名（`ServerCallContext.Method`）。
- MCP：`tools/call` 的子调用记 `mcp` 与 tool 名；HTTP 传输时远端地址、User-Agent 与来源页沿用外层请求，stdio 传输没有。外层 HTTP 请求本身仍是 `http`。
- 命令行：`CommandLineInvocation.Create` 增加 `operationId` 参数，记 `cli` 与操作 ID。
- 消息派发记主题，作业运行记作业名，工作流活动记活动类型。缓存回源、存储维护、测试宿主等内部调用不写。
- HTTP 状态码不进来源：访问日志要状态码时，失败按 `ProblemResponse.StatusCodeFor(error)`，成功按 `HttpRouteConvention.SuccessStatusCode(contract)`。这两个就是框架写响应时用的同一映射，作为正式入口。

## 理由

- 客户端信息是这一跳的传输事实，不应跨进程传播；放在 `Items` 与安全上下文同一机制，派生上下文（`WithBaggage`）共享。
- 由适配器写入，Observe 阶段的中间件、操作处理器与经 `IInvocationAccessor` 的深层服务都能读，应用不需要知道协议。
- 只认宿主已改写的连接地址：转发头可以伪造，是否信任由宿主的 `ForwardedHeadersOptions`（已知代理与网络）决定，与 ASP.NET Core 一致。

## 影响

- 公开 API：Kernel 新增 `InvocationOrigin`、`InvocationProtocols` 与两个扩展方法；`CommandLineInvocation.Create` 改为 `(CommandContext, string operationId)`（5.0 尚未发布）；消息、调度、工作流的一致性套件记录来源（`ReceivedMessage.Origin`、`RecordingJobLog.Runs` 三元组、`ConformanceLog.Origins`）。
- 行为：所有经协议适配器与派发器的调用都带来源，没有其他行为变化。
- 测试：`WebHostTests`（方法与路径、PathBase、查询串不进目标、IPv4 映射、UA / Referer、经 `UseForwardedHeaders()` 的客户端地址）、gRPC（方法全名、gRPC 客户端 UA）、MCP（HTTP 传输沿用外层 UA / 来源页，stdio 只有 tool 名）、命令行（操作 ID）、内核单测（派生上下文共享、校验）与三个一致性套件。
