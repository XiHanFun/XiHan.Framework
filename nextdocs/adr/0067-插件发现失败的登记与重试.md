# ADR-0067 插件发现失败的登记与重试

## 状态

已采纳（`spec/plugin/lifecycle.md` §1、§5、§6 与 `handshake.md` §5 的落地）。

## 日期

2026-11-01

## 背景

写文档站时核对插件宿主的实际行为，发现三处与规范不符：

- 发现时被拒的插件（清单读不出或种类不符、权限未授予、缺入口、入口文件不存在）在登记运行时之前就返回，特性的发现循环直接跳过。它们不在 `IPluginHost.Plugins` 里，没有健康条目，配置阶段宿主日志还是空日志工厂，连日志都没有。包 README 却写着「以 Failed 留在宿主里」。
- `handshake.md` §5 要求握手阶段的失败按重启策略处理，但 `PluginRuntime.RestartAsync` 只由运行期崩溃触发。启动阶段的握手、`Configure`、`Start` 失败一次就永远 `Failed`。
- 停止超时直接终止进程树。`lifecycle.md` §5.2 要求先发 SIGTERM、5 秒后再强杀，Windows 一侧只写了含糊的「关闭进程」。

## 决策

**发现时被拒**

- 按目录发现时，被拒的插件以 `Failed` 登记，不启动插件代码。它可描述，出现在 `Plugins` 里，是健康条目 `plugins.<清单 ID>`，可以 `UnloadAsync`。
- 清单读不出来时没有清单 ID，只登记健康条目，名字取 `plugins.<目录名>`。
- 这类失败是配置错误，不重试。
- 宿主附着到容器、有了日志之后，把清单读不出、被拒与握手失败的插件逐个记为错误日志。
- 运行期 `LoadAsync` 的同类失败仍直接返回给调用方，不登记。

**启动阶段失败的重试（进程外）**

- 握手、`Configure`、`Start` 失败与崩溃共用同一个退避循环，计入 `RestartLimit`。
- 配置阶段发现时的失败，等宿主附着到容器后才开始重试。那时回调服务器已在监听，日志与时钟也换成了容器里的。
- 运行期 `LoadAsync` 的这类失败返回给调用方，插件保持 `Failed` 并立即开始重试，直到 `UnloadAsync`。
- 首次握手就失败的插件，重试成功后才有声明。宿主按运行期加载的方式把代理操作登记进 `OperationRegistry`，只对 `IOperationInvoker` 可见。事件订阅与消息目录要在配置阶段接进容器，这时补不进去：宿主记一条警告，宿主重启后才生效。
- 声明登记不进去（与已有操作重名）是配置错误：停掉进程，按发现时被拒处理，不再重试。
- 懒激活插件首次调用时启动失败，该次调用失败，下一次调用再试，不起后台重试。
- 宿主附着时改用容器里的 `TimeProvider`。重启退避、健康轮询与停止等待都按它计时，测试可以推进时钟、不等真实时间。

**停止超时的终止信号**

- 宽限内没有退出：先关闭插件的 stdin（`handshake.md` §1 要求插件随之退出），Unix 上同时经 libc `kill` 发 SIGTERM。
- 按宿主时钟再等 5 秒，仍未退出才终止进程树。
- Windows 没有 SIGTERM，关闭 stdin 就是等价的终止信号。规范里写明这一点，取代原来的「关闭进程」。
- 两种结局都记为 `Failed`（`PLUGINS_TIMEOUT_001`）：插件没有在宽限内完成 `Stop`。

## 理由

- 静默消失的插件最难排查：健康端点、`Plugins` 与日志都看不到它，只能翻配置去猜。登记为 `Failed` 后它和握手失败的插件一样可观测。
- 被拒不重试：清单、授予与文件在进程内不会自己变好，重试只会刷日志。改正后显式 `UnloadAsync` + `LoadAsync`，或重启宿主。
- 重试要等附着之后：配置阶段还没有容器，回调服务器没有监听，日志是空的，这时起后台重试既不能回调也看不到过程。
- 迟到的声明只登记代理操作：协议适配器的路由与消息订阅在启动时已经定型。与运行期加载保持同一个边界，比为迟到插件另开一套补登记机制简单，也不会改变已发布的协议面。
- Windows 不用 `GenerateConsoleCtrlEvent`：插件以 `CreateNoWindow` 启动，向它发控制台事件需要新的进程组并附着控制台，代价与副作用都大。stdin 关闭本来就是协议规定的退出信号，跨平台一致。

## 影响

- 公开 API：没有新增。
- 行为：
  - 发现时被拒的插件出现在 `Plugins` / `Describe` / 健康条目里，应用因此 `Degraded`。之前应用仍是 `Ready`。
  - 启动阶段失败的进程外插件会在后台重试。
  - 停止超时多等至多 5 秒。
- Wasm 宿主只做了「发现时被拒以 `Failed` 登记」。它的握手失败仍不重试，`wasm.md` §5 只规定了陷阱后的重建。
- 进程外宿主为 `LibraryImport` 生成代码开启 `AllowUnsafeBlocks`，源码不写 `unsafe`。
- 测试：
  - 被拒插件的登记、健康条目与日志（进程外、Wasm）。
  - 启动阶段与运行期加载的握手失败在依赖恢复后按推进的时钟重试成功，并补登记代理操作。
  - 终止信号：收到信号即退出的进程不被强杀；不理会信号的进程满 5 秒才被终止。
