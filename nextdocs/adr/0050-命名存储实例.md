# ADR-0050 命名存储实例

## 状态

已采纳（`spec/rfcs/0012-objectstorage.md` 增「命名存储实例」一节，`spec/conventions/error-codes.md` 登记两个错误码）。

## 日期

2026-10-29

## 背景

BasicApp 6.0 N2 第四批（Files）报告：4.x 的存储配置可以有多条（本地、S3、OSS、COS、MinIO），按平台与租户各有缺省，每条有自己的端点、桶与密钥，存放在库里、运行时可改。5.0 的对象存储只有一个缺省的 `IBlobStore`，配置来自一个固定的配置节。BasicApp 只好自己按存储配置建 `S3BlobStore`，自己缓存与释放 S3 客户端，自己做逐条的健康检查。本轮要求由框架实现、BasicApp 不写替代。

## 备选

1. 键控服务（`AddKeyedSingleton<IBlobStore>(name)`）：实例在装配时就要定下来，运行时从库里读出、可改可删的存储配置放不进去。
2. 工厂 `IBlobStoreFactory.Create(settings)`：每次都建新实例，缓存、替换、释放与健康检查仍要应用自己做。
3. 注册表：按名缓存实例，定义来自配置或运行时登记；每个存储包登记一个按定义建实例的 Provider；注册表负责替换、释放与逐实例健康项。

## 决策

采用 3。

- **定义** `BlobStoreDefinition`：
  - 实例名（`^[a-z0-9][a-z0-9-]{0,63}$`）、Provider 名（不区分大小写）与设置。
  - 设置的键同该 Provider 的配置节，不区分大小写。未知的键报错，拼错的键不会被静默忽略。
  - `Describes(other)`：Provider 名与设置完全相同才是同一个实例。
- **Provider** `IBlobStoreProvider`（每个存储包一个，单例）：
  - `CreateAsync(definition)`：设置不合法抛 `ArgumentException`；后端此刻建不出来抛 `IOException` / `UnauthorizedAccessException`。
  - `ProbeAsync(store)`：给健康项用。
  - `FileSystemBlobStoreProvider`（`filesystem`）：
    - `RootPath` 必填，不给就会和缺省实例落到同一目录。
    - 建出时即建目录、扫描用量。
    - 探测看总配额。
  - `S3BlobStoreProvider`（`s3`）：
    - 每个实例按自己的端点、区域与密钥建客户端，不读连接绑定。
    - 实例拥有客户端，释放实例即释放客户端；容器里的缺省实例不拥有客户端。
    - 探测对实例的 `HealthBucket` 做 HEAD，没配时列桶。
  - 选项各增 `FromSettings`，与 `FromConfiguration` 共用一份解析。S3 的探测间隔不在设置里，由注册表统一。
- **注册表** `BlobStores`（`ObjectStorage.Abstractions`，单例）：
  - 存储包装配时经 `AddBlobStoreProvider<T>(configuration)` 登记，任一存储包装配即有，注册表本身只登记一次。
  - `GetAsync(name)`：取已建的实例；配置节 `XiHan:ObjectStorage:Stores:<name>`（`Provider` 加设置）里有定义的，首次取用时建出；都没有 → `OBJECTSTORAGE_NOTFOUND_003`。
  - `GetOrAddAsync(definition)`：同定义复用；定义变了建新实例替换并释放旧的。
    - Provider 未登记或设置不合法 → `OBJECTSTORAGE_VALIDATION_003`。
    - I/O 或权限错误 → `OBJECTSTORAGE_UNAVAILABLE_001`。
    - 这两种情况下，已有的同名实例都不受影响。
  - `RemoveAsync(name)` 移除并释放；`DisposeAsync` 释放全部。
  - 缺省的 `IBlobStore` 注入方式不变，命名实例与缺省实例互不相干。
- **健康**：
  - 注册表是健康项贡献者，每个实例一条 `objectstorage.store.<name>`。
  - 按 `XiHan:ObjectStorage:StoreHealthProbeIntervalSeconds`（缺省 15 秒）在后台逐个探测，一轮没探完就跳过下一轮；新实例建出后立即探一次。
  - 尚未探过为 Started，探测失败或超时为 Degraded（实例仍可取用）。实例在探测期间被替换或移除，结果丢弃。
- **预签名**：命名实例的能力随实例本身。
  - S3 实例同时是 `IBlobMultipartStore` 与 `IBlobUrlSigner`，直连存储。
  - 文件系统实例经宿主签名器 `HostedBlobUrlSigner.ForStore(name)`：签出的地址带 `x-store=<name>`，实例名进签名的规范串（第三行，缺省实例为空行），端点经注册表取实例。
  - 签名有效但实例不存在 → 404（`OBJECTSTORAGE_NOTFOUND_003`）；分片地址要求该实例实现 `IBlobMultipartStore`。
- **一致性**：新增 `BlobStoreProviderConformance`，文件系统与 S3（MinIO）都通过。四个用例：
  - 按定义建出的实例可读写、探测通过。
  - 未知的设置键被拒绝。
  - 经注册表同定义复用、定义变了替换、移除后不存在。
  - 定义错误被翻译成对应错误码，且不影响已有实例。

## 理由

- 定义可以来自库、运行时可改，注册表按定义比对就能把"改了配置"变成一次替换，应用不必自己判断。
- Provider 按包登记，与能力选择无关：应用可以只把文件系统选为缺省实例，同时用 S3 的命名实例。
- 设置沿用各 Provider 配置节的键：同一份说明既管配置节也管命名实例；未知键报错，库里的存储配置写错能在保存时就发现。
- 宿主签名器按实例签名而不是每个实例一把密钥：密钥轮换仍只有一处，实例名进签名，地址不能被挪到别的实例上用。

## 影响

- 公开 API：
  - `ObjectStorage.Abstractions` 新增 `Stores.*`（`BlobStoreDefinition`、`IBlobStoreProvider`、`BlobStores`、`BlobStoreServiceCollectionExtensions`）。
  - 错误码两个、消息键三个，十种区域。
  - 包引用 `Microsoft.Extensions.Configuration.Abstractions` 与 `Microsoft.Extensions.DependencyInjection.Abstractions`。
  - `ObjectStorage.FileSystem` 新增 `FileSystemBlobStoreProvider` 与 `FileSystemObjectStorageOptions.FromSettings`。
  - `ObjectStorage.S3` 新增 `S3BlobStoreProvider` 与 `S3ObjectStorageOptions.FromSettings`，`S3BlobStore` 实现 `IDisposable`。
  - `Hosting.AspNetCore` 新增 `HostedBlobUrlSigner.ForStore` 与 `Store`。
  - `ObjectStorage.Conformance` 新增 `BlobStoreProviderConformance`。
- 行为：
  - 宿主签名的规范串多一行实例名，ADR-0049 签出的地址失效（5.0 尚未发布，且地址本身限时）。
  - S3 绑定属性 `forcePathStyle` 写错时的报错文字改为说明是绑定属性。
- 架构门禁：注册表的健康项名随运行时登记的实例而定，存储包的清单列不出来，`HealthContributionTests` 把 `ObjectStorage.Abstractions` 列入与插件宿主同类的动态贡献者（只豁免反向检查）。
- 测试：
  - 文件系统：注册表（配置定义的实例、名字不合法的配置节、设置错误、配额耗尽即降级、替换 / 移除 / 停止时释放、特性装配后的健康项）与宿主端点（命名实例的下载与上传、改实例名或去掉即 403、实例不存在 404）。
  - S3：对 MinIO 的配置定义实例直签下载、健康桶不存在即降级、拼错的设置键。
