# ADR-0124 载荷错误只留路径

## 状态

已采纳（`spec/rfcs/0011-operations.md` 随之修订）。

## 日期

2026-11-04

本 ADR 记录第三十一批回灌（`ak-batch-backlog.md`，N5 安全审查，用户定修）的第五项。

## 背景

`OperationDescriptor<TRequest, TResponse>.DecodeRequest` 把 `JsonException.Message` 写进 `KERNEL_VALIDATION_001` 的 `reason`，这个错误回给调用方。System.Text.Json 的消息带目标类型的全名，比如 `The JSON value could not be converted to MyApp.Orders.CreateOrderRequest`，调用方能借它看到内部的类型与命名空间。

N5 的审查扫了把异常消息写进错误的地方，用户定只改这一处，其余 62 处不动。

## 决策

`reason` 只写 `JsonException.Path`（`$.quantity`）。`Path` 缺失时写 `$`。

## 备选

1. **用正则从消息里去掉类型名**：消息文本不是 System.Text.Json 的契约，升级就失效。否决。
2. **写固定文本**：调用方定位不到哪个字段。否决。

## 影响

这是对外行为变化：`reason` 的内容变了，`KERNEL_VALIDATION_001` 的错误码和 `id`、`reason` 两个参数都不变。

缺必填属性时路径是 `$`，错误不再说缺哪个属性。要字段级的错误，给操作登记请求 Schema，Validate 阶段先于解码报出 `required` 违例。

其余把异常消息写进错误的地方没有动，包括 `DecodeResponse`：它解的是幂等回放时存下来的响应，不是调用方发来的载荷。
