# ADR-0021 撤掉 4.x 迁移规则集：4.x 单独维护，只保留通用迁移机制

## 状态

已采纳（部分替代 ADR-0014 中「迁移靠 `xihan migrate v4`」的安排；RFC-0020 修订）。

## 日期

2026-10-26

## 背景

ADR-0014 取消了 `Compat.V4` 垫片，改由 `xihan migrate v4` 把 4.x 源码改写成 5.0，规则 `V4-01` … `V4-10` 写在 `spec/migration/v4.md`。工具在 BasicApp 上跑通之后，BasicApp 第一批模块已在其 `next` 分支上完成迁移并独立演进；4.x 由维护者单独维护（ADR-0008 的维护期安排不变），不再计划把其他 4.x 应用迁到 5.0。

规则集约 6000 行实现、1700 行测试，规则正文 234 行，随 5.0 每次改契约（命名空间分区、实体协议、租户标识）都要同步修，却只服务一次性的迁移。

## 备选

1. **保留 `migrate v4` 并继续维护**：每次 5.0 契约变化都要改规则与测试，收益只剩"万一还有 4.x 应用要迁"。
2. **整个删除 `migrate` 命令**：5.x 之后的大版本升级要重新搭执行器、标记与报告。
3. **删除 4.x 规则集，保留通用机制**：命令按来源版本选规则集，执行器、规则基类、会话、标记、报告与试运行留下，规则集为空。

## 决策

选 3。

- 删除 4.x 规则集的全部实现与测试、规范 `spec/migration/v4.md`、只服务这些规则的文案键。
- `xihan migrate <来源版本>` 保留：执行器两遍扫描、按顺序改写、写回、生成 / 删除 / 改名、报告与 `--dry-run` 不变；规则集按来源版本登记，当前为空，任何来源版本都报 `CLI_VALIDATION_002`。通用约定移到 `spec/migration/README.md`。
- 开发计划去掉"迁移指南覆盖 4.x 全部 66 个项目的去向"这一 P5 退出条件，P5-07 的文档站不再包含 4.x → 5.0 迁移指南。

## 理由

- 规则集只为一次迁移存在，迁移已经做完，继续随契约同步是纯成本。
- 通用机制与具体规则无关，删掉再重建反而浪费；5.x → 6.x 时只需写规则正文与规则实现。
- 规则正文与实现都留在 git 历史里（framework-spec 的 `b69d13a`、XiHan.Framework 的 `399df703` 之前的提交），需要时可以查。

## 影响

- `XiHan.Framework.Cli`：`Migration` 目录只剩执行器、规则基类、Roslyn 改写基类、会话、标记、文件模型与报告；`migrate` 的帮助文案与错误文案改为按规则集描述。
- BasicApp 源码里残留的 `// xihan-migrate(V4-xx)` 标记不再有规则正文对应，按普通待复核注释处理，处理完删掉。
- `nextdocs/architecture/05-开发计划.md`：P5-02 标为已撤回，P5-07 与 7.2 退出条件同步。
