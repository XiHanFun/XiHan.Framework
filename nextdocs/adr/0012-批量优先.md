# ADR-0012 批量优先：集合入参、原生批量、逐项结果

## 状态

已采纳

## 日期

2026-10-23

## 背景

AGENTS.md 要求仓储、缓存等对集合的操作提供原生批量方法，调用方不在循环里逐条操作。[06-BasicApp迁移清查](../architecture/06-BasicApp迁移清查.md) 第 5 节查出 5.0 的 `IRepository<TEntity, TKey>`、`ICacheStore` / `ICache` / `ISharedCache`、`IMessagePublisher` / `IMessageBroker` 只有单条方法，而 BasicApp 迁移会把 4.x 的循环单条写法原样带进来。P5 把批量优先放在最前（P5-00）。

## 备选

1. 只在实现层加批量扩展方法（`AddRangeAsync` 作为对单条方法的循环封装），抽象不动。
2. 抽象层加批量方法，单条是批量的特例；逐项结果与入参顺序一一对应，Provider 用后端原生批量；按查询条件的批量更新 / 删除也进抽象。
3. 同备选 2，但不提供按查询条件的批量更新 / 删除。

## 决策

采用备选 3，写成规范性约定 `spec/conventions/batch-first.md`，并修订 RFC-0005 / 0006 / 0009 / 0019：

- 仓储：`FindManyAsync(ids)`、`AddRangeAsync` / `UpdateRangeAsync` / `RemoveRangeAsync(entities)` 返回与入参等长的 `IReadOnlyList<Result>`；逐项校验（标识重复、缺租户、不存在、并发冲突）后通过校验的项一次写入，写入阶段的基础设施失败对这些项统一报告；EF Core 用 `AddRange` + 一次 `SaveChanges`，内存实现一次进覆盖层。
- 缓存：`GetManyAsync(keys)`、`SetManyAsync(entries)`、`RemoveManyAsync(keys)`，`TryAdd` / `TryRemove` 保持单键；Redis 用 `MGET` 与管道，内存实现一次加锁；远程操作集加 `cache-entries.get-many / set-many / remove-many`，Go SDK 的 `caching.Store` 同步。
- 消息：`PublishAsync(topic, envelopes)` 逐项结果，发件箱用仓储批量一次写入，投递循环按主题批量发布后批量更新；RabbitMQ 在同一通道上连续发布，内存代理一次入队。
- 批内重复项按入参顺序逐项施加语义；空集合不触后端；进入后端前检查取消，写入阶段不中途取消。
- 框架内部（发件箱、插件宿主的 `Host.Publish`、CloudEvents 入站、数据库翻译存储）与示例处理多个对象时调用批量方法，`Architecture.Tests` 检查循环体内不出现单条写入与发布。

## 理由

- 备选 1 没有改变后端往返次数，只是把循环藏起来；Provider 原生批量（多行插入、`MGET`、管道、同通道连续发布）才是用户要的"原生"。
- 逐项结果比汇总异常更适合校验类失败（一批里只有一条标识重复），而基础设施失败（后端不可用）本来就是整批的事，两者并用最诚实。
- 按查询条件的批量更新 / 删除（`UPDATE … WHERE`）绕过协议维护的审计、并发戳与软删除字段，抽象层承诺不了一致语义；由 Provider 专属包（EF Core 的 `DbContext`、SqlSugar 的客户端）按需提供。
- 单条作为批量的特例保留，调用方不被迫包装成单元素列表。

## 影响

- `IRepository`、`ICacheStore`、`ICache`、`IMessagePublisher`、`IMessageBroker` 各加批量成员；自定义实现者必须实现它们（5.0 之前的 Preview 实现没有兼容垫片）。
- 一致性套件 `Persistence.Conformance`、`Caching.Conformance`、`Messaging.Conformance` 加批量用例，所有 Provider 必须通过。
- 新增 `CacheEntry` 类型；`RemoteCacheOperations` 与向量 `caching-distributed.json` 加三个批量操作；framework-sdk-go 的 `caching` 包加 `GetMany` / `SetMany` / `RemoveMany`。
- 后续 `Persistence.SqlSugar`（P5-03）按同一约定用 `Insertable(list)` / `Updateable(list)` / `Deleteable(list)` 实现。
