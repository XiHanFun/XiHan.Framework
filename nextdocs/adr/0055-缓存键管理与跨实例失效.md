# ADR-0055 缓存键管理与跨实例失效

## 状态

已采纳（`spec/rfcs/0006-caching.md` 增加「键管理」「变更通知」两节，两级缓存一段修订）。

## 日期

2026-10-30

## 背景

BasicApp 6.0 N2 第七批（Maintenance）做 4.x 的缓存管理页时报告了两个缺口：

- 页面要按模式列键、读值与字节数、改值、删键、按模式删。`ICacheStore` 只有按键的读写删，没有枚举、元数据与按前缀删除。
- 两级缓存在一个实例删键后，别的实例的 L1 最长 `LocalTimeToLive` 仍读到旧值。管理页删了键也不能马上生效。

## 决策

- 键管理是可选能力 `ICacheStoreInspector`，不进 `ICacheStore`：
  - `ListKeysAsync(CacheKeyQuery)`：按前缀分页列键。`Prefix` 与键同文法、可以为空（全部）；`Limit` 1–1000，默认 100；`Continuation` 续页，没有更多时为空。
  - `InspectAsync(key)`：载荷字节数（不含存储自己的头部）、剩余存活时间与滑动窗口；不存在或已过期为无值。读元数据不延长滑动过期。
  - `RemoveByPrefixAsync(prefix)`：返回删除数；空前缀抛出 `ArgumentException`，不提供清空全部。
  - 读值、改值、删单个键仍走 `ICacheStore`。
- 实现：
  - 内存存储按键的序数顺序分页，续页标记是上一页最后一个键。
  - Redis 存储用单个端点的 `SCAN`：续页标记是游标，页大小是提示值，同一个键可能出现在两页；前缀里的 glob 字符转义。读元数据把 `PTTL`、`STRLEN`、`GETRANGE` 放进一个批次。
  - 远程插件的存储不实现。
- 变更通知是可选能力 `ICacheChangeFeed`：`Subscribe(handler)` 收到 `CacheChange`，内容是写入或删除的键，或按前缀删除时的前缀。
  - 本实例的变更在写入返回前同步通知；其他实例的经后端转发，不回送给发出者。
  - 通知是尽力而为的：断线期间可能丢失，发布失败不让写入失败。
  - Redis 存储在每次写入与删除（真的删到了才算，按前缀删除总是）后，向频道 `<KeyPrefix>__changes` 发后不等地发布，消息带来源标识；第一次有人订阅时才订阅频道。`XiHan:Caching:Redis:PublishChanges`（默认 `true`）关掉发布，本实例的同步通知不受影响。
- 两级缓存：L2 的存储实现了 `ICacheChangeFeed` 时订阅它，收到变更即删掉 L1 里的这些键或前缀。
  - `HybridCache` 因此实现 `IDisposable`，释放即退订；`InvalidatesAcrossInstances` 表示是否订阅到了。
  - 没有通知时（远程插件等）保持原来的上限：最长 `LocalTimeToLive`。

## 理由

- 枚举键在 Redis 上是 `SCAN`，代价与语义（可能重复、页大小不定）都和按键读写不同。放进可选接口，业务代码拿不到，管理界面明确地转型使用。
- 用前缀而不用 glob 模式：前缀在内存与 Redis 上语义一致，转义后键里的 `*`、`?`、`[` 不会改变含义。4.x 的「按模式」在管理页上换成「按前缀」。
- 失效走存储层的通知，而不是两级缓存自己发消息：管理界面直接改存储也能失效各实例的 L1，不要求写入方是两级缓存。
- 本地同步通知加写后发布：一次写入之后，本实例的 L1 与 L2 不会分歧；跨实例只承诺尽力而为，与 L1 的存活上限组合起来，读到旧值的时间仍然有界。

## 影响

- 公开 API：
  - Caching.Abstractions：`ICacheStoreInspector`、`CacheKeyQuery`、`CacheKeyPage`、`CacheEntryInfo`、`ICacheChangeFeed`、`CacheChange`、`CacheKey.IsValidPrefix`。
  - Caching.InMemory：`InMemoryCacheStore` 实现 `ICacheStoreInspector`。
  - Caching.Redis：`RedisCacheStore` 实现 `ICacheStoreInspector`、`ICacheChangeFeed` 与 `IDisposable`；`RedisCachingOptions.PublishChanges`。
  - Caching.Hybrid：`HybridCache` 实现 `IDisposable`，增加 `InvalidatesAcrossInstances`。持有它的类型需要随之可释放（CA1001）。
  - Caching.Conformance：新增用例 `Inspector_ListsInspectsAndRemovesByPrefix`，存储不实现即跳过。
- 行为：
  - Redis 存储每次写入与删除多一次发后不等的 `PUBLISH`。
  - 多实例部署下，两级缓存的 L1 在别的实例写入后立即失效。
- 测试：
  - 一致性套件的键管理用例，在内存与真实 Redis 上运行。
  - Redis 变更通知：两个连接模拟两个实例，覆盖本地同步、跨实例转发、不回送、按前缀、退订与关闭发布。
  - 两级缓存收到键与前缀的变更即失效 L1，释放即退订。
