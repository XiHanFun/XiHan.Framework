## 一、文件与项目规范

### 1.1 文件编码

| 规范 | 值 |
| --- | --- |
| 编码 | UTF-8 without BOM |
| 换行符 | LF（`\n`） |
| 文件末尾 | 一个空行 |

### 1.2 文件头

所有 `.cs`、`.csproj`、`.props` 文件只保留两行版权声明；生成的代码（`.g.cs`、`*.generated.cs`）可省略：

```csharp
// Copyright (c) XiHanFun Contributors. Licensed under the MIT License.
// See the LICENSE file in the project root for full license text.
```

### 1.3 文件组织（每个 .cs 文件）

```csharp
// 1. 版权声明
// 2. using 指令（命名空间外）：系统 → 第三方 → 框架内部，空行分隔
// 3. 文件作用域命名空间
// 4. 类型定义

using System.Collections.Immutable;
using Microsoft.Extensions.DependencyInjection;
using XiHan.Framework.Kernel.Capabilities;

namespace XiHan.Framework.Kernel.Hosting;

public sealed class AppBuilder { }
```

规则：

- 一个文件一个顶层类型；嵌套类型与私有辅助类型例外。
- 全局 using 在项目级 `GlobalUsings.cs` 中定义。
- 不使用 `#region`。

### 1.4 项目文件（.csproj）

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <PackageId>XiHan.Framework.Kernel</PackageId>
    <Description>XiHan Framework 微内核：宿主、能力图谱、执行管道、诊断与安全原语、插件宿主抽象。</Description>
    <PackageTags>XiHan;Framework;Kernel</PackageTags>
    <RootNamespace>XiHan.Framework.Kernel</RootNamespace>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Microsoft.Extensions.DependencyInjection.Abstractions" />
    <PackageReference Include="Microsoft.Extensions.Hosting.Abstractions" />
  </ItemGroup>
</Project>
```

规则：

- 每个包必须有 `<Description>`、`<PackageTags>`、`README.md`、`PublicAPI.Shipped.txt` / `PublicAPI.Unshipped.txt`。
- 版本号由 `Directory.Build.props` 统一管理，所有包共享一条版本线。
- 依赖版本由 `Directory.Packages.props` 中央管理，不在项目里写版本。
- 原语层与内核只能引用 `Microsoft.Extensions.*` 抽象包。

## 二、命名规范

### 2.1 通用规则

| 元素 | 风格 | 示例 |
| --- | --- | --- |
| 命名空间 | PascalCase，等于包 ID，子命名空间最多一层 | `XiHan.Framework.Kernel.Pipeline` |
| 类 / 结构体 / 记录 | PascalCase | `PipelineBuilder` |
| 接口 | PascalCase + `I` 前缀 | `IPipelineMiddleware` |
| 枚举类型与成员 | PascalCase | `Stability.Stable` |
| 方法 | PascalCase，异步以 `Async` 结尾 | `InvokeAsync()` |
| 属性 | PascalCase | `IsEnabled` |
| 局部变量、参数 | camelCase | `serviceProvider` |
| 私有实例字段 | `_camelCase` | `_middlewares` |
| 私有静态字段 | `s_camelCase` | `s_defaultOptions` |
| 常量 | PascalCase | `DefaultTimeout` |
| 泛型类型参数 | `T` 或 `T` + 描述 | `T`、`TFeature`、`TContext` |

### 2.2 框架特有约定

| 元素 | 约定 | 示例 |
| --- | --- | --- |
| 包 ID | 总体方案 §5.3 文法：`XiHan.Framework.<领域>[.<角色>]` | `XiHan.Framework.Persistence.EntityFrameworkCore` |
| 领域词 | 只能取自术语表（总体方案 §5.4） | `Persistence`、`Caching`、`Security` |
| 抽象包 | `<领域>.Abstractions` | `XiHan.Framework.Caching.Abstractions` |
| 实现包 | 按机制或技术命名，不用 `Default` | `Caching.InMemory`、`Caching.Redis` |
| 一致性套件 | `<领域>.Conformance` | `XiHan.Framework.Caching.Conformance` |
| 源生成器 / 分析器 | `<领域>.Generators`、`Kernel.Analyzers` | `XiHan.Framework.Persistence.Generators` |
| 能力包入口 | `<名称>Feature`，实现 `IFeature` | `EntityFrameworkCoreFeature` |
| 中间件 | `<名称>Middleware`，实现 `IPipelineMiddleware` | `TenantResolutionMiddleware` |
| 操作 | `<动词><资源>`，实现 `IOperation<TRequest, TResponse>` | `CreateOrder` |
| 端口接口 | `I` + 名词 | `IRepository<T>`、`IMessagePublisher` |
| 选项 | `<领域或能力>Options` | `CachingOptions` |
| 能力 ID | `<领域小写>.<能力>` | `persistence.relational` |
| 操作 ID | `<resource>.<verb>` | `orders.create` |
| 错误码 | `<领域大写>_<KIND>_<NNN>` | `PERSISTENCE_CONFLICT_001` |
| 配置节 | `XiHan:<领域>` | `XiHan:Caching` |
| Baggage 键 | `xihan.<name>` | `xihan.tenant` |

### 2.3 禁止的命名

- 类型名带 `XiHan` 前缀（命名空间已标识归属）。
- 无意义后缀：`Manager`、`Helper`、`Util`、`Utils`、`Common`、`Shared`、`Core`、`Base`、`Impl`、`Default`。
- 隐喻词：`Bus`、`Engine`、`Magic`，以及任何哲学词汇。
- 匈牙利命名法：`strName`、`intCount`。
- 非官方缩写：`Mgr`、`Cfg`、`Svc`。业界通用缩写按 .NET 规则，两字母全大写（`AI`、`IO`），更长用 Pascal（`Jwt`、`Mcp`、`Oss`）；品牌名保留官方拼写（`RabbitMQ`、`MongoDB`）。
- 中文或拼音标识符。
- 版本号进包名或类型名（原语层破坏性并存的 `.V2` 除外）。

## 三、C# 代码风格

### 3.1 类型定义

```csharp
// 正确：简洁、sealed、只实现需要的接口
public sealed class PipelineBuilder
{
    private readonly ImmutableList<MiddlewareDescriptor>.Builder _descriptors = ImmutableList.CreateBuilder<MiddlewareDescriptor>();

    public PipelineBuilder UseAt<TMiddleware>(PipelineStage stage, Placement placement = Placement.End)
        where TMiddleware : IPipelineMiddleware
    {
        _descriptors.Add(new MiddlewareDescriptor(typeof(TMiddleware), stage, placement));
        return this;
    }
}
```

规则：

- 非继承用的类一律 `sealed`。
- 字段能 `readonly` 就 `readonly`。
- 公开类型必须有 `[ApiLevel]`。

### 3.2 接口定义

```csharp
// 最小接口，单一职责
public interface IPipelineMiddleware
{
    ValueTask InvokeAsync(InvocationContext context, PipelineDelegate next);
}

// 能力包入口
public interface IFeature
{
    string Name => GetType().Name;
    void Configure(FeatureContext context);
}

// 错误：大量方法在一个接口中
public interface IApplicationService
{
    Task<T> GetAsync<T>(Guid id);
    Task<IReadOnlyList<T>> GetListAsync<T>(QueryRequest request);
    Task<T> CreateAsync<T>(T dto);
    // ...
}
```

### 3.3 方法

- 方法体不超过 30 行（生成代码例外）。
- 参数不超过 4 个，超过用选项对象。
- 避免 `out` 和 `ref` 参数。
- 返回具体类型（`PipelineBuilder`），接受接口参数（`IPipelineMiddleware`）。
- 异步方法接受并传递 `CancellationToken`，不阻塞、不吞异常。

### 3.4 属性与方法

属性：简单数据访问，无副作用。方法：有计算、有副作用、有异步。

### 3.5 空值处理

```csharp
public string? OptionalValue { get; init; }       // 可为空
public required string RequiredValue { get; init; } // 不可为空，用 required 而非空字符串默认值

public void Configure(FeatureContext context)
{
    ArgumentNullException.ThrowIfNull(context);
}
```

Nullable 是契约的一部分，不用 `!`、空字符串或默认实例掩盖非法状态。

### 3.6 不可变与记录

```csharp
// 数据载体用 record
public sealed record Error(string Code, string Message, IReadOnlyDictionary<string, object?>? Details = null, Error? Inner = null);

// 选项用 record + init
public sealed record PipelineOptions
{
    public bool ThrowOnError { get; init; } = true;
    public TimeSpan Timeout { get; init; } = TimeSpan.FromSeconds(30);
}
```

## 四、注释与文档

### 4.1 何时写注释

| 情况 | 是否写 |
| --- | --- |
| 显而易见的代码 | 不写 |
| 非显而易见的"为什么" | 写一行 |
| 公开 API | XML 文档注释，说明职责、约束、参数与返回值语义 |
| 性能敏感的决策 | 写一行 |
| 对某个缺陷的绕行 | 必须写，标明 issue 编号 |
| 临时方案 | `// HACK: 原因` |

### 4.2 禁止的注释

- 装饰性块注释、作者与日期注释（Git 已记录）。
- 注释掉的代码。
- 复述代码的废话注释（`// 设置名称`）。

### 4.3 XML 文档注释

```csharp
/// <summary>
/// 管道中处理一次调用的中间件。
/// </summary>
public interface IPipelineMiddleware
{
    /// <summary>
    /// 执行中间件逻辑并调用管道中的下一个中间件。
    /// </summary>
    /// <param name="context">当前调用的上下文。</param>
    /// <param name="next">管道中下一个中间件的委托。</param>
    ValueTask InvokeAsync(InvocationContext context, PipelineDelegate next);
}
```

公开类型、成员和选项必须有准确的 XML 文档；中文说明，标识符与术语保留英文。

## 五、异常与错误

### 5.1 异常设计

```csharp
// 框架异常基类（原语层）
public class FrameworkException : Exception
{
    public string Code { get; }
    public FrameworkException(string code, string message, Exception? inner = null) : base(message, inner) => Code = code;
}

// 具体异常（内核）
public sealed class CapabilityResolutionException : FrameworkException
{
    public string CapabilityId { get; }
    public CapabilityResolutionException(string capabilityId, string message)
        : base("KERNEL_CAPABILITY_001", message)
        => CapabilityId = capabilityId;
}
```

规则：

- 所有框架异常继承 `FrameworkException`，带错误码。
- 错误码格式 `<领域大写>_<KIND>_<NNN>`，注册在 `spec/conventions/error-codes.md`。
- 异常只用于不可恢复或编程错误；可恢复的失败用 `Result<T>`。

### 5.2 Result 模式

原语层提供 `Result<T>`、`Result`、`Error`、`Maybe<T>`，不在其他包重复定义：

```csharp
public async ValueTask<Result<OrderId>> HandleAsync(CreateOrderRequest request, InvocationContext context)
{
    if (request.Lines.Count == 0)
        return Error.Validation("ORDERS_VALIDATION_001", "订单至少包含一行。");

    var id = await _repository.AddAsync(Order.Create(request), context.CancellationToken);
    return id;
}
```

## 六、日志规范

### 6.1 级别

| 级别 | 场景 |
| --- | --- |
| `Trace` | 极详细信息，仅开发时启用 |
| `Debug` | 调试信息 |
| `Information` | 关键状态变更：特性 Ready、租户创建 |
| `Warning` | 非预期但可恢复：重试、降级、可选依赖缺失 |
| `Error` | 需要关注的错误 |
| `Critical` | 系统级故障：必需绑定不可用 |

### 6.2 结构化日志

```csharp
// 正确：结构化参数，使用 LoggerMessage 源生成器
[LoggerMessage(Level = LogLevel.Information, Message = "Feature {FeatureName} reached {State} in {ElapsedMs}ms")]
static partial void FeatureStateChanged(ILogger logger, string featureName, LifecycleState state, long elapsedMs);

// 错误：字符串插值
_logger.LogInformation($"Feature {name} configured");
```

内核只依赖 `Microsoft.Extensions.Logging.Abstractions` 与 `System.Diagnostics`，不自建日志体系。

## 七、测试规范

### 7.1 测试项目结构

```text
test/
├── XiHan.Framework.Primitives.Tests/        # 原语层单元测试 + 一致性向量回放
├── XiHan.Framework.Kernel.Tests/
│   ├── Capabilities/
│   ├── Pipeline/
│   └── Hosting/
├── XiHan.Framework.<领域>.<实现>.Tests/       # 每个实现包一个测试项目，引用对应 Conformance 套件
├── XiHan.Framework.Architecture.Tests/      # 依赖方向、命名文法、零反射、第三方类型泄漏
├── XiHan.Framework.Integration.Tests/       # 跨包装配与协议端到端
├── XiHan.Framework.Benchmarks/              # BenchmarkDotNet 基线
└── XiHan.Framework.Aot.Smoke/               # Native AOT 发布冒烟
```

`<领域>.Conformance` 套件位于 `src/`，是正式发布的包，供第三方 Provider 引用。

### 7.2 测试命名

```text
{Method}_{Scenario}_{ExpectedBehavior}

Build_WithNoFeatures_ReturnsApp
Resolve_WithCircularRequires_ThrowsCapabilityResolutionException
Resolve_WithOptionalMissing_MarksFeatureDegraded
```

### 7.3 测试结构（AAA）

```csharp
[Fact]
public async Task Invoke_WithAuthorizeStage_DeniesWithoutPermission()
{
    // Arrange
    var pipeline = new PipelineBuilder()
        .UseAt<AuthorizationMiddleware>(PipelineStage.Authorize)
        .Build();
    var context = TestInvocationContext.Anonymous();

    // Act
    var result = await pipeline.InvokeAsync(context, TestOperations.Echo);

    // Assert
    Assert.Equal("SECURITY_DENIED_001", result.Error!.Code);
}
```

### 7.4 覆盖要求

| 对象 | 要求 |
| --- | --- |
| 原语层与内核公开 API | 100% 单元测试覆盖，并回放 Spec 一致性向量 |
| 实现包 | 通过对应 `Conformance` 套件；未通过最高只能标 `Preview` |
| 管道阶段与内置中间件 | 100% 集成测试覆盖 |
| 生命周期状态机 | 覆盖所有状态迁移与失败路径 |
| 容量、过期、并发语义 | 每个有界集合有测试 |

不以覆盖率数字代替有效断言；不删除测试或放宽阈值来通过门禁。

## 八、依赖管理规范

### 8.1 依赖方向

```text
Primitives ← Kernel ← <领域>.Abstractions ← <领域>.<实现> ← Hosting / Protocols ← Plugins ← 应用
```

只能依赖更低的环；同环之间只经 `.Abstractions`；架构测试强制。

### 8.2 第三方依赖规则

| 规则 | 说明 |
| --- | --- |
| 原语层与内核零第三方依赖 | 仅 `Microsoft.Extensions.*` 抽象包 |
| 实现包最小传递 | 只引入该实现必需的库 |
| 版本集中管理 | `Directory.Packages.props` |
| 选择顺序 | 微软官方包 → .NET 基金会或成熟官方生态 → 社区长期维护的成熟包 |
| 安全审计 | 每个 PR 跑 `dotnet list package --vulnerable`，高危阻断 |

### 8.3 API 封装规则

- `.Abstractions` 包不暴露任何第三方类型。
- 实现包通过接口包装，内部委托给第三方库；`ICacheStore` 不暴露 `StackExchange.Redis.IDatabase`。

## 九、Git 提交规范

### 9.1 提交消息

与仓库 `AGENTS.md` 一致：

```text
<type>(<scope>): <中文说明>

type：feat / fix / docs / style / refactor / perf / test / build / chore
scope：术语表领域词小写（primitives / kernel / persistence / caching / security …），或 spec / docs / build
说明：中文，简短，不加句号

示例：
feat(kernel): 管道支持按阶段插入中间件
fix(persistence): 工作单元在取消时正确回滚
docs(spec): 补充能力 ID 文法
```

### 9.2 分支策略

- 下一代在 `next` 分支开发，GA 后并入主线；日常改动直接提交到当前分支。
- 并行工作按仓库约定开 worktree：`feat/<名>`、`fix/<名>`、`issue/<编号>`、`pr/<编号>-review`。

### 9.3 PR 要求

- 关联一个 issue 或 RFC。
- 通过 CI：构建、测试、分析器、架构测试、包验证、AOT 冒烟。
- 公开 API 变更必须更新 `PublicAPI.Unshipped.txt` 并在 PR 描述中标注。
- 新增术语表条目或错误码必须附 RFC。
