## 一、总览

### 1.1 门槛制

路线图不按日期，按门槛：每个阶段列出退出条件，满足才进入下一阶段。任务规模用 S / M / L 粗估（约 1 天 / 3 天 / 1 周以上），不做日级排期。

```text
P0 定边界 → P1 内核 → P2 子系统 → P3 协议与宿主 → P4 插件与跨语言 → P5 GA 与迁移 → 5.x 后续
```

### 1.2 开发原则

| 原则 | 说明 |
| --- | --- |
| **规范先行** | 公共契约先进 Spec（RFC → ADR），再写代码 |
| **测试先行** | 每个公开 API 先写测试，再写实现 |
| **文档同步** | API 变更同步更新 XML 文档、README、Spec |
| **语义版本** | 所有包共享 `5.x` 版本线，严格 SemVer |
| **API 分级** | 公开类型必须标 `[ApiLevel]`，公开面写进 PublicAPI 文件 |
| **PR 最小化** | 单 PR 不超过 500 行变更 |
| **持续集成** | 每次 push 跑构建、测试、分析器、架构测试、包验证、AOT 冒烟 |
