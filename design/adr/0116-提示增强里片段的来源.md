# ADR-0116 提示增强里片段的来源

## 状态

已采纳（`spec/rfcs/0022-ai.md` 随之修订）。

## 日期

2026-11-04

本 ADR 记录第二十九批回灌（`ai-batch-backlog.md`，N5 审查发现，用户定）的决定。

## 背景

`RagPromptAugmenter` 给每个片段打的是 `[n] (document: <文档 ID>, chunk: <序号>)`。文档 ID 多半是 Guid，模型看不到标题，回答时说不清依据出自哪份文档。

BasicApp 已经把 `title`、`source` 写进块的元数据，框架只差约定键名并用上。

## 决策

1. 每个片段一段：先是 `[n] Source: <来源>` 一行，再是片段文本。
2. 来源依次取元数据的 `title`、`source`，空白视同没有，都没有才取文档 ID，让模型至少能区分片段。
3. 键名是公开常量 `KnowledgeMetadataKeys.Title`、`KnowledgeMetadataKeys.Source`，摄入时放进 `KnowledgeIngestRequest.Metadata`。
4. 来源只占一行，值里的换行换成空格。否则模型分不清来源到哪里结束、片段从哪里开始。
5. 内置模板的英文指令不动，所以这一行的提示词也是英文的 `Source:`。要中文就配 `XiHan:AI:Knowledge:PromptName` 换模板，`{context}` 的格式不随模板变。

## 备选

1. **保留块序号 `chunk: n`**：模型引用靠 `[n]`，块序号对它没有意义。否决。
2. **给 `RetrievedChunk` 加 `Title`、`Source` 属性**：要改 `KnowledgeRecord`、`IKnowledgeStore` 与向量记录的结构，存量向量也要迁移；元数据已经随块保存。否决。
3. **按文档语言本地化 `Source:`**：增强不知道模型回答用什么语言，模板也是单语言的，混用没有收益。否决。

## 影响

- `{context}` 的文本变了。断言过旧格式的测试要改，比如 BasicApp 的 `KnowledgeDocumentsTests`。
- 没写 `title`、`source` 的存量块照常可用，来源回落到文档 ID，不需要重新摄入。
- 新增公开类型 `KnowledgeMetadataKeys`。其余公开 API 不变。
