# ADR-0059 表达式求值的空结果

## 状态

已采纳（`spec/rfcs/0021-workflow.md` 表达式一段修订）。

## 日期

2026-10-30

## 背景

原语的成功结果不携带 `null`：`Result.Success<T>(value)` 先 `ArgumentNullException.ThrowIfNull(value)`，没有值用 `Maybe<T>` 表示（RFC-0001）。

工作流的 `IWorkflowExpressionEvaluator.Evaluate` 与 `ActivityContext.EvaluateProperty` 却声明为 `Result<JsonNode?>`，规范还写了「缺少的成员或键是 null」「null 渲染成空串」「没有属性返回 null」。实际上这些情况都在构造成功结果时抛出 `ArgumentNullException`：

- 求值只捕获语法与求值错误，这个异常直接冒出去。
- 引擎把它当成活动的意外异常，实例出错。
- `{{ 缺少的成员 }}` 渲染不出空串。

BasicApp 报告调度租约的同类缺陷（`Result.Success<DateTimeOffset?>(null)`，已另行修复）后，按同样的写法检查发现了这一处。

## 决策

- 契约改为 `Result<Maybe<JsonNode>>`：
  - `IWorkflowExpressionEvaluator.Evaluate(expression, scope)`：结果为 `null` 时（字面量 `null`、缺少的成员或键、值为 null 的变量）是成功的无值。
  - `ActivityContext.EvaluateProperty(name)`：没有这个属性是成功的无值，字符串属性当表达式求值，其余属性原样作为有值。
- 下游语义不变：
  - `EvaluateCondition` 遇到无值失败（不是布尔）。
  - `Render` 把无值渲染成空串。
  - 写回变量、输出与子流程变量时，无值就是 JSON 的 `null`。
- 未知根变量仍是错误，不是无值。

## 理由

- 不放宽原语：`Result` 的成功结果不为空是全框架的约定，调用方据此不做空检查。缺陷在于契约声明了原语表达不了的东西，应该让契约用 `Maybe` 说出「无值」。
- 5.0 尚未正式发布，`Workflow.Abstractions` 的这两个签名直接改，不保留旧签名。

## 影响

- 公开 API：
  - `IWorkflowExpressionEvaluator.Evaluate` 与 `WorkflowExpressionEvaluator.Evaluate` 返回 `Result<Maybe<JsonNode>>`。
  - `ActivityContext.EvaluateProperty` 返回 `Result<Maybe<JsonNode>>`。
  - 自定义活动与求值器的调用方从 `TryGetValue` 取出 `Maybe<JsonNode>` 后再判断有无值。
- 行为：表达式结果为 null 的工作流不再出错；内置活动（延迟、遍历、设置变量、子流程、用户任务、表达式指派）与输出映射照常处理 null。
- 测试：
  - 表达式：字面量 `null`、缺少的成员、值为 null 的变量是成功的无值；模板渲染空串；条件失败；未知变量仍是错误。
  - 引擎一致性套件：设置变量的表达式求出 null 时写成值为 null 的变量、实例照常完成（内存与数据库实现都跑）。
  - 这些用例在修复前都会失败。
