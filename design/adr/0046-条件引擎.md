# ADR-0046 条件引擎移入 Security.Abstractions

## 状态

已采纳（`spec/rfcs/0008-security.md` 增「条件」节，`spec/conventions/error-codes.md` 登记四个错误码）。

## 日期

2026-10-29

## 背景

BasicApp 6.0 Access 深化报告：访问策略、权限条件、约束规则的"条件"类型都要属性判定（ABAC）。4.x 在 `XiHan.Framework.Authorization/Conditions`（约 1840 行），5.0 没有。BasicApp 只提供属性来源（主体、资源、环境）与条件的存储，要求运算符、值种类、值语法、校验与求值语义照搬 4.x——条件已存在库里，运算符与值种类的整数值是持久化契约。

## 备选

1. 新开包 `Security.Conditions`：引擎是纯逻辑、零外部依赖，只服务安全领域的策略判定，单独一个包只增加装配与版本面。
2. 放进 `Security.Abstractions` 的子命名空间 `Conditions`：与权限检查器一样是协议无关的纯逻辑，所有授权 Provider 与应用都能直接用。
3. 留给应用自己移植：BasicApp 之外的应用同样需要 ABAC，而且语义要跨应用一致。

## 决策

采用 2。

- 语义原样保留：十五个运算符与七种值种类（整数值不变）、`ConditionOperatorRules` 搭配规则、属性登记（精确名 → 别名 → 最长前缀的族，多值）、值语法（集合 JSON 数组或逗号 / 全角逗号 / 换行分隔，区间 `a,b` / `[a,b]` / `{"min","max"}`，IP 集合收 CIDR 且主机位为零，时刻区间可跨零点）、求值（命中 / 不命中 / 无法判定 / 待定，组内且组间或，无法判定取反不翻转，为空可取反）、说明模式、额外登记项、编译时区。
- 按 5.0 约定调整：
  - 编译错误 `ConditionCompileError.Error` 与说明里的原因 `ConditionClauseEvaluation.Reason` 由中文字符串改为 `Error`，带错误码与消息键：`SECURITY_VALIDATION_002`（条件无效），以及取不到 `SECURITY_NOTFOUND_003`、暂不可得 `SECURITY_UNAVAILABLE_004`、属性值不合法 `SECURITY_VALIDATION_003`。十八个消息键，十种内置区域（RFC-0010），编辑界面按调用方区域本地化。
  - 类型去掉 `Default` 前缀（`ConditionAttributeRegistry`、`ConditionCompiler`、`ConditionEvaluator`）。登记不再走 Options，各模块调 `services.AddConditionAttributes(...)`，登记项逐个进容器，登记表、编译器、求值器按单例 `TryAdd`。
  - 枚举不带 `[Description]` 中文名，显示名属于应用的界面文案。
  - `CancellationToken` 不再有缺省值，`EvaluateAsync` 的 `explain` 必传。
  - 解开 JSON 字符串改用 `JsonDocument`，不用反射序列化（包是 AOT 兼容的）。
  - 程序错误（登记冲突）的异常文本用英文。
- 求值按需取属性：编译结果给出 `ReferencedAttributes`，求值器只向来源取被引用的属性，不要说明时短路。

## 理由

- 条件存在库里，整数值与值语法必须与 4.x 一致，存量数据才能直接迁过来。
- 消息走目录：框架包不能出现硬编码的单一语言文案，错误码还能让界面区分"保存前必须修"与"运行时取不到"。
- 放在 `Security.Abstractions`：与检查器、过滤器、授予来源同包，应用在授权中间件里组合它们时只依赖一个契约包。

## 影响

- 公开 API：`Security.Abstractions.Conditions` 全部类型（Preview）；`SecurityErrors` 四个常量，`SecurityMessages` 十八个常量与十种区域的语言文件。
- 不在框架里：属性来源（主体、资源、环境，含 `environment.geo.*`）、条件存储与策略组合由应用提供；权限条件要用请求属性（IP、时间、路径），应用在 Authorize 阶段的中间件里求值。`IPermissionFilter` 只拿 `SecurityContext`，本次不扩大。
- 测试：4.x 的条件用例逐条移植（编译、求值、登记表、搭配规则、契约），错误断言改为错误码与消息键；新增多值属性的不搭配消息、全角逗号区间、IPv6 区域标识、说明模式的四种原因。
