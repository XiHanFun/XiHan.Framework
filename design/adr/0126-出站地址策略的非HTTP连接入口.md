# ADR-0126 出站地址策略的非 HTTP 连接入口

## 状态

已采纳（`spec/rfcs/0008-security.md` 随之修订）。

## 日期

2026-11-04

本 ADR 记录第三十一批回灌（`ak-batch-backlog.md`，N5 安全审查，用户定修）的第七项。

## 背景

ADR-0117 的 `OutboundAddressPolicy` 只有两个入口：`Apply(SocketsHttpHandler)` 给 HTTP，`IsAllowed(IPAddress)` 判断一个 IP。真正防 DNS 重绑定的解析、判定、连接是私有的。

不是 HTTP 但地址同样来自用户的连接没有入口。BasicApp 的 SMTP 发送（租户自己填的邮件服务器）只好抄一份：解析、`AllowedHosts`、`IsAllowed`、逐个地址连接，二十多行，而且策略的日志与规则变化都跟不上。

## 决策

1. 公开 `ValueTask<Socket> ConnectAsync(string host, int port, CancellationToken)`：解析主机名，只连策略允许的地址，返回连好的 `Socket`，由调用方释放。
2. 规则与 HTTP 路径完全相同，HTTP 的连接回调就是调用它再包一层 `NetworkStream`，所以不是两份实现：`AllowedHosts`、部分拒绝只连其余、全部拒绝抛 `OutboundAddressDeniedException`、逐个地址试到最后一个、日志。
3. 返回 `Socket` 而不是 `Stream`：SMTP 这类协议库接受套接字，要自己做 STARTTLS；要流的调用方自己 `new NetworkStream(socket, ownsSocket: true)`。
4. 主机名空白、端口不在 1～65535 抛 `ArgumentException`。这是调用方的编程错误；保存配置时的校验是应用的事。

## 备选

1. **公开解析与判定（`ResolveAllowedAsync` 返回地址列表）**：调用方再自己连，容易二次解析，正好打开重绑定的窗口。否决。
2. **不做，BasicApp 留着自己的副本**：规则变化时两边不同步，这正是要避免的。否决。
3. **同时接数据库与消息代理的驱动**：驱动自己连接，要经各自的扩展点，现在也没有使用者。否决。

## 影响

公开 API 增量，既有行为不变。

BasicApp 的 `SmtpEmailTransport.ConnectAsync` 可以换成这个入口，得到策略的日志。这由 N5 做。
