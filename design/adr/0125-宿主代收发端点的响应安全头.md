# ADR-0125 宿主代收发端点的响应安全头

## 状态

已采纳（`spec/rfcs/0012-objectstorage.md` 随之修订）。

## 日期

2026-11-04

本 ADR 记录第三十一批回灌（`ak-batch-backlog.md`，N5 安全审查，用户定修）的第六项。

## 背景

`MapXiHanBlobs` 的端点通常与应用同源，内容是用户上传的。它原样写出存储里的内容类型，没有别的响应头：上传一个 HTML 或 SVG，再让别人打开它的预签名地址，页面脚本就在应用的源上运行。内容类型写错或缺失时，浏览器还可能自己猜。

BasicApp 用自己的中间件 `ResponseSecurityHeadersMiddleware` 补上了这一点。每个用这个端点的应用都要这样做，所以放进框架。

## 决策

1. 端点的响应都带 `X-Content-Type-Options: nosniff`，下载、上传、错误响应都一样。
2. 写出内容时带 `Content-Security-Policy: sandbox; default-src 'none'; img-src 'self' data:; media-src 'self'; style-src 'unsafe-inline'`。沙箱让文档得到一个唯一的源，也不能运行脚本；后面几项让浏览器能显示图片、媒体和它给这些内容生成的页面。
3. PDF 不进沙箱：浏览器内置的阅读器在沙箱里打不开。它本身跑不了页面脚本，有 `nosniff` 时把 HTML 标成 PDF 也不会按 HTML 解析。按媒体类型比较，不区分大小写，忽略参数。
4. 应用已经给这个响应设了 `Content-Security-Policy` 时不覆盖。没有新配置项：要换策略的应用在 `UseXiHan` 之前的中间件里设自己的头。

## 备选

1. **做成选项（`HostedBlobUrlOptions.ContentSecurityPolicy`）**：现在没有使用者要换，中间件已经够用。否决。
2. **强制 `Content-Disposition: attachment`**：图片、视频预览和 PDF 阅读器就都不能用了，预览是这个端点的主要用途。否决。
3. **只设 `nosniff`**：标对了内容类型的 HTML 和 SVG 还是会运行脚本。否决。
4. **放到通用的响应头中间件里，对全部响应生效**：API 响应的策略是应用的事，框架不替应用决定。沙箱只对这个端点有意义。否决。

## 影响

这是对外行为变化。

- 把 `/blobs` 上的 HTML 当网页用的应用，脚本不再运行，页面里的外部资源也不再加载。要这样用的应用自己设策略。
- 嵌在 `<iframe>` 里的内容：沙箱文档不能运行脚本，也不能取得父页面的源。图片、视频和 PDF 不受影响。
- 公开 API 不变。

只有宿主代收发的端点走这里。S3 直传直下的地址不经宿主，响应头由 S3 与它的配置决定。
