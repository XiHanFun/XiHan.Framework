# ADR-0016 工作流子系统：引擎进抽象包，Provider 只管存储、锁与轮询

## 状态

已采纳

## 日期

2026-10-26

## 背景

[06-BasicApp迁移清查](../architecture/06-BasicApp迁移清查.md) 把 `Workflow.*` 列为硬阻塞：BasicApp.Workflow（59 文件、7 325 行）依赖 4.x 的引擎、定义生命周期、用户任务、书签与三个存储契约，并自己用 SqlSugar 实现了存储。总体方案把 `Workflow.Abstractions`（`workflow.execution@1`）与默认实现 `Workflow.InMemory` 放在 5.x 后续。用户于 2026-10-25 拍板提前到现在做，范围与 4.x 全功能对齐（去掉 `Http` / `Script` 活动）。要决定引擎放在哪一层、值模型、活动的执行方式、事件的去向。

## 备选

1. 引擎放进 `Workflow.InMemory`，`Workflow.Abstractions` 只有契约；每个 Provider 各自实现引擎。
2. 引擎放进 `Workflow.Abstractions`（与 `Scheduling.Abstractions` 的 `JobDispatcher`、`Messaging.Abstractions` 的 `MessageDispatcher` 同一做法），Provider 只实现三个存储、实例锁与到期书签的轮询驱动。
3. 变量沿用 4.x 的 `Dictionary<string, object?>` 加反射 JSON；或改为 `JsonObject` / `JsonNode` 值模型。
4. 事件沿用"引擎内事件总线"；或发布为 `workflow.*` 主题的消息。

## 决策

- 采用备选 2：`WorkflowEngine`、`WorkflowDefinitionValidator`、`WorkflowExpressionEvaluator`、`ActivityRegistry`、`AssigneeResolver`、`WorkflowTaskService`、`DueBookmarkPoller` 与全部内置活动都在 `Workflow.Abstractions`；Provider 实现 `IWorkflowDefinitionStore` / `IWorkflowInstanceStore` / `IWorkflowBookmarkStore` / `IWorkflowInstanceLock` 并驱动轮询。`Workflow.Database`（后续）复用同一引擎，只换存储、分布式锁与领导租约。
- 值模型是 JSON（`JsonObject` / `JsonNode`）：AOT 可序列化（`WorkflowJsonContext` 源生成）、存储可直接落 JSON 列、表达式求值无需反射；内存存储保存深拷贝。
- 活动是作用域服务，每个节点执行在新作用域、新上下文里经完整内核管道执行（关联 ID = 实例 ID，租户 = 实例租户），与作业、消息处理器同构；活动返回 `Result<ActivityOutcome>`，失败即故障。
- 事件是消息：装配了 `messaging.queue` 时以 CloudEvents 信封发布到 `workflow.*` 主题，没有发布者时跳过；应用用 `AddMessageHandler<T>(topic)` 订阅。
- 控制操作批量优先（ADR-0012）：取消、终止、挂起、恢复、重试、发布、停用、归档、删除、完成任务、转办、加签都以集合为入参、逐项结果，单条是扩展方法。
- 不提供 `Http`、`Script` 活动（分别需要 `Microsoft.Extensions.Http` 与 Roslyn，不属于抽象包可依赖的范围；应用按需登记自己的活动）。
- 默认出边改为"兜底"：`AllMatched` 下只有一条条件边都不匹配时才走默认边（4.x 总是流出）。

## 理由

- 引擎是工作流的协议性规则（波次、书签、故障、Join、子流程回调），Provider 之间不应各自实现一遍；三个存储与锁才是真正随基础设施变化的部分。
- JSON 值模型让 AOT、存储与表达式三件事同时成立；4.x 的 `object?` 模型靠反射序列化，与 5.0 的 AOT 门禁冲突。
- 经管道执行让活动天然获得租户、授权、审计与追踪；取消令牌用宿主停止令牌，避免调用方断连把执行中的状态写一半。
- 事件走消息与 V4-08 的迁移方向一致，BasicApp 的处理器迁成 `IMessageHandler` 即可。

## 影响

- 新包：`Workflow.Abstractions`（Ring 2）、`Workflow.InMemory`（Ring 3，`role: default`，进 `Profiles.Full`）、`Workflow.Conformance`；新 RFC-0021；错误码 `WORKFLOW_*`；消息目录 `workflow`。
- BasicApp.Workflow 迁移时：三个 SqlSugar 存储改实现 5.0 契约（JSON 列存 `JsonObject`，批量方法），事件处理器改消息处理器，`IWorkflowDefinitionManager` / `IWorkflowUserTaskService` 换成目录与任务服务的批量 API，异常改 `Result`。
- `xihan migrate v4` 后续补 V4-11：`XiHan.Framework.Workflow*` 命名空间与类型名的映射。
