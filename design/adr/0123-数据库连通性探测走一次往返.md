# ADR-0123 数据库连通性探测走一次往返

## 状态

已采纳（`spec/rfcs/0005-persistence.md` 随之修订）。

## 日期

2026-11-04

本 ADR 记录第三十一批回灌（`ak-batch-backlog.md`，用户定修）的第四项。

## 背景

ADR-0118 给从库探针加了执行语句，同时记下两处同类问题没有改：健康项 `persistence.sqlsugar.database` 用 `Ado.IsValidConnection`，运行时数据源的探测用 `DbConnection.OpenAsync`，都只打开连接。

连接池把空闲连接直接交出来，打开不碰网络。真实 PostgreSQL 上的实验：服务停掉之后这两种方式都返回成功。结果是数据库宕了健康项还是 Ready。

另外两个问题：

- `IsValidConnection` 是同步的，不接受取消令牌。服务器接受连接但不回话时，它卡到驱动自己的超时（Npgsql 缺省 15 秒，连接串可以配得更长），健康项写明的「单次探测超时」不起作用，首探还拖住宿主启动。
- `IsValidConnection` 吞掉异常，健康项只有一个固定的错误，看不到原因。
- `TestAsync` 没有上限，等多久看调用方和驱动。

## 决策

1. 三个探测共用一个内部实现 `SqlSugarRoundTrip`：另建客户端，打开连接，执行一条语句。从库探针原来的那段代码搬过去。
2. 语句按 `DbType`：缺省 `SELECT 1`；Oracle、达梦、`OceanBaseForOracle`、`TDSQLForOracleODBC` 带 `FROM DUAL`；HANA `FROM DUMMY`；DB2 `FROM SYSIBM.SYSDUMMY1`。`MongoDb`、`Custom`、`Odbc` 不知道后端说什么语言，只打开连接：一条不认识的语句会让健康的库报 Degraded，比现状更糟。
3. 超时沿用已经写明的配置：`HealthProbeIntervalSeconds`。不加新配置项。`TestAsync` 也以运行时数据源的这个值为上限，超时返回 `PERSISTENCE_UNAVAILABLE_006`，调用方取消照常抛出。
4. 探测放到线程池上，再按令牌等它。不是每个驱动都实现了真正的异步（基类的 `OpenAsync` 同步打开，只在进入时看一眼令牌），这样超时对所有驱动都成立。超时后不再等那个连接，它到驱动自己的超时才结束，它的异常不再有人要。这段时间每次探测最多多留一个连接，上限由驱动的连接超时决定。
5. 主库探测用当前作用域客户端的连接配置另建客户端，不碰作用域客户端自己的连接。
6. `persistence.sqlsugar.database` 失败时不再返回固定的 `PERSISTENCE_UNAVAILABLE_003`，异常交给 `PeriodicHealthContributor`：错误是 `KERNEL_UNAVAILABLE_005`，`reason` 写异常类型，完整异常进日志，同一种失败第一次 Warning、之后 Debug（ADR-0115）。其他 Provider 的探针抛异常时就是这样。

## 备选

1. **保留 `IsValidConnection`，再执行一条语句**：它不接受令牌，超时问题还在。否决。
2. **保留 `PERSISTENCE_UNAVAILABLE_003`，把异常类型放进详情**：超时走令牌取消，探针分不清是超时还是宿主停止，这部分还是要交给 `PeriodicHealthContributor`，同一个健康项就有两个错误码。否决。
3. **给探测单独加超时配置**：健康项的文档已经写明间隔也是单次超时，现在只是让它成立。否决。
4. **加 `Pooling=false` 探测**：连接串的写法各驱动不同；不走连接池也测不到连接池里的连接是不是好的。否决。
5. **同时改 EF Core 的 `CanConnectAsync`**：不在这一批的范围，也没有验证它在连接池下的表现。记进待办。

## 影响

这是对外行为变化。

- 数据库宕了健康项 `persistence.sqlsugar.database` 真的变 Degraded，运行时数据源的健康项与 `TestAsync` 也一样。按健康项告警的部署会开始收到以前收不到的告警。
- `persistence.sqlsugar.database` 的错误码由 `PERSISTENCE_UNAVAILABLE_003` 变成 `KERNEL_UNAVAILABLE_005`。按这个码告警的要改。`PERSISTENCE_UNAVAILABLE_003` 还在，EF Core 的健康项用它。
- 服务器不回话时首探不再卡住启动，最多等 `HealthProbeIntervalSeconds`。
- `TestAsync` 有了上限，缺省 15 秒。慢的库（比如冷启动的 Serverless 数据库）要调大运行时数据源的 `HealthProbeIntervalSeconds`。
- 探测账号要能执行 `SELECT 1`。几乎不受限；连得上但什么都不能执行的账号现在报 Degraded。
- 公开 API 不变。

### 没有测到的

驱动不理令牌的分支没有用例：要造一个假的 ADO.NET 驱动，并让 SqlSugar 按 `Custom` 加载它。用例覆盖的是 Npgsql，它理令牌。
