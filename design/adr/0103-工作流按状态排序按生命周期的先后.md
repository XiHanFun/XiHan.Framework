# ADR-0103 工作流按状态排序按生命周期的先后

## 状态

已采纳（`spec/rfcs/0021-workflow.md`「列表排序」与 Workflow.Database 一段随之修订）。修订 ADR-0102：按状态排序由「状态名的字母序」改为生命周期的先后。

## 日期

2026-11-02

本 ADR 记录第十二批回灌（`p-batch-backlog.md`）的一项决定：第十一批 ADR-0102 留下的待定「状态按状态名字母序」，用户定按生命周期排。

## 背景

ADR-0102 的列表排序里，`SortBy = Status` 按状态列比较；状态列存的是状态名，排出来是字母序：定义 `Archived` < `Disabled` < `Draft` < `Published`，实例 `Canceled` < `Completed` < `Faulted` < `Running` < `Suspended` < `Terminated`。这是按名字的分组，不是生命周期的先后。

## 备选

1. 维持状态名的字母序：用户已否决。
2. 把状态列改存整数：改变已有的列与所有按状态过滤的写法（待办查询下推的书签行也冗余了状态名），影响面大，也让库里的数据不可读。
3. 另加一列状态序号，按它排（采纳）。
4. 在 SQL 里用 `CASE` 表达式按状态名映射成序号再排：SqlSugar 与 EF Core 对排序键里条件表达式的翻译各库不一，SQL Server、Oracle 上没有实测；排序键也不能利用索引。

## 决策

取备选 3。

- 生命周期的顺序（写进 RFC-0021「列表排序」，是契约）：定义 `Draft` → `Published` → `Disabled` → `Archived`；实例 `Running` → `Suspended` → `Completed` → `Canceled` → `Faulted` → `Terminated`。升序是这个顺序，降序反过来，同状态按 ADR-0102 的次序键（定义：名字升序、版本降序、ID；实例：创建时间降序、写入先后降序、ID）。两个枚举的 XML 文档写明「声明顺序就是生命周期的先后」，以后新增状态要在 RFC 里定它的位置。
- 序号的取值是存储内部的细节，不是公开常量：定义 0、1、2、3，实例 1～6，与枚举的整数值相同。两个实现各有一个内部的 `WorkflowStatusOrder`（显式的 `switch`，不取枚举的整数值——枚举的数值是公开 API，排序的先后是另一份约定），白名单以外的状态抛 `ArgumentOutOfRangeException`。
- 内存实现：`SortBy = Status` 时按 `WorkflowStatusOrder.Of(status)` 比较。
- 数据库实现：定义行与实例行（平台表与租户表）新增 `StatusOrder`（`int?`），存储在 `ToRecord` / `Copy` 里随 `Status` 一起写——实例与定义的每一次写入（新增、状态变更、迁移、跳转、重试、挂起、恢复、取消、终止，定义的发布、停用、归档）都经整行写入，没有别的路径单独改状态列，与第八批 `Search*` 冗余列由存储维护是同一做法。`SortBy = Status` 时 `ORDER BY StatusOrder`。
- 列可空：`InitTables` 要能给已有行的表加上——RFC-0005 下 SqlSugar 只在 PostgreSQL 上给非空数值列带 CLR 缺省值，SQLite 等库给已有行的表加非空列会失败；存储写入的行总有值。不加索引：按状态排序是对过滤后的行排序。

## 理由

- 用户拍板；顺序与枚举的声明顺序一致，没有需要另定位置的状态。
- 冗余列由存储随整行写入维护，路径单一，不会漏；排序仍是普通的列排序，各库、各 Provider 的翻译都一样。
- 序号不公开：调用方只需要「按生命周期排」这个语义，不需要知道数值；数值留在存储里，将来新增状态时可以重新编排而不动公开 API。

## 影响

- 公开 API：Workflow.Database 的 `WorkflowDefinitionRow.StatusOrder`、`WorkflowInstanceRow.StatusOrder`（`int?`，实体列必须是公开属性）；Workflow.Conformance 新增用例方法一个。Abstractions 只改文档，没有签名变化；没有新错误码、消息键、配置键、启动失败条件。
- 行为：`SortBy = Status` 的结果从字母序变为生命周期顺序（定义与实例都是），其余排序不变。
- 表结构：`WorkflowDefinitionRecord` / `PlatformWorkflowDefinitionRecord`、`WorkflowInstanceRecord` / `PlatformWorkflowInstanceRecord` 新增可空整数列 `StatusOrder`，`InitTables` 照常给已有行的表加上，没有新索引；独立库的租户库同样要加。回填只靠 `Status` 列：`UPDATE … SET StatusOrder = CASE Status WHEN 'Draft' THEN 0 WHEN 'Published' THEN 1 WHEN 'Disabled' THEN 2 WHEN 'Archived' THEN 3 END WHERE StatusOrder IS NULL`（定义表），`CASE Status WHEN 'Running' THEN 1 WHEN 'Suspended' THEN 2 WHEN 'Completed' THEN 3 WHEN 'Canceled' THEN 4 WHEN 'Faulted' THEN 5 WHEN 'Terminated' THEN 6 END`（实例表）。没回填的行按状态排序时位置照数据库的空值规则，下一次整行写入时自愈。
- 测试：存储用例 12、13 的状态排序改为生命周期顺序，并补整体替换改了状态之后的位置（定义归档、发布；实例终止、恢复、故障）；引擎用例 37（定义经目录发布、停用、归档，实例经引擎挂起、取消、终止、恢复，升降序都覆盖，名字序与状态名序都与生命周期不同）。修改验证：内存实现改回状态名字母序时 3 例失败，数据库实现整行替换时不写 `StatusOrder` 时 4 例失败。
