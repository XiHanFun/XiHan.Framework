# ADR-0042 凭据无效映射 HTTP 401 / gRPC Unauthenticated，401 带 `WWW-Authenticate` 质询

## 状态

已采纳（`spec/protocol/http.md`、`spec/protocol/grpc.md`、`spec/protocol/mcp.md`、`spec/rfcs/0008-security.md` 修订）。

## 日期

2026-10-29

## 背景

BasicApp 6.0 N2 报告：`ProblemResponse.StatusCodeFor` 只把 `SECURITY_DENIED_001`（未认证）映射成 401，`JwtAuthenticationHandler`、`OpenIdConnectAuthenticationHandler`、`ApiKeyAuthenticationHandler` 对过期、签名不符、缺主体声明一律返回的 `SECURITY_DENIED_003`（凭据无效）落进"其余 DENIED"，得到 403。RFC 6750 §3.1 规定 `invalid_token`（过期、被吊销、格式错、签名不符）回 401 并带 `WWW-Authenticate: Bearer error="invalid_token"`，403 留给 `insufficient_scope`；通用 HTTP 客户端与网关按 401 触发刷新、按 403 判定越权。gRPC 的 `GrpcStatusMapping` 同样把它映射成 `PermissionDenied`。另外框架的 401 响应从来没有 `WWW-Authenticate` 头，而 RFC 7235 §3.1 要求 401 至少带一个质询。BasicApp 的前端按错误码判断、已自行对 003 先刷新再重放，不依赖状态码；这里修的是协议语义。

## 备选

1. 只改状态码：003 → 401，不加质询头。
2. 改状态码并在 401 上加 `WWW-Authenticate`：凭据无效时质询被拒的方案，没有凭据时质询全部已装配的方案。
3. 让认证处理器各自写质询（`IAuthenticationHandler` 加方法）：处理器不碰 HTTP，gRPC / MCP / 命令行共用同一处理器。

## 决策

采用 2。

- `ProblemResponse.StatusCodeFor`：DENIED 种类里 `SECURITY_DENIED_001` 与 `SECURITY_DENIED_003` 为 401，其余为 403；新增 `ProblemResponse.IsAuthenticationFailure(Error)` 表达这一判定。
- `UseXiHan` 唯一的错误写出点在 401 时追加 `WWW-Authenticate`（内部 `AuthenticationChallenge`）：
  - 凭据无效且请求出示了凭据：只质询那个方案；Bearer 为 `Bearer error="invalid_token"`（不带 `error_description`，与"不区分原因对外暴露"一致），其他方案只写方案名（如 `ApiKey`）。方案名按认证处理器登记的写法输出。
  - 没有凭据（未认证）：按容器里 `IAuthenticationHandler.Scheme` 逐个质询（去重、不区分大小写），不带错误码（RFC 6750 §3）；一个处理器都没有时不写。
- gRPC：`SECURITY_DENIED_003` 与 `001` 一样映射 `Unauthenticated`。gRPC 没有质询头的约定，尾部元数据仍带 `xihan-error-code`。
- MCP 端点在 `UseXiHan` 之后，凭据无效时随之是 401 加质询。命令行按 KIND 给退出码，DENIED 仍是 4，不变。

## 理由

- 401 / 403 的区分是 HTTP 生态的通用契约：刷新令牌、重新登录、网关重试都只看状态码；把过期令牌报成 403 会让客户端误以为越权而不刷新。
- 质询头放在宿主的错误写出点：只有它同时知道状态码、请求出示的凭据（调用上下文）与已装配的方案（容器），处理器保持协议无关。
- 凭据无效只质询被拒的方案：客户端已经选了方案，告诉它换别的方案没有意义；没有凭据时列出全部方案，客户端据此选一个。

## 影响

- 行为变化：带无效 / 过期 / 签名不符凭据的 HTTP 请求从 403 变为 401（含 MCP 端点）；gRPC 从 `PermissionDenied` 变为 `Unauthenticated`。所有 401 现在带 `WWW-Authenticate`。错误码与 Problem Details 正文不变。
- 公开 API：`Hosting.AspNetCore` 新增 `ProblemResponse.IsAuthenticationFailure`（PublicAPI +1）；`AuthenticationChallenge` 为内部类型。
- 测试：`WebHostTests`（状态码映射、质询计算：Bearer invalid_token、ApiKey、按登记写法、去重、无方案、非认证失败不质询）、`JwtHttpChallengeTests`（真实宿主上过期与签名不符的令牌 401 + `Bearer error="invalid_token"`、缺令牌 401 + `Bearer`、有效令牌 200 无质询）、MCP 与 gRPC 用例改为 401 / `Unauthenticated`。
