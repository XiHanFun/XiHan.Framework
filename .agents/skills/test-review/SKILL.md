# XiHan.Framework 测试审查

对每个测试给出“保留、改写、合并或删除”结论，并指出它保护的公开不变量。

- 保留：能在缺陷复发时失败，覆盖 API、异常、取消、并发、容量、生命周期、DI、配置或 Provider 接线。
- 改写：mock 自证、只断言实现方法被调用、依赖私有字段/顺序、使用长时间真实等待或没有失败路径。
- 合并：与相邻用例输入和断言等价，不能提供额外定位。
- 删除：不可能失败、只验证常量/框架本身，或已被更清晰的同层测试完整覆盖。

## Framework 专项

- 默认存储测试必须覆盖空状态、容量上限、TTL/驱逐、并发、取消和释放。
- 模块测试验证 `[DependsOn]`、生命周期顺序、幂等注册和失败传播。
- Provider 测试区分契约测试与真实基础设施集成，不让内存假实现掩盖序列化和一致性问题。
- MTP 测试命令和测试项目配置不能改回 VSTest。
- 覆盖率是门禁，不替代对非法输入和边界行为的断言。

输出按风险排序并附文件和行号。除非用户要求运行，否则先静态审查；不得通过删除测试或降低 CI 阈值解决生产缺陷。
