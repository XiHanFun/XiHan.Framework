# 默认实现与资源治理

## 默认实现

- 公共契约的框架默认实现命名为 `DefaultXxx`，让替换点一目了然。
- 默认实现必须零外部基础设施依赖，不要求 Redis、数据库、消息队列或远程服务。
- 默认实现不是“无限内存版本”：集合、缓存、队列和历史记录都要有容量、过期或清理机制。
- 达到容量上限时采用文档化、可测试的策略；不要静默无限扩容。
- 默认实现与分布式实现共享契约，但不假装提供跨进程一致性。

## 外部资源边界

- Framework 定义抽象、选项和扩展点；消费应用选择持久化、Redis、消息或云 Provider。
- Provider 的连接生命周期、重试、超时、健康检查和序列化策略由对应实现拥有。
- 不因 BasicApp 或单个消费者需要，就让 Framework 默认实现读取其配置或引用其程序集。
- 外部服务不可用时，只有契约明确允许降级才可降级；否则快速、可诊断地失败。

## 并发与内存

设计任何长生命周期状态时明确：

1. 键空间是否有界。
2. 条目何时过期、被驱逐或显式删除。
3. 并发读写是否原子，回调是否可能重入。
4. 取消和关闭时是否停止后台任务并释放资源。
5. 统计值在冷启动、空集合和竞争条件下是否合法。

托管堆读数取 `GC.GetGCMemoryInfo()` 的快照（`HeapSizeBytes - FragmentedBytes`），不用 `GC.GetTotalMemory(false)`：后者在 regions GC 下会无符号下溢返回负数（dotnet/runtime#130888），且把尚未回收的垃圾计入，用它做阈值判定或断言都会随 GC 触发时机随机变红。快照在进程首次 GC 前为 0，这是合法边界值，不要误判为未初始化。诊断内存事件时区分宿主级 OOM、应用无界增长和正常长连接，只根据日志、转储、指标和代码路径下结论。

## 测试要求

- 覆盖空状态、上限、过期、驱逐、重复写入、并发和释放。
- 对时间敏感实现使用可控时钟或仓库现有测试原语，不使用长时间真实等待。
- 分布式实现测试其真实一致性语义；不要让内存假实现掩盖序列化或并发问题。
- 故障测试断言错误类型和可诊断信息，不只断言“没有崩溃”。
